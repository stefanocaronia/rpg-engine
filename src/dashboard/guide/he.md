# RPG Engine: המדריך המלא

**RPG Engine** מאפשר לשחק משחק תפקידים שולחני עם **בינה מלאכותית בתור מנחה**.

מדברים עם המנחה ב**צ'אט**: המנחה מספר את הסיפור, מגלם את כל השאר ופוסק מה קורה.

RPG Engine עובד מאחורי הקלעים: הוא **זוכר את העולם**, **מטיל את הקוביות** ו**מנהל את החשבונות**.

לצד הצ'אט משאירים בדפדפן דף פתוח, **לוח הבקרה**, עם דף הדמות, הקוביות, המפות והיומן.

המדריך מיועד לשחקנים. אין צורך לדעת תכנות.

## התחלה מהירה <!-- icon: send -->

1. להתקין את **Node.js** מ-[nodejs.org](https://nodejs.org) (גרסת ה-LTS).
2. להתקין את **Claude Code** או את **Codex**, אפליקציית הבינה המלאכותית שהמנחה רץ בתוכה, ולהתחבר ([2.4](#24-connect-your-ai)).
3. לפתוח טרמינל ולהתקין את RPG Engine: `npm install -g rpg-engine`.
4. בטרמינל, ליצור קמפיין: `rpg init "The Salt Isles"`.
5. לפתוח את Claude Code או את Codex בתיקייה החדשה ולכתוב *שלום! בוא נתחיל.* המנחה עונה עם הקישור ללוח הבקרה: לפתוח אותו לצד הצ'אט.

בהמשך המדריך מוסבר כל שלב, ואחר כך איך משחקים.

## 1. מהו RPG Engine <!-- icon: about -->

### מי עושה מה

| מי | מה הוא עושה |
|---|---|
| **אתה** | משחק את הדמות. אומר מה היא עושה, אומרת ומנסה. |
| **המנחה** (הבינה המלאכותית) | מספר את הסיפור, מגלם כל דמות אחרת, מחליט מה קורה, מבקש הטלות. |
| **RPG Engine** | זוכר הכול בקבצים, מטיל את הקוביות, סופר נקודות חיים, כסף, זמן ומרחקים, ושומר סודות עד שמגלים אותם. |

בינה מלאכותית טובה בסיפור סיפורים וגרועה בזכירה. בלי עזרה היא שוכחת מי חייב לך כסף, כמה חיצים נשארו לך, או שהגשר נשרף לפני שני סשנים. RPG Engine שומר את כל זה, ולכן העולם נשאר זהה מערב לערב, גם בצ'אט חדש ואפילו עם בינה מלאכותית אחרת.

### איך זה מרגיש

כותבים בצ'אט כמו שמדברים סביב שולחן:

> אני דוחף את הדלת לאט ומציץ פנימה.

המנחה עונה במה שרואים, ועוצר כשמגיע הרגע לבחור. כשמשהו לא ברור וחשוב, המנחה אומר מה על הכף ומבקש הטלה. כפתורי ההטלה מופיעים בלוח הבקרה. לוחצים, הקוביות נופלות על הדף, והמנחה מספר מה קורה.

### מה מייחד אותו

- **העולם קבוע.** מה שנאמר נשאר נכון. נבל שמת נשאר מת.
- **הקוביות אמיתיות.** המנחה לא יכול לעקם אותן (חוץ מברמת הקושי הקלה ביותר, אם בוחרים בה).
- **סודות נשארים סודות.** המנחה לא מגלה מה שהדמות לא יודעת, גם אם מתעקשים.
- **העולם ממשיך לנוע גם בלעדיך.** איומים מתקדמים בזמן מנוחה או מסע, ורואים את הסימנים שלהם.
- **הרבה ערבים, סיפור אחד.** קמפיין הוא תיקייה במחשב. אפשר לעצור מתי שרוצים ולהמשיך אחר כך.

### המשחק שזמין היום

RPG Engine נבנה לכל משחק תפקידים שולחני. היום מגיע איתו מערכת משחק אחת: **המהדורה החמישית** (מתוך System Reference Document 5.1 החופשי). משחקים נוספים יגיעו. ראו [מערכות משחק](#5-game-systems-and-house-rules) ו[בקרוב](#9-coming-later).

## 2. להתחיל <!-- icon: path -->

### 2.1 מה צריך

- מחשב עם Windows, macOS או Linux.
- **Node.js 22** או חדש יותר. להוריד מ-[nodejs.org](https://nodejs.org): גרסת "LTS" מתאימה. הוא מגיע עם `npm`, שמתקין את RPG Engine.
- **טרמינל**, החלון שבו כותבים פקודות: ב-Windows, אפליקציית Terminal או PowerShell; ב-macOS, Terminal. משתמשים בו כדי להתקין את RPG Engine, ליצור כל קמפיין ולהפעיל את Claude Code או את Codex.
- **מארח בינה מלאכותית**, האפליקציה שהמנחה רץ בתוכה: **Claude Code** או **Codex**, עם התוכנית וההתחברות שלהם. ראו [2.4](#24-connect-your-ai).
- **המודל הגדול ביותר** שהמארח מציע. מודל קטן נותן לעבוד עליו: בבדיקות שלנו הוא גילה סודות לשחקן שטען שהוא המנחה האמיתי.
- דפדפן, ללוח הבקרה.

ההתחברות למארח משמשת גם למשימות נוספות: RPG Engine משתמש בה, במחשב שלך, כדי לצייר תמונות של מקומות, משימות והדמות, ולתרגם את לוח הבקרה לשפות שאינן מגיעות איתו. ראו [תמונות](#311-pictures) ו[שפות](#72-languages).

**איך פותחים טרמינל בתיקייה.** שלבים רבים אומרים "בתיקיית הקמפיין". ב-Windows, לוחצים קליק ימני על התיקייה ב-File Explorer ובוחרים **פתיחה בטרמינל**. ב-macOS, קליק ימני על התיקייה ב-Finder ו-**שירותים > טרמינל חדש בתיקייה**. או, בטרמינל שכבר פתוח, כותבים `cd` ואת נתיב התיקייה, למשל `cd "C:\Users\me\Games\The Salt Isles"`.

### 2.2 התקנה

לפתוח טרמינל ולכתוב:

```text
npm install -g rpg-engine
```

כך מקבלים את הפקודה `rpg`. כדי לבדוק שההתקנה הצליחה:

```text
rpg --version
```

משתמשים ב-`rpg` פעם אחת לכל קמפיין, כדי ליצור אותו. מאז רק מדברים עם המנחה: מארח הבינה המלאכותית מפעיל את RPG Engine בעצמו, עם אותה פקודת `rpg`.

### 2.3 ליצור קמפיין

קמפיין הוא תיקייה. לפתוח טרמינל בתיקייה שבה שומרים את המשחקים, ולכתוב:

```text
rpg init "The Salt Isles"
```

הפקודה יוצרת את התיקייה `The Salt Isles` עם קמפיין חדש בתוכה, ואומרת מה לעשות עכשיו:

```text
Created the campaign "The Salt Isles" in C:\Users\me\Games\The Salt Isles.
To play, open Claude Code or Codex in this folder and say hello: the master asks you the rest.

For the master: Still to agree with the player: ...
```

השורות שאחרי *For the master* מיועדות למנחה, שקורא אותן בצ'אט: אין לכם מה לעשות איתן. כדאי לזכור איפה התיקייה: חוזרים אליה בכל פעם שמשחקים. בלי שם תיקייה, `rpg init` הופך את התיקייה הנוכחית לקמפיין.

`init` יוצר כל מה שהקמפיין צריך: ההגדרות שלו, תיקיות העולם, והקבצים הקטנים שאומרים למארח הבינה המלאכותית להשתמש ב-RPG Engine ולא לשמור זיכרון משלו מחוץ לקמפיין.

אין צורך לבחור שום דבר עכשיו. המנחה שואל את השאר בצ'אט, או שאפשר לבחור בלוח הבקרה. אם כבר ידועות כמה בחירות, אפשר לתת אותן כאן:

```text
rpg init salt-isles --name "The Salt Isles" --language en --system 5e --difficulty normal --lethality dice
```

הפקודה יוצרת את התיקייה `salt-isles`, ובתוכה את הקמפיין *The Salt Isles*: שם תיקייה בלי רווחים, ושם קמפיין כרצונך.

| אפשרות | מה היא קובעת | ערכים |
|---|---|---|
| `--name` | שם הקמפיין | כל שם; אם משמיטים, שם התיקייה |
| `--language` | שפת המשחק | קוד, כמו `en`, `it`, `fr` |
| `--system` | מערכת המשחק | `5e`, היחידה כיום |
| `--difficulty` | כמה קשה העולם | `story`, `easy`, `normal`, `hard`, `brutal` |
| `--lethality` | מה משמעות הנפילה בקרב | `narrative`, `epic`, `dice` |

גם `rpg init --help` מציג אותן. אי אפשר ליצור קמפיין בתוך תיקייה של קמפיין אחר.

אי אפשר לבקש מהמנחה ליצור קמפיין: לפני `init` אין בתיקייה שום דבר שאומר למארח הבינה המלאכותית איפה RPG Engine.

### 2.4 לחבר את הבינה המלאכותית

RPG Engine עובד עם **Claude Code** ועם **Codex**. אפליקציות בינה מלאכותית אחרות שתומכות בכלי MCP אולי יעבדו גם, אבל איננו מבטיחים זאת.

**התקנת המארח.** Claude Code ו-Codex רצים בטרמינל: הם אינם אפליקציית Claude או ChatGPT שבטלפון. לכל אחד תוכנית והתחברות משלו: ל-Claude Code תוכנית Claude בתשלום, ל-Codex התחברות ל-ChatGPT. יש לפעול לפי הדפים שלהם כדי להתקין ולהתחבר: [Claude Code](https://code.claude.com/docs/en/setup) ו-[Codex](https://learn.chatgpt.com/docs/codex/cli). עושים זאת פעם אחת, לכל הקמפיינים.

**Claude Code.** לפתוח טרמינל בתיקיית הקמפיין ולכתוב `claude`. בפעם הראשונה הוא שואל אם סומכים על התיקייה, ואומר שהתיקייה מתירה את כלי המשחק (`mcp__rpg`): לבחור **Yes, I trust this folder**. זהירות: התשובה שמסומנת מראש היא *No, exit*, ולכן לחיצה מיידית על Enter סוגרת את Claude Code. זה הכול: הקמפיין כבר אמר ל-Claude Code להשתמש ב-RPG Engine ובכלים שלו, ולכבות את הזיכרון שלו.

**Codex.** לפתוח טרמינל בתיקיית הקמפיין ולכתוב `codex`. כשהוא שואל אם סומכים על התיקייה, עונים כן: הגדרות הקמפיין עצמו אומרות ל-Codex איפה RPG Engine, מתירות את הכלים שלו ומכבות את הזיכרון שלו, ו-Codex קורא אותן רק בתיקייה שסומכים עליה. באפליקציית שולחן העבודה יש לוודא שהזיכרונות כבויים בצ'אטים של המשחק.

**למה הזיכרון חשוב.** הקמפיין חי בקבצים שלו. אם המארח זוכר דברים גם בעצמו, חזרה לשמירה לא תהיה חזרה באמת: המנחה עדיין יזכור מה בוטל.

### 2.5 הצ'אט הראשון

לכתוב משהו, למשל:

> שלום! בוא נתחיל.

המנחה קורא איפה המשחק עומד ועונה. בתשובה הראשונה בכל צ'אט הוא נותן את **הקישור ללוח הבקרה** (משהו כמו `http://127.0.0.1:4750`). לפתוח אותו בדפדפן ולהשאיר אותו לצד הצ'אט לאורך כל המשחק. כל קמפיין שומר על אותו קישור מצ'אט לצ'אט, אלא אם תוכנית אחרת תפסה אותו: אז המנחה נותן את החדש.

בין ההודעות של המנחה, המארח מציג את הכלים שהמנחה משתמש בהם, בשורות קצרות. לא לפתוח את הפרטים שלהם (ב-Claude Code, ctrl+o): הם עלולים להראות מה המנחה כותב, כולל סודות.

קמפיין חדש עובר שלושה שלבים, כמו משחק עם מנחה אנושי. לוח הבקרה מציג אותם למעלה כ-*1 הגדרות · 2 סשן אפס · 3 משחק*:

1. **הגדרות**: בוחרים איך רוצים לשחק. מחוץ לסיפור.
2. **סשן אפס**: יוצרים את הדמות, תוך כדי משחק.
3. **משחק**: הסיפור.

### 2.6 הגדרות: בחירת אופן המשחק

המנחה שואל רק את מה שעדיין חסר, כמה שאלות בכל פעם. אם כותבים "ההחלטה שלך", המנחה בוחר ואומר במה בחר. כשלוח הבקרה פתוח, השלב הראשון שלו, **הגדרות**, מציג את אותן שאלות ככרטיסים: שאלה אחת בכל פעם, כל ערך עם מה שהוא אומר, והרגיל מסומן **מומלץ**. בוחרים שם, והמנחה לא ישאל שוב בצ'אט; **דילוג** משאיר שאלה למאוחר יותר. הצ'אט מסדיר את מה שרק מילים יכולות: הנחת היסוד של עולם חדש, השפה, והתמונות, שעליהן המנחה שואל רק אם המחשב יכול ליצור אותן. לכן הדף שואל פחות שאלות ממה שהטבלה למטה מונה.

אין צורך ללמוד את הטבלה: היא נועדה לעיון. אפשר לשנות כל אחת מההגדרות האלה אחר כך, בצ'אט או ב**הגדרות** של לוח הבקרה. שינוי נכנס לתוקף מהתשובה הבאה של המנחה.

| הגדרה | מה היא קובעת | ערכים | מומלץ |
|---|---|---|---|
| **מנטור** (נשאל כ"כמה אתם מכירים את המשחק?") | כמה המנחה מלמד את החוקים, מחוץ לסיפור | **כבוי** (הסיפור בלבד; שואלים בסוגריים מרובעים מתי שרוצים), **רמזים** (טיפ קצר לפני בחירות חשובות וכשחוק חומק), **הדרכה** (כל חוק מוסבר בפעם הראשונה, כל סכום של כל הטלה, סיכום קצר אחרי קרבות) | לפי התשובה: מעולם לא שיחקתי ← הדרכה, קצת ← רמזים, אני מכיר ← כבוי |
| **רמת קושי** | כמה קשה העולם: קרבות, טקטיקות האויבים, רמזים, אוצרות, כמה מהר מתקדמים האיומים | story, easy, normal, hard, brutal | |
| **קטלניות** | מה משמעות הנפילה בקרב | **סיפורית** (הדמות לא מתה לעולם), **אפית** (מתה רק כשזה חשוב לסיפור), **קוביות** (הקוביות מחליטות) | לפי רמת הקושי: story ← סיפורית, easy ← אפית, normal ומעלה ← קוביות |
| **שמירות** | מתי אפשר לחזור אחורה | **permadeath** (אף פעם; רק להתחיל את הקמפיין מחדש), **checkpoint** (חזרה לסוף הסצנה האחרונה, רק אם הדמות מתה), **free** (חזרה לכל שמירה, ושמירה בכל רגע שמבקשים) | checkpoint |
| **קפדנות** | באיזו הקפדה עוקבים אחרי אוכל, אור, עייפות, משקל נישא, רכיבי לחש ומסעות לפי החוקים | **smooth** (המנחה מדלג עליהם), **rules** (כמו שכתוב: לפידים כבים, מנות אוכל אוזלות), **simulation** (מעבר לחוקים: בלאי, קלקול, מזג אוויר) | smooth |
| **קוביות** | מי מטיל את קוביות הדמות | **digital** (RPG Engine מטיל, על הדף), **physical** (מטילים בעצמכם ואומרים את התוצאות) | |
| **יחידות מידה** | מרחקים ומשקלים בסיפור | מטרי, אימפריאלי | |
| **בני לוויה** | מי מטייל איתך | אין, נוצרים איתך בסשן אפס, נוצרים על ידי המנחה, נפגשים במשחק | |
| **תמונות** | תמונות של מקומות ומשימות, ודיוקן הדמות כשמבקשים | אין, לפי בקשה, מקומות ומשימות חדשים | נשאל פעם אחת, רק אם המחשב יכול ליצור אותן |
| **קווים אדומים** | מה לא מופיע במשחק לעולם | רשימה, או אין | |
| **וילונות** | מה יכול לקרות, אבל רק מחוץ למסך | רשימה, או אין | |
| **שפה** | שפת המשחק ולוח הבקרה | כל שפה | נלקחת מאופן הכתיבה, ומאושרת |

מערכת המשחק יכולה להוסיף הגדרות משלה. המהדורה החמישית מוסיפה **התקדמות**: איך הדמות עולה ברמה, עם **נקודות ניסיון** או ב**אבני דרך** של הסיפור.

**מה משמעות רמת הקושי במשחק.** story: אויבים חלשים ותמימים, רמזים ברורים, שפע של הכול; המנחה רשאי לרכך את ההטלות שלו. easy: אויבים פשוטים, משאבים נדיבים. normal: אויבים הגיוניים, שלושה רמזים לכל מסקנה, מחירים ואוצרות רגילים. hard: אויבים חכמים, רמזים עדינים, משאבים מועטים, איומים שנעים מהר. brutal: אויבים שמארבים, נסוגים וגומרים את הנופלים, משאבים מועטים מאוד, מנוחות קשות ביותר. הקרבות תמיד בגודל שמתאים לחבורה כפי שהיא עכשיו.

**בלי עולם כתוב**, ההכנה שואלת שני דברים נוספים:

- **הנחת יסוד**: הז'אנר, הטון וכמה מרכיבים של העולם, במילים שלך. למשל: *"פנטזיה נמוכה, קודרת אבל עם תקווה. עיירה על נהר, מעבר מוכה רוחות, כת בגבעות."*
- **הכנה**: **תוך כדי משחק** (המנחה בונה כל חלק בעולם רגע לפני שצריך אותו; מומלץ) או **הכול בהתחלה**.

אחר כך המנחה מציע שם לקמפיין. כשלא חסר דבר ואומרים שמוכנים, המשחק עובר לסשן אפס.

### 2.7 סשן אפס: הדמות שלך

סשן אפס הוא משחק: יוצרים את הדמות עם המנחה, כמו סביב שולחן.

- **כל בחירה היא שלך**, אלא אם מבקשים מהמנחה לבחור. אפשר לבוא עם רעיון מלא ("כומר חצי-שדון שעזב את המקדש שלו"), עם רעיון מעורפל ("מישהו שמרפא, אבל לא נחמד") או בלי כלום ("תפתיע אותי, ואז תן לי לשנות").
- **ערכי יכולות.** המנחה אומר את השיטה ואת רשת הביטחון לפני שמוטלת קובייה כלשהי. במהדורה החמישית: המערך הסטנדרטי, קניית נקודות, או 4d6 בלי הנמוכה. השיטה שמסכימים עליה נשארת בהסכמות השולחן.
- **הסיפור של הדמות** אינו חובה לעולם. אם נותנים אחד, המנחה כותב אותו במילים שלך, מקריא אותו פעם אחת, וקושר את האנשים והמקומות שבו לעולם. אפשר גם לכתוב אותו בלוח הבקרה (ראו [חבורה](#party)).
- **אישיות** (המהדורה החמישית): תכונה, אידיאל, קשר ופגם, מטבלאות הרקע או משלך.
- **תמונה.** אחרי שהדמות נוצרה, המנחה מבקש תמונה שלה: קובץ במחשב, או דיוקן שנוצר במחשב לפי התיאור (ראו [תמונת הדמות](#37-your-characters-story-and-picture)).

המספרים בדף הדמות מחושבים על ידי RPG Engine מתוך הבחירות: אף פעם לא עושים חישובים. כשהדמויות נוצרו ומאשרים, הסיפור מתחיל.

## 3. לשחק <!-- icon: chat -->

### 3.1 לדבר עם המנחה

כותבים מה הדמות עושה או אומרת, במילים משלך. קצר זה בסדר.

> אני שואל את בעל הפונדק מי עוד עבר כאן הלילה.
>
> "לא באנו לעשות צרות," אני אומר, והיד רחוקה מהחרב.
>
> אני מטפס על הגג וממתין.

**מחוץ לסיפור**, כותבים בין סוגריים מרובעים:

> [איך עובד היאחזות?]
>
> [אפשר עוד להשתמש בתגובה שלי בסבב הזה?]
>
> [בואו נעצור כאן להערב.]

המנחה עונה גם הוא בסוגריים מרובעים, ואז חוזר לסיפור.

**אתה אומר מה אתה מנסה; המנחה אומר מה קורה.** דבר ששובר את ההיגיון של העולם או עובדות שכבר נקבעו לא קורה: המנחה אומר זאת, בתוך הסיפור, ומציע מה אפשרי.

**המנחה לא מחליט בשביל הדמות.** הוא לא יגרום לך לדבר, להרגיש או לבחור. במקרה של ספק, הוא שואל.

**המנחה לא מדבר על המנוע.** אם שואלים אותו אם הוא עוקב אחרי דברים, הוא עונה כמו מנחה: "אני שומר הכול: נמשיך מכאן בפעם הבאה."

**אפשר לשאול את המנחה איך משתמשים בלוח הבקרה.** הוא מכיר את הדף: "איפה רואים את הלחשים שלי?", "איך מטילים ידנית?"

### 3.2 הטלות

**מתי יש הטלה.** המנחה מבקש הטלה רק כשהתוצאה לא ברורה וחשובה. אחרת הוא אומר כן, או "כן, אבל". לפני ההטלה, המנחה אומר מה על הכף ואילו בדיקות מתאימות, ועוצר. מטילים, או משנים את דעתך:

> **המנחה:** הכרכוב צר ורטוב. אם תחליק, זו נפילה ארוכה אל הנהר. בדיקת זריזות (אקרובטיקה), או שאפשר לחזור ולחפש את המדרגות.
>
> **אתה:** אני אנסה.

**להטיל בלוח הבקרה.** כשהמנחה מבקש, מופיע בראש הדף שלט עם כפתור לכל בדיקה, למשל *אקרובטיקה ‏+4 · עם יתרון*. לוחצים: הקוביות נופלות על הדף, והמנחה שומע את התוצאה. אפשר גם:

- ללחוץ על השורה המתאימה בדף הדמות, שמוארת בזהב;
- להטיל את הקוביות המתאימות מהמגש;
- לכתוב מילים משלך בשלט, אם רוצים לעשות משהו אחר.

**להטיל ידנית.** אם מעדיפים לבחור את הקוביות בעצמכם, מפעילים **ידנית** בפינת השלט (או ב**הגדרות**). כפתור הבדיקה נעלם, והשלט אומר מה להטיל כמו שמנחה היה אומר: *הטל אקרובטיקה בעצמך, בדף הדמות או עם הקוביות.* לוחצים על השורה המוארת בדף הדמות, או מטילים את הקוביות המתאימות מהמגש: RPG Engine מטיל אותן, מוסיף את המתאם והמנחה שומע את התוצאה. בדיקה שלא דף הדמות ולא המגש יכולים לבצע, כמו נזק שמטיל מחדש את ה-1 שלו, שומרת על הכפתור שלה. **ידנית** נשאר פעיל בדפדפן הזה עד שמכבים אותו.

**קוביות פיזיות לכל המשחק.** כשההגדרה **קוביות** על physical, המנחה מבקש את ההטלות במילים וכותבים את הפאות שיצאו:

> [הטלתי 14.]

RPG Engine מוסיף את המתאמים ודוחה פאה שהקוביות שלך לא יכולות להראות.

**הטלות חופשיות.** לוחצים על כל מספר בדף הדמות, או פותחים את מגש הקוביות, כדי להטיל סתם בשביל הכיף. הטלות חופשיות לא נחשבות, לא נרשמות, והמנחה לא רואה אותן לעולם. 20 חופשי לא הופך לאמיתי אחר כך.

**ההטלות של המנחה.** המנחה מטיל עבור אויבים ואחרים גם הוא עם RPG Engine. רוב ההטלות מוצגות בעמודת ההטלות שלך. כשאסור לראות תוצאה, המנחה מטיל בסתר. תמיד אפשר לשאול:

> [ההטלה הזו הייתה אמיתית?]

על הטלה גלויה, המנחה נותן את המספרים והסיבה. על הטלה סודית, טביעת אצבע שמוכיחה שההטלה נעשתה לפני ששאלת.

**הטלות בצ'אט** מופיעות בסוגריים מרובעים, מיד אחרי הרגע שהן מכריעות: *[שכנוע 14 + 3 = 17]*. אחר כך הסיפור מספר את התוצאה.

### 3.3 סצנות וקרבות

המנחה מנהל את הסיפור ב**סצנות**: קרב, שיחה, חקירה, מסע, מנוחה, אתגר (מרדף, מירוץ, חידה). אין צורך לנהל אותן: כך RPG Engine שומר את פרקי הסיפור. בסוף כל סצנה המשחק נשמר מעצמו, והסצנה נכנסת לסיפור ביומן.

**בקרב**, המנחה מספר את כל התורות שאינן שלך, אחד אחרי השני, עם כל הטלה, ו**עוצר איפה שאפשר להחליט**: התור שלך, תגובה, בחירה. בתור שלך, אומרים מה עושים:

> אני מטיל Sacred Flame על זה שליד הדלת.

המדור **קרב** בלוח הבקרה מראה את סדר התורות, של מי התור, את נקודות החיים של החבורה ואת מצב האויבים (בלי פגע, פגוע, מדמם, מוטל: במילים, לא במספרים). אם הדמות נופלת, הטלות ההצלה מפני המוות מופיעות בגדול בדף.

**כשהקרב כבר הוכרע**, המנחה עשוי להציע לספר את השאר בהודעה אחת.

### 3.4 זמן, מסעות והעולם שנע

**זמן.** כל פעולה לוקחת זמן בסיפור, ו-RPG Engine שומר את התאריך: יום 3, בוקר מוקדם. המנחה מספר זמן כמו שהעולם מודד אותו: שחר, הפעמון השלישי, רדת הלילה. בין סשנים לא עובר זמן: ממשיכים מאיפה שעצרתם.

**מנוחות.** אומרים שנחים, והמנחה מחיל את מה שמנוחה מחזירה, כמו נקודות חיים ומשבצות לחשים:

> אנחנו מקימים מחנה ונחים מנוחה ארוכה.

**מסעות.** אומרים לאן רוצים ללכת:

> אנחנו לוקחים את הדרך צפונה אל רוקה.

RPG Engine מחשב את הדרך, את המרחק ואת הימים בקצב שלך, ומעביר אותך לשם. מסע נעצר כשקורה משהו מתוכנן בדרך, בסוף כל יום מסע ובהגעה. אפשר לשאול כמה רחוק מקום לפני שיוצאים:

> [כמה רחוקה רוקה, וכמה זמן ייקח ללכת אליה ברגל?]

**העולם נע גם בלעדיך.** לנבלים יש תוכניות עם מועדים ושעונים. בכל יום חדש המנחה מזיז את האיומים שהזמן קידם, ורואים את הסימנים שלהם: שמועה, עקבה, שינוי בעיירה. השעון עצמו אף פעם לא נראה, רק מה שהוא משאיר אחריו.

**כסף** נספר במטבעות המשחק. משלמים, מוכרים, מקבלים שכר: RPG Engine נותן עודף.

### 3.5 מפות

**מפת העולם** (בלוח הבקרה: **עולם**) מראה רק את המקומות שהדמות מכירה, עם הדרכים ביניהם, השביל שצעדתם בו, והערפל על כל השאר. לוחצים על מקום כדי לראות מה ידוע עליו וכמה הוא רחוק.

**מפת המקום** (בלוח הבקרה: **סצנה**, ו**קרב** בקרב) מופיעה כשהמנחה מצייר אחת למקום שבו אתם נמצאים: קירות, דלתות, הקרקע, ומי עומד איפה, כאסימונים. בקרב, בתור שלך, המשבצות שאי אפשר להגיע אליהן מכוסות בצעיף, וכך רואים במבט אחד לאן אפשר ללכת. כשהמנחה שואל לאן הדמות זזה, הדף פותח את המפה ונוגעים במשבצת, או כותבים אותה, כמו *E4*.

### 3.6 משימות, יומן ופתקים

**משימות.** כשהדמות לוקחת על עצמה משימה, היא הופכת למשימה ב**יומן**: מי נתן אותה, איפה, עד מתי, המטרות שלה ברשימה, ומה היא מודדת (מועד אחרון עם הזמן שנותר, שעון, ספירה). מסמנים משימה בכוכב שלה כדי לעקוב אחריה: היא נשארת קטנה בראש **סצנה**, עם המטרה הבאה שלה. המשימה מסתיימת כשהסיפור מסיים אותה, לעולם לא מעצמה.

**הסיפור.** לשונית הסיפור ביומן היא הקמפיין שלך כציר זמן: כל סצנה פרק, עם המקום, התאריך וסיכום קצר, האחרון ראשון.

**הפתקים שלך.** בלשונית הפתקים ביומן כותבים פתקים משלך: תיאוריות, שמות, תוכניות. הם נשארים במחשב והמנחה לא קורא אותם, אלא אם **לשתף** אחד. פתק משותף מגיע למנחה בתשובה הבאה שלו כמה שאתה חושב, לא כעובדה. התיאוריה שלך לא הופכת לנכונה כי כתבת אותה. פתק שמבקש לעצור או להימנע מתוכן מסוים נחשב כאילו אמרת זאת ליד השולחן.

### 3.7 הסיפור והתמונה של הדמות

בדף הדמות, בכרטיס **תיאור** יש תיבה לכתוב את סיפור הדמות. שולחים, והמנחה כותב אותו לתוך הדמות במילים שלו, אחרי שאומרים כן.

לתמונת הדמות, נותנים למנחה קובץ תמונה בצ'אט, עם המקום שלו במחשב (PNG, JPEG, WebP או SVG, עד 5 MB):

> [הנה הדיוקן של הדמות שלי: C:\Users\me\Pictures\mira.png]

המנחה מעתיק אותו לקמפיין, והוא מופיע על האסימון של הדמות בלוח הבקרה. אפשר להחליף אותו באותה דרך מתי שרוצים.

או שאפשר ליצור את הדיוקן, אם המחשב יוצר תמונות (ראו [תמונות](#311-pictures)): מתארים את הדמות למנחה, או נותנים למנחה לתאר אותה.

> [צור לי דיוקן: שיער אפור בצמה, צלקת על הסנטר, עיניים עייפות.]

הדיוקן מראה בדיוק מה הדמות במשחק, בני עמה כפי שהעולם הזה מכיר אותם, גמד גבעות כגמד גבעות, עם המראה שתיארת. הוא מגיע בתוך דקה בערך, על האסימון של הדמות. גם לבני הלוויה יכול להיות דיוקן כזה.

### 3.8 שמירות וחזרה אחורה

RPG Engine שומר את כל הקמפיין **בסוף כל סצנה**, מעצמו. מה שאפשר לעשות עם השמירות האלה תלוי בהגדרה **שמירות**:

| שמירות | לשמור כשרוצים | לחזור אחורה |
|---|---|---|
| **permadeath** | לא | אף פעם; אפשר רק להתחיל את הקמפיין מחדש |
| **checkpoint** | לא | לשמירה האחרונה, רק כשהדמות מתה |
| **free** | כן | לכל שמירה, מתי שרוצים |

בכל מצב אפשר **להתחיל מחדש**: מתחילת המשחק עם אותה דמות, או מסשן אפס עם דמות חדשה.

אפשר לעשות את כל זה בצ'אט ("[בואו נחזור לפני הדו-קרב.]") או במדור **שמירות** בלוח הבקרה.

**אחרי חזרה אחורה, לפתוח צ'אט חדש.** הצ'אט שבו שיחקתם זוכר מה בוטל. פותחים צ'אט חדש עם המנחה (`/clear` ב-Claude Code, `/new` ב-Codex), כותבים *המשך*, ואז לוחצים **נפתח צ'אט חדש** במדור שמירות, או אומרים למנחה בצ'אט החדש. לא להמשיך לעולם את הצ'אט הישן. עד שמאשרים, המנחה לא ימשיך.

### 3.9 סשנים: לעצור ולחזור

**מסיימים את הסשן** מתי שרוצים:

> [בואו נעצור כאן להערב.]

אין "לשמור ולצאת": הכול כבר בקבצים.

**כדי לסגור** את הצ'אט, כותבים `/exit` ב-Claude Code, או `/quit` ב-Codex. לוח הבקרה משתתק עד הצ'אט הבא.

**כדי לחזור**, פותחים טרמינל בתיקיית הקמפיין (זו ש-`init` הדפיס), מפעילים שם את המארח וכותבים *המשך*. המנחה קורא איפה המשחק עומד, נותן תקציר קצר, ומתחיל במשהו שקורה. צ'אט חדש לא מאבד כלום: הקמפיין חי בקבצים שלו, לא בצ'אט.

המנחה לא שואל שאלות שגרה בסוף. רק אם שם לב שמשהו לא עבד, הוא שואל בקצרה.

### 3.10 מצב הרוח של המנחה

בראש לוח הבקרה נמצא האווטאר של המנחה, רובוט קטן. הפנים שלו עוקבות אחרי הטון של הסיפור: מודאג כשהסכנה גוברת, שמח מרעיון נועז, מופתע מתפנית. הוא מגיב לרגע ל-20 טבעי או ל-1 טבעי. הוא לעולם לא מראה מה שעוד לא ידוע: בלי חיוך לפני שהמלכודת נסגרת. גם האסימונים של החבורה מראים מצבי רוח. כשהצ'אט סגור, הרובוט ישן.

### 3.11 תמונות

RPG Engine יכול ליצור תמונה לכל מקום שמגיעים אליו ולכל משימה שלוקחים, כפי שההגדרה **תמונות** קובעת, ואת דיוקן הדמות כשמבקשים. הוא משתמש במה שכבר נמצא במחשב:

- **Codex**, עם ההתחברות ל-ChatGPT: תמונה מצוירת בצבע.
- אחרת **Claude Code**, עם ההתחברות ל-Claude: רישום.

התמונה משתמשת בתוכנית שלך, לא בשלנו. המדור **הגדרות** אומר אם אפשר ליצור תמונות במחשב, ואם לא, מה השלבים להגדרה. בלי תמונות, הדף מציג במקומן את הסימן של כל סוג מקום. אפשר גם לתת למנחה תמונה משלך לכל מקום או דמות.

### 3.12 ביטחון: קווים אדומים, וילונות ועצירה

- **קווים אדומים**: מה שלא מופיע במשחק לעולם.
- **וילונות**: מה שיכול לקרות, אבל רק מחוץ למסך.
- **עצירה**: בכל רגע אפשר לעצור תוכן, בלי להסביר. כותבים זאת מחוץ לסיפור:

> [stop]

המנחה זונח אותו מיד ומוסיף אותו לקווים האדומים, לכל הסשנים הבאים. אפשר לראות ולשנות את הקווים האדומים והווילונות ב**הגדרות**.

### 3.13 לשנות את הדעה

אפשר לשנות כל הגדרה במהלך הקמפיין: בצ'אט ("[בואו נעשה את זה קשה יותר.]") או ב**הגדרות**. המנחה שומע על שינוי בתשובה הבאה שלו. פסיקה שהמנחה נתן בלי הספר הופכת ל**תקדים** ונשמרת, כך שאותה שאלה תקבל אותה תשובה בפעם הבאה.

## 4. לוח הבקרה, מדור אחר מדור <!-- icon: party -->

לוח הבקרה הוא דף במחשב שלך. המנחה נותן את הקישור שלו בתחילת כל צ'אט. הוא עוקב אחרי המשחק בזמן אמת: כשהמנחה משנה משהו, הדף משתנה גם הוא.

רק הדפדפן של המחשב שבו משחקים יכול לפתוח אותו: לא טלפון או טאבלט, גם לא באותה רשת Wi-Fi. הדף מתאים גם לחלון צר: אז המדורים עוברים לסרגל בתחתית, והסמלים לתפריט.

הדף חי כל עוד הצ'אט חי. אם סוגרים את הצ'אט, דף שנשאר פתוח מציג *לא מחובר* עם דף הדמות כפי שהיה, והרובוט של המנחה נרדם; פותחים שוב צ'אט בקמפיין, ואחרי שהמנחה ענה, הדף חוזר מעצמו.

### למעלה

- **האווטאר של המנחה**, עם מצב הרוח שלו.
- שם הקמפיין, מערכת המשחק, **זמן המשחק** והאם המשחק **מחובר** (הצ'אט מחובר).
- המדורים: **חבורה**, **סצנה**, **קרב** (רק בזמן קרב), **יומן**, **עולם**; בסוף השורה, כסמלים: **שמירות**, **עזרה**, **הגדרות**, **אודות**.
- ערכת הנושא הבהירה והכהה, בפינה הימנית העליונה.

כשהמנחה שואל משהו, השלט שלו נשאר בראש הדף, בכל מדור שלא תהיו.

### חבורה

דף הדמות שלך, ושל בני הלוויה. כל חלק בדף הוא כרטיס שאפשר לפתוח ולסגור.

- **ללחוץ על מספר** כדי להטיל אותו בשביל הכיף. מצביעים על מספר כדי לראות איך הוא מורכב ("+5: חוכמה ‏+3, מיומנות ‏+2").
- **נקודות חיים, משבצות ושימושים** מוצגים כפסים וכנקודות.
- **מצבים והשפעות** מוצגים עם משך הזמן שלהם.
- **תיאור** מחזיק את הטקסט של הדמות, ואת התיבה לשלוח למנחה את סיפור הדמות.
- ב-0 נקודות חיים, **הטלות ההצלה מפני המוות** מופיעות בגדול מתחת לשם.
- לצד הדף (מתחתיו במסך צר): **ההטלות**, החדשה ראשונה, שלך ושל המנחה שמותר לראות. **ניקוי** מרוקן את הרשימה; **שחזור** מחזיר אותה. הטלות חופשיות מוצגות מקווקוות ועמומות.

בן לוויה עם דף יצור, כמו זאב, מציג את דף היצור שלו במקום דף דמות מלא.

### סצנה

איפה החבורה נמצאת: התמונה והשם של המקום, המקומות סביבו, מפת המקום כשיש כזו, מי נמצא שם, והסצנה הפתוחה עם מה שקורה עכשיו. המשימה שעוקבים אחריה נמצאת למעלה.

### קרב

רק בזמן קרב. למעלה: הסבב, מי פועל, מי הבא. למטה: סדר התורות, כל לוחם עם מצבו, החבורה במספרים והאויבים במילים; מה שיש לדמות בהישג יד (Classe Armatura, נקודות חיים, התקפות); מפת המקום, עם הפועל מוקף בטבעת. בתור שלך הקישור לקרב פועם בזהב, בכל מקום שתהיו.

### יומן

שלוש לשוניות:

- **משימות**: פעילות, שהושלמו ושנכשלו, כל אחת ככרטיס עם המטרות שלה, המועד האחרון שלה כטיימר והשעונים שלה. הכוכב עוקב אחרי משימה.
- **סיפור**: פרקי הקמפיין, סצנה אחר סצנה, האחרון ראשון.
- **פתקים**: הפתקים שלך, פרטיים עד שמשתפים אחד.

### עולם

מפת העולם כפי שהדמות מכירה אותו, עם הערפל על השאר. גוררים כדי להזיז, גלגלת או צביטה כדי להתקרב. לוחצים על מקום לכרטיס שלו. רשימת המקומות, הקרוב ראשון, נמצאת לצדו. כשיש יותר ממפה אחת (עיר, יבשת, מישור אחר), לשוניות מחליפות ביניהן.

### מגש הקוביות

כפתור הקוביות פותח את המגש: בוחרים קוביות ומתאם, ומטילים. עם שתי קוביות או יותר מאותו סוג, בוחרים אילו נספרות: **הכול**, **גבוה** (רק הגבוהה ביותר) או **נמוך** (רק הנמוכה ביותר). הקוביות שבחרתם נשארות עד שלוחצים **ניקוי**, כך שאותה הטלת נזק היא לחיצה אחת בכל סבב. בזמן שהמנחה מבקש הטלה, המגש אומר אילו קוביות עונות עליה.

### שמירות

השמירות שלך, החדשה ראשונה, כל אחת עם המקום שלה, תאריך המשחק ומתי נוצרה. **לשמור עכשיו** (עם שמירות חופשיות), **לחזור לכאן**, ו**להתחיל מחדש**, באדום, בשני שלבים. ראו [שמירות וחזרה אחורה](#38-saves-and-going-back).

### הגדרות

ההגדרות שלך, בקבוצות: המשחק, ללמוד את המשחק (המנטור והחוקים שכבר הוסברו לך), קוביות ומידות, גבולות (קווים אדומים ווילונות), תמונות, שפה. לוחצים על ערך כדי לבחור; מתחתיו, מה הוא אומר. אחר כך ההעדפות של הדף עצמו, שנשמרות בדפדפן הזה בלבד: ערכת הנושא, הצליל של הקוביות, **סט הקוביות** (שרף, מתכת, עץ, אבן), קצוות מעוגלים או חדים, הטלה ידנית.

ההגדרות של המנחה עצמו, כמו חוקי בית ותקדימים, אינן כאן: הן נשארות בצ'אט.

### עזרה ואודות

**עזרה**: המדריך הזה. **אודות**: מהו RPG Engine, הקישורים שלו, הרישיונות שלו, והקרדיטים של מערכת המשחק.

### לפני המשחק: הגדרות וסשן אפס

כשקמפיין חדש בשלב הראשון שלו, **הגדרות**, כל הדף שואל את השאלות שלו: אחת בכל פעם, כל אחת עם מה שהערכים שלה אומרים והערך המומלץ. **ההחלטה שלך** משאיר שאלה למנחה, חוץ מקווים אדומים ווילונות, שהם תמיד שלך; **דילוג** משאיר אותה למאוחר יותר. בסוף, **אפשר להתחיל**.

### הודעות מהדף

לפעמים הדף מציג הודעה מעל עצמו: בעיה בקבצי הקמפיין (המנחה מתקן), המשחק לא זמין (הצ'אט סגור), הדף בתהליך תרגום.

## 5. מערכות משחק וחוקי בית <!-- icon: dice -->

### 5.1 מהי מערכת משחק

מערכת משחק היא הנתונים של משחק אחד: דף הדמות שלו, המספרים שלו, היצורים, החפצים, הלחשים וטקסט החוקים שלו. כל קמפיין משחק מערכת אחת.

RPG Engine מחשב את דף הדמות ואת מה שמוצא ומה שחוזר, כמו נקודות חיים ומשבצות לחשים, כמו שדף דמות דיגיטלי עושה. איך יכולת או לחש עובדים, המנחה קורא בחוקים ומחליט, כמו ליד שולחן.

### 5.2 המהדורה החמישית, כלולה

RPG Engine מגיע עם **5e**, מתוך System Reference Document 5.1 (חוקי 2014, חופשיים תחת Creative Commons). היא כוללת:

- את הגזעים, המקצועות, תתי-המקצועות, רקע ויכולת מיוחדת של ה-SRD;
- את 319 הלחשים, את הנשקים, השריונות והציוד, את החפצים הקסומים ואת המפלצות של ה-SRD;
- את פרקי החוקים, שהמנחה מחפש לפי הטקסט המדויק שלהם;
- את דף הדמות המלא, מחושב: מתאמי יכולות, שמירות (tiri salvezza), מיומנויות, Classe Armatura, התקפות, דרגת הקושי של הלחשים, משבצות, קוביות חיים, יכולות לפי רמה, ניסיון ועלייה ברמה;
- מנוחות שמחזירות מה שצריך; מצבים עם טקסט החוק שלהם; תזכורות ריכוז.

**תוכן מעבר ל-SRD.** אפשר לשחק במהדורה החמישית עם תוכן שחסר ב-SRD, כמו מקצוע או מפלצת מספר שברשותך. המנחה מכיר את המשחק, יכול לקרוא את הספרים שלך ויכול לחפש ברשת. הוא כותב מה שהוא צריך כדפים של הקמפיין, ו-RPG Engine עובד איתם באותו אופן. מה שאנחנו מספקים מוגבל על ידי הרישיון שלו; מה שהמנחה שלך יודע אינו מוגבל.

RPG Engine תואם למהדורה החמישית.

### 5.3 חוקי בית ותוספות משלך

אין צורך לגעת באף קובץ. מבקשים מהמנחה:

> [חוק בית: 1 טבעי בהתקפה אומר שהנשק נופל לך מהיד.]
>
> [הייתי רוצה לשחק Blood Hunter. יש לי את הספר: הנה יכולות המקצוע.]
>
> [בקמפיין הזה, מנוחה קצרה לוקחת 10 דקות.]

המנחה רושם אותם בקמפיין שלך, באחת הדרכים האלה:

- **הסכמה של השולחן**, במילים, כמו הנשק שנופל או המנוחה הקצרה למעלה. המנחה שומר אותה עם הגדרות הקמפיין ומשחק לפיה מאז. פסיקה שהמנחה נתן בלי הספר נשמרת באותו אופן, כ**תקדים**.
- **דף חדש**, כמו מקצוע, גזע או חפץ. מקצוע חדש עובד כמו של המערכת: הרמה, קוביות החיים והיכולות שלך סופרים אותו. גזע חדש יכול להתבסס על קיים ("כמו השדון, ועוד…"); חרב בעלת שם יכולה להתבסס על החרב הארוכה.
- **מספרים חדשים לדף הדמות**: שדה, טבלה, נוסחה, מונה שמנוחה מחזירה. למשל, קוביות העליונות של Battle Master שחוזרות במנוחה קצרה. חוק בית יכול גם להחליף אחת מהנוסחאות של המערכת.

אם כבר כתובים חוקי בית, אפשר גם להניח אותם כקבצי טקסט בתיקיית `rules` של הקמפיין (ראו [תיקיית הקמפיין](#8-for-the-curious-the-campaign-folder)): המנחה קורא אותם לפני חוק הספר בעל אותו שם.

### 5.4 להוסיף או לייבא מערכת משחק משלך

היום RPG Engine משחק רק את המהדורה החמישית. מערכות משחק נוספות יגיעו, וגם דרך להוסיף משלך, או להפוך משחק שברשותך למערכת מתוך הספרים שלו. ראו [בקרוב](#9-coming-later).

## 6. הרחבות <!-- icon: plus -->

**הרחבות עדיין אינן זמינות.** הרחבה תוסיף משהו לקמפיין מעל מערכת המשחק שלו: עולם, הרפתקה, יכולת כמו מזג אוויר או חפיסת טארוט, חוקי בית לשיתוף. תבחרו אילו מהן כל קמפיין משתמש. הראשונות המתוכננות למהדורה החמישית הן מזג אוויר ופריצת מנעולים.

## 7. מאיפה בא קמפיין, והשפה שלו <!-- icon: world -->

### 7.1 שלוש דרכים לקבל עולם

**נוצר תוך כדי משחק.** נותנים הנחת יסוד בהכנה, והמנחה בונה את העולם תוך כדי: כל מקום, אדם ועלילה רגע לפני שצריך אותם, ונשמרים מאז. זו הדרך המהירה ביותר לשחק: מתקינים, יוצרים, ותוך כמה דקות כבר יוצרים דמות. שום דבר שהומצא לא הולך לאיבוד: ברגע שנאמר, הוא נכתב ונשאר נכון.

**מוכן בהתחלה.** אותה הנחת יסוד, אבל עם **הכנה: הכול בהתחלה**, המנחה בונה את המקומות, הפלגים, האיומים והתוכניות שלהם לפני שהמשחק מתחיל. הסשן הראשון מתחיל מאוחר יותר, עם יותר מוכן מאחורי הקלעים.

**מקמפיין או הרפתקה קיימים.** היום אין כפתור ייבוא. נותנים למנחה את ההרפתקה (טקסט או PDF שהמארח יכול לקרוא) ומבקשים ממנו להכין אותה:

> [יש לי את ההרפתקה הזו כ-PDF. הכן אותה ככמפיין שלנו: קרא אותה, וכתוב את המקומות, הדמויות והסודות שלה. אל תגלה לי שום דבר ממה שכתוב בה.]

המנחה קורא אותה עם הכלים של מארח הבינה המלאכותית וכותב אותה כדפי קמפיין, כולל הסודות, שתגלו במשחק. Claude Code קורא קובצי PDF; עם Codex, קובץ טקסט או markdown הוא בחירה בטוחה יותר. עושים זאת בזמן ההכנה, לפני סשן אפס.

בזמן שהמנחה עובד, לא לפתוח את הפרטים של מה שהוא קורא או כותב (ב-Claude Code, ctrl+o): הם מראים את טקסט ההרפתקה, כולל הסודות. המנחה עצמו שומר את הסודות, כמו תמיד.

ברגע שיש לקמפיין דפים משלו, ההכנה מפסיקה לשאול על הנחת יסוד והכנה. גם בקמפיין כתוב, כשהולכים למקום שהטקסט לא מכסה, המנחה יוצר את מה שצריך ורושם אותו.

**קמפיין משחקים פעם אחת.** כדי לשחק שוב את אותה הרפתקה, יוצרים קמפיין חדש. בתוך קמפיין אפשר עדיין לחזור לשמירה או להתחיל מחדש, כפי שההגדרה שמירות מתירה.

### 7.2 שפות

**שפה אחת לקמפיין**: זו של המנחה. המנחה כותב בה, ולוח הבקרה עוקב אחריה. המנחה לוקח אותה מאופן הכתיבה שלך, ומאשר אותה.

**לוח הבקרה** מגיע באנגלית ובאיטלקית (בעריכה קפדנית) וב-24 שפות נוספות: צרפתית, גרמנית, ספרדית, פורטוגזית (ברזילאית), הולנדית, שוודית, נורווגית, דנית, פינית, איסלנדית, רוסית, אוקראינית, פולנית, צ'כית, רומנית, הונגרית, יוונית, טורקית, ערבית, עברית, הינדי, סינית, יפנית, קוריאנית. ערבית ועברית נקראות מימין לשמאל: הדף מתהפך, והמפות והקוביות נשארות כפי שצוירו.

**כל שפה אחרת** שבוחרים ב**הגדרות** מתורגמת במחשב שלך, ברקע, על ידי Codex או Claude Code עם ההתחברות שלך, החל מהמדור שפתוח. זה נעשה פעם אחת לכל שפה, לכל הקמפיינים. עד שהתרגום מוכן, הדף באנגלית. ההגדרות אומרות אם התרגום בעיצומו, מוכן, או בלתי אפשרי במחשב שלך.

**מילות המשחק.** המהדורה החמישית מביאה את המונחים שלה באיטלקית מה-SRD האיטלקי הרשמי, כך ששחקנים איטלקים קוראים *Classe Armatura*, *tiro salvezza*, *vantaggio*. בשפות אחרות מונחי המערכת מתורגמים.

**הטקסט של מערכת המשחק עצמה** (הלחשים, המפלצות, פרקי החוקים) נשאר באנגלית. המנחה קורא אותו ומספר לך אותו בשפה שלך.

**החלפת שפה באמצע קמפיין** משאירה את הדפים שכבר נכתבו כפי שהם; המנחה כותב חדשים בשפה החדשה.

## 8. לסקרנים: תיקיית הקמפיין <!-- icon: list -->

אף פעם אין צורך לפתוח אותה. אם פותחים, כדאי לדעת ש**היא מחזיקה את הסודות** של הקמפיין: קריאה בה קלקלה את המשחק.

תיקיית קמפיין מחזיקה:

- `campaign.yaml`: ההגדרות שלך;
- `state.yaml`: איפה המשחק עומד עכשיו: השלב, התאריך, הסצנה הפתוחה;
- `world/`: דף אחד לכל דמות, מקום, פלג, משימה, חפץ, אירוע, נושא או יצור, כקובצי markdown;
- `rules/`: חוקי הבית שלך כקובצי טקסט, אם מוסיפים (`init` לא יוצר אותה);
- `images/`: התמונות, כשיש כאלה;
- `log.jsonl`: כל שינוי, לפי הסדר;
- `.saves/`: השמירות, מהראשונה ואילך;
- `.player/`: הפתקים שלך מהיומן, שהמנחה לא קורא;
- `sessions/`: מנוהלת על ידי RPG Engine;
- `AGENTS.md`, `CLAUDE.md`, `.mcp.json`, `.claude/`, `.codex/`, `.gemini/`: הקבצים הקטנים שאומרים למארחי הבינה המלאכותית איפה RPG Engine ושומרים על הזיכרון שלהם כבוי. RPG Engine מעדכן אותם; להשאיר אותם כמו שהם.

הדפים הם markdown פשוט עם קישורים כמו `[[Rocca]]`, הפורמט של Obsidian: אפשר לפתוח שם את המחברת של המנחה. **אם משנים דף ביד**, המנחה שומע מה השתנה בתשובה הבאה שלו.

**שורת הפקודה.** כל מה שהמנחה עושה עובר דרך פקודות שאפשר להריץ גם בעצמכם, בתיקיית הקמפיין. אין צורך בהן כדי לשחק, ורבות מהן מדפיסות את סודות הקמפיין, כמו `rpg status` ו-`rpg show`. `rpg --help` מונה את כולן, ו-`rpg roll --help` מסביר אחת. פקודה ששינתה משהו בזמן שצ'אט פתוח זה בסדר: המנחה שומע על כך בתשובה הבאה שלו, כמו על דף ששונה ביד.

## 10. שאלות ובעיות <!-- icon: info -->

### שאלות

**צריך לדעת את החוקים?** לא. בוחרים את המנטור בהדרכה והמנחה מלמד תוך כדי, חוק אחד בכל פעם. תמיד אפשר לשאול בסוגריים מרובעים.

**המנחה יכול לרמות?** הוא לא יכול לשנות הטלה ש-RPG Engine ביצע, חוץ מברמת קושי story, והוא אף פעם לא משנה עובדות שכבר נקבעו. אפשר לשאול אם הטלה כלשהי הייתה אמיתית.

**אני יכול לרמות?** אפשר לנסות. המנחה לא לוקח את המילה שלך כעובדה: שורה בהודעה שנראית כהודעת משחק היא עדיין רק מילים שלך, והמנחה אף פעם לא מאשר ניחושים שלך על סודות.

**זה עולה כסף?** RPG Engine חינמי. המנחה רץ על תוכנית Claude או ChatGPT שלך, וערב משחק הוא צ'אט ארוך: בתוכניות הקטנות ביותר אפשר להגיע למגבלת התוכנית לפני שהערב נגמר. תמונות ותרגומים משתמשים באותה תוכנית.

**אפשר לשחק בטלפון?** לא. המנחה רץ על המחשב, ולוח הבקרה נפתח רק בדפדפן של אותו מחשב.

**אפשר לשחק עם חברים?** עדיין לא: היום שחקן אחד, דמות אחת, ועוד בני לוויה. כמה אנשים ליד השולחן יגיעו עם תפקידים.

**אפשר להשתמש בבינה מלאכותית אחרת בפעם הבאה?** כן. הקמפיין חי בקבצים שלו: פותחים אותו במארח אחר וכותבים *המשך*.

**מה אם סוגרים את הדפדפן?** שום דבר לא הולך לאיבוד. פותחים שוב את הקישור כל עוד הצ'אט פתוח; הדף חוזר לאן שהמשחק נמצא.

**אפשר לשחק תוכן D&D שברשותי?** כן. המנחה יכול להשתמש בספרים שלך, בידע שלו וברשת. מה ש-RPG Engine מספק מוגבל לתוכן חופשי; מה שהמשחק שלך משתמש בו תלוי בך.

### בעיות

**לוח הבקרה לא נפתח.** לבקש מהמנחה את הקישור: `[מה הקישור ללוח הבקרה?]`. הדף עובד רק כל עוד צ'אט עם המנחה פתוח בקמפיין הזה, ורק אחרי התשובה הראשונה של המנחה באותו צ'אט. כשהצ'אט סגור, הדפדפן לא מגיע לדף; דף שנשאר פתוח אומר *לא מחובר*.

**נראה שהמנחה לא מכיר את המשחק, או ממציא כלים.** מארח הבינה המלאכותית לא טען את RPG Engine.

- קודם, לבדוק שהפעלתם את המארח **בתיקיית הקמפיין**, ושאמרתם שסומכים עליה.
- **Claude Code**: לכתוב `/mcp`. אם `rpg` שם אבל נכשל, לבחור בו, ואז **Reconnect**. אם הוא חסר, לסגור את Claude Code, לכתוב `claude mcp reset-project-choices` בתיקיית הקמפיין, ולהפעיל אותו שוב.
- **Codex**: לכתוב `codex mcp list` בטרמינל, בתיקיית הקמפיין. אם `rpg` חסר, Codex לא סומך על התיקייה: להפעיל אותו שוב שם ולענות כן כשהוא שואל.
- בשניהם: אם `rpg --version` בטרמינל אומר שהפקודה לא נמצאה, להתקין שוב את RPG Engine ([2.2](#22-install)) ולפתוח טרמינל חדש.

**אחרי עדכון, שום דבר לא השתנה.** מנחה שרץ שומר על הגרסה שאיתה התחיל. לפתוח צ'אט חדש, או ב-Claude Code לחבר מחדש את השרת (`/mcp`, ואז `rpg`, ואז **Reconnect**).

**המנחה זוכר משהו שביטלתי.** חזרתם לשמירה אבל המשכתם לשחק באותו צ'אט. לפתוח צ'אט חדש וללחוץ **נפתח צ'אט חדש** במדור שמירות.

**המנחה שואל שאלות הכנה שכבר עניתי עליהן בדף.** לומר לו: `[בחרתי אותן בלוח הבקרה.]`

**לא מופיעות תמונות.** לפתוח הגדרות > תמונות: הדף אומר אם המחשב הזה יכול ליצור אותן, ואת השלבים אם לא, כל פקודה עם כפתור להעתקה.

**הדף באנגלית אבל בחרתי שפה אחרת.** הוא מתורגם ברקע; ההגדרות אומרות איך זה מתקדם. בלי Codex או Claude Code במחשב הזה, הוא נשאר באנגלית.

**המנחה אומר שיש בעיות בקמפיין.** הוא מתקן אותן בעצמו. אם ערכתם קבצים ביד, הוא עשוי לשאול מה התכוונתם.

**Windows: `npm` נכשל בתיקייה שלי.** לא לשמור את הקמפיין, או את RPG Engine, בנתיב שמכיל `&`.

**ההתקנה נכשלת, או ש-`rpg` לא עולה.** לבדוק את גרסת Node.js עם `node --version`: היא חייבת להיות 22 או חדשה יותר. אם היא ישנה יותר, להתקין את גרסת ה-LTS מ-[nodejs.org](https://nodejs.org), ואז להתקין שוב את RPG Engine.

**הקישור ללוח הבקרה השתנה.** תוכנית אחרת השתמשה בכתובת הרגילה של הקמפיין, או ש-Windows שמרה אותה. RPG Engine לקח כתובת אחרת; המנחה נותן את הקישור החדש. שום דבר אחר לא משתנה.
