# RPG Engine：完整指南

**RPG Engine** 让你与一位 **AI 主持人** 一起玩桌面角色扮演游戏。

你在 **聊天** 里和主持人交谈：主持人讲述故事，扮演其他所有人，并裁定发生的一切。

RPG Engine 在幕后工作：它会 **记住世界**，**掷骰子**，还会 **记好账目**。

聊天旁边，你在浏览器里开着一个页面，也就是 **仪表盘**。上面有你的角色的角色卡、骰子、地图和日志。

这份指南写给玩家：你不需要会编程。

## 快速开始 <!-- icon: send -->

1. 从 [nodejs.org](https://nodejs.org) 安装 **Node.js**（LTS 版本）。
2. 安装 **Claude Code** 或 **Codex**，也就是主持人运行所在的 AI 应用，并登录（[2.4](#24-connect-your-ai)）。
3. 打开终端，安装 RPG Engine：`npm install -g rpg-engine`。
4. 在终端里创建战役：`rpg init "The Salt Isles"`。
5. 在新文件夹里打开 Claude Code 或 Codex，写下 *你好！我们开始吧。* 主持人会回复仪表盘的链接：把它打开，放在聊天旁边。

本指南的其余部分会详细解释每一步，然后讲怎么玩。

## 1. RPG Engine 是什么 <!-- icon: about -->

### 谁负责什么

| 谁 | 做什么 |
|---|---|
| **你** | 扮演你的角色。说出角色做什么、说什么、尝试什么。 |
| **主持人**（AI） | 讲述故事，扮演所有其他角色，决定发生什么，要求掷骰。 |
| **RPG Engine** | 把一切记在文件里，掷骰子，计算生命值、金钱、时间和距离，在你发现之前替你保守秘密。 |

AI 擅长讲故事，却不擅长记忆。放着不管，它会忘记谁欠你钱、你还剩几支箭，或者桥在两次游戏之前就烧毁了。RPG Engine 把这些全部记下来，所以世界在每个晚上之间保持一致，即使换了新聊天，甚至换了另一个 AI。

### 玩起来是什么感觉

你在聊天里写字，就像在桌边说话：

> 我慢慢推开门，往里看。

主持人回答你看到的东西，并在轮到你选择时停下。遇到不确定又重要的事，主持人会说明风险，并要求掷骰。掷骰的按钮会出现在你的仪表盘上。你点一下，骰子落在页面上，主持人告诉你发生了什么。

### 它有何不同

- **世界是持久的。** 说过的事就是真的。死掉的反派不会复活。
- **骰子是真的。** 主持人无法操纵骰子（除非你选了最简单的难度）。
- **秘密始终是秘密。** 角色不知道的事，主持人绝不会告诉你，哪怕你再三追问。
- **世界不会等你。** 你休息或赶路时，威胁仍在推进，你会看到它们的迹象。
- **许多个夜晚，一个故事。** 战役就是你电脑上的一个文件夹。你可以随时停下，以后再接着玩。

### 目前能玩的游戏

RPG Engine 为任何桌面角色扮演游戏而设计。目前内置一个游戏系统：**第五版**（来自免费的系统参考文档 5.1）。其他游戏会陆续加入；见[游戏系统](#5-game-systems-and-house-rules)和[以后会有](#9-coming-later)。

## 2. 开始上手 <!-- icon: path -->

### 2.1 你需要什么

- 一台装有 Windows、macOS 或 Linux 的电脑。
- **Node.js 22** 或更新版本。从 [nodejs.org](https://nodejs.org) 下载，选“LTS”版本即可。它自带 `npm`，用来安装 RPG Engine。
- 一个**终端**，也就是输入命令的窗口。Windows 上用“终端”应用或 PowerShell，macOS 上用“终端”。你要用它来安装 RPG Engine、创建每个战役，以及启动 Claude Code 或 Codex。
- 一个 **AI 宿主**，也就是主持人运行所在的应用：**Claude Code** 或 **Codex**，并备好它的套餐和登录账号。见 [2.4](#24-connect-your-ai)。
- 宿主提供的**最大模型**。小模型容易被骗：在我们的测试里，它把秘密告诉了自称是真主持人的玩家。
- 一个网页浏览器，用来打开仪表盘。

你登录宿主的账号还有别的用处。RPG Engine 会在你的电脑上用它来绘制地点、任务、你遇到的人物和你的角色的图片，也用它把仪表盘翻译成自带语言之外的语言。见 [图片](#311-pictures) 和 [语言](#72-languages)。

**在文件夹里打开终端。** 许多步骤会说“在战役文件夹里”。在 Windows 上，在文件资源管理器中右键点击文件夹，选择**在终端中打开**。在 macOS 上，在访达中右键点击文件夹，选择**服务 > 新建位于文件夹位置的终端窗口**。也可以在已打开的终端里输入 `cd` 加文件夹的路径，例如 `cd "C:\Users\me\Games\The Salt Isles"`。

### 2.2 安装

打开终端，输入：

```text
npm install -g rpg-engine
```

这样你就有了 `rpg` 命令。检查是否安装成功：

```text
rpg --version
```

每个战役只需用一次 `rpg`，用来创建战役。之后你只要和主持人交谈：你的 AI 宿主会用同样的 `rpg` 命令自动启动 RPG Engine。

### 2.3 创建战役

战役就是一个文件夹。在存放你的游戏的文件夹里打开终端，输入：

```text
rpg init "The Salt Isles"
```

这会生成文件夹 `The Salt Isles`，里面有一个新战役，并告诉你下一步做什么：

```text
Created the campaign "The Salt Isles" in C:\Users\me\Games\The Salt Isles.
To play, open Claude Code or Codex in this folder and say hello: the master asks you the rest.

For the master: Still to agree with the player: ...
```

*For the master* 之后的几行是写给主持人的，主持人会在聊天里读到：你不用管。记住这个文件夹在哪里，每次游戏都要回到这里。如果不写文件夹名，`rpg init` 会把你当前所在的文件夹变成战役。

`init` 会生成战役需要的一切：设置、世界文件夹，以及一些小文件，它们告诉你的 AI 宿主使用 RPG Engine，并且不要在战役之外保留自己的记忆。

现在不用选任何东西。主持人会在聊天里问你其余的问题，你也可以在仪表盘上选择。如果你已经想好了一些选项，可以在这里直接给出：

```text
rpg init salt-isles --name "The Salt Isles" --language en --system 5e --difficulty normal --lethality dice
```

这会生成文件夹 `salt-isles`，里面是战役 *The Salt Isles*。文件夹名不带空格，战役名则随你喜欢。

| 选项 | 设置内容 | 可选值 |
|---|---|---|
| `--name` | 战役的名称 | 任意；不写则用文件夹名 |
| `--language` | 游戏的语言 | 语言代码，如 `en`、`it`、`fr` |
| `--system` | 游戏系统 | `5e`，目前只有这一个 |
| `--difficulty` | 世界有多难 | `story`, `easy`, `normal`, `hard`, `brutal` |
| `--lethality` | 在战斗中倒下意味着什么 | `narrative`, `epic`, `dice` |

`rpg init --help` 也会列出这些选项。战役不能放在另一个战役的文件夹里面。

你不能让主持人来创建战役：在运行 `init` 之前，文件夹里没有任何东西能告诉你的 AI 宿主 RPG Engine 在哪里。

### 2.4 连接你的 AI

RPG Engine 可以配合 **Claude Code** 和 **Codex** 使用。其他支持 MCP 工具的 AI 应用也许可行，但我们不作保证。

**安装宿主。** Claude Code 和 Codex 在终端里运行，不是手机上的 Claude 或 ChatGPT 应用。它们各自需要自己的套餐和登录：Claude Code 需要付费的 Claude 套餐，Codex 需要 ChatGPT 账号登录。请按它们各自的页面安装并登录：[Claude Code](https://code.claude.com/docs/en/setup) 和 [Codex](https://learn.chatgpt.com/docs/codex/cli)。这一步只做一次，所有战役通用。

**Claude Code。** 在战役文件夹里打开终端，输入 `claude`。第一次运行时，它会问你是否信任这个文件夹，并说明该文件夹允许使用游戏的工具（`mcp__rpg`）：选择 **Yes, I trust this folder**。注意：默认选中的是 *No, exit*，所以直接按回车会关闭 Claude Code。这样就好了：战役已经告诉 Claude Code 使用 RPG Engine 和它的工具，并关闭它自己的记忆。

**Codex。** 在战役文件夹里打开终端，输入 `codex`。当它问你是否信任这个文件夹时，选择信任：战役自带的设置会告诉 Codex RPG Engine 在哪里、允许使用它的工具、并关闭记忆，而 Codex 只会在你信任的文件夹里读取这些设置。在桌面应用里，请确认游戏聊天的记忆已关闭。

**为什么记忆很重要。** 战役保存在它的文件里。如果宿主也自己记东西，回到存档就不是真正的回去：主持人仍会记得那些被撤销的事。

### 2.5 第一次聊天

随便写点什么，例如：

> 你好！我们开始吧。

主持人会读取游戏进行到哪里，然后回答你。每次聊天的第一条回复里，主持人都会给你**仪表盘的链接**（类似 `http://127.0.0.1:4750`）。在浏览器里打开它，整局游戏都放在聊天旁边。同一个战役在不同聊天之间使用同一个链接，除非被别的程序占用了：那时主持人会给你新的链接。

在主持人的两条消息之间，你的宿主会用简短的几行显示主持人用到的工具。不要展开它们的详情（在 Claude Code 里是 ctrl+o）：详情里可能出现主持人写下的内容，包括秘密。

新战役会经过三个阶段，就像有真人主持人的游戏一样。仪表盘在顶部显示它们：*1 设置 · 2 零号团 · 3 游戏*。

1. **设置**：你选择想怎么玩。在故事之外进行。
2. **零号团**：你在游戏中创建角色。
3. **游戏**：故事开始。

### 2.6 设置：选择你的玩法

主持人只问还缺的内容，每次问几个问题。如果你写“你来定”，主持人会自己选择，并告诉你选了什么。打开仪表盘后，它的第一步 **设置** 会把同样的问题做成卡片：一次一个问题，每个值都附有说明，常用的那个标着 **推荐**。在那里选好，主持人就不会在聊天里再问；**跳过** 会把问题留到以后。聊天负责解决只有文字才能说清的事：新世界的前提、语言，以及图片（只有你的电脑能生成图片时，主持人才会问）。所以页面上的问题比下表列出的要少。

不用研究这张表：它是留着查阅的。这些设置以后都可以改，在聊天里或在仪表盘的 **设置** 里都行。改动从主持人的下一条回复起生效。

| 设置 | 决定什么 | 可选值 | 推荐 |
|---|---|---|---|
| **导师**（问法是“你对这个游戏有多熟？”） | 主持人在故事之外教你多少规则 | **关闭**（只有故事；想问时用方括号提问）、**提示**（在重要选择之前给一句简短提示，规则被漏掉时也会提醒）、**教程**（每条规则第一次出现时讲解，每次掷骰的完整算式，战斗后简短复盘） | 根据你的回答：没玩过 → 教程，玩过一点 → 提示，很熟 → 关闭 |
| **难度** | 世界有多难：战斗、敌人的战术、线索、宝藏、威胁推进的速度 | 故事、简单、普通、困难、残酷 | |
| **致命度** | 在战斗中倒下意味着什么 | **叙事**（你的角色永远不会死）、**史诗**（只在对故事重要时才会死）、**骰子**（由骰子决定） | 跟随难度：故事 → 叙事，简单 → 史诗，普通及以上 → 骰子 |
| **存档** | 你什么时候可以回去 | **永久死亡**（不能回去，只能重开战役）、**检查点**（回到上一个场景结束时，仅在你的角色死亡时）、**自由**（回到任意存档，想存就存） | 检查点 |
| **严谨度** | 食物、光源、疲劳、负重、法术材料和旅行对规则的遵守有多严 | **流畅**（主持人一笔带过）、**规则**（照规则书来：火把会烧尽，口粮会吃完）、**模拟**（超出规则：磨损、腐坏、天气） | 流畅 |
| **骰子** | 谁来掷你的角色的骰子 | **数字**（由 RPG Engine 在页面上掷）、**实体**（你自己掷，并告诉主持人点数） | |
| **单位** | 故事里的距离和重量 | 公制、英制 | |
| **同伴** | 谁与你同行 | 无、在零号团中与你一起创建、由主持人创建、在游戏中遇到 | |
| **图片** | 地点、任务和你遇到的人物的图片，以及你要求时的角色肖像 | 无、按需、新地点、任务和你遇到的人物 | 只问一次，且仅在你的电脑能生成图片时 |
| **底线** | 游戏中永远不会出现的内容 | 一个列表，或者没有 | |
| **帷幕** | 可以发生，但只在幕后发生的内容 | 一个列表，或者没有 | |
| **语言** | 游戏和仪表盘使用的语言 | 任意 | 根据你的书写习惯判断，并向你确认 |

游戏系统可以增加自己的设置。第五版增加了**升级方式**：你的角色如何升级，用**经验值**，或者按故事的**里程碑**。

**难度在游戏中意味着什么。** 故事：敌人弱小天真，线索明显，什么都很充足；主持人可以对自己的掷骰手下留情。简单：敌人简单，资源慷慨。普通：敌人合理，每个结论有三条线索，价格和宝藏为标准水平。困难：敌人聪明，线索隐蔽，资源稀缺，威胁推进很快。残酷：敌人会伏击、撤退、补刀倒下的人，资源极度稀缺，休息的条件最苛刻。战斗的规模始终按你当前的队伍来定。

**如果没有写好的世界**，设置还会多问两件事：

- **前提**：用你自己的话说明类型、基调和世界的一些元素。例如：*“低魔奇幻，灰暗但有希望。一座河边小镇，一处闹鬼的渡口，山丘里的一个邪教。”*
- **准备**：**即兴**（主持人在你需要之前才构建世界的每一部分；推荐）或**开局全部准备**。

接着主持人会为战役提议一个名字。当没有缺漏、你也说准备好了，游戏就进入零号团。

### 2.7 零号团：你的角色

零号团本身就是游戏：你和主持人一起创建角色，就像在牌桌上一样。

- **每个选择都由你做主**，除非你请主持人代选。你可以带来完整的想法（“一位离开了神殿的半精灵牧师”），模糊的想法（“会治疗，但脾气不太好的人”），或者什么都没有（“给我个惊喜，然后让我改”）。
- **属性值。** 在掷任何骰子之前，主持人会告诉你方法和兜底的办法。第五版有：标准数组、购点法，或 4d6 去掉最低值。你们商定的方法会留在牌桌的约定里。
- **你的故事**从来不是必须的。如果你提供了，主持人会用你的话写下来，向你复述一遍，并把其中的人物和地点编进世界。你也可以在仪表盘上写（见 [队伍](#party)）。
- **个性**（第五版）：一个特点、一个理想、一个羁绊和一个缺陷，可以来自你的背景表，也可以自己写。
- **一张图片。** 角色创建完成后，主持人会问你要角色的图片：可以是你电脑上的一个文件，也可以是根据你的描述在你的电脑上生成的肖像（见 [角色的图片](#37-your-characters-story-and-picture)）。

角色卡上的数值由 RPG Engine 根据你的选择算出：你永远不用自己算。角色都创建好、你确认之后，故事就开始了。

## 3. 游戏进行 <!-- icon: chat -->

### 3.1 和主持人交谈

用你自己的话写下角色做什么或说什么。简短就行。

> 我问旅店老板今晚还有谁来过。
>
> “我们不是来惹麻烦的。”我说着，把手从剑旁移开。
>
> 我爬上屋顶，等着。

**在故事之外**，写在方括号里：

> [擒抱是怎么运作的？]
>
> [这一轮我还能用反应吗？]
>
> [今晚就先到这里吧。]

主持人也会用方括号回答，然后回到故事里。

**你说你尝试什么，主持人说发生什么。** 违背世界逻辑或已确立事实的事不会发生：主持人会在故事里告诉你，并提出可行的办法。

**主持人从不替你的角色做决定。** 主持人不会让你说话、感受或选择。拿不准时，主持人会问你。

**主持人从不谈论引擎。** 问主持人是否在记录这些事，主持人会像游戏主持人那样回答：“我都记着：下次从这里接着来。”

**你可以问主持人怎么用仪表盘。** 主持人了解这个页面：“我在哪里看法术？”“怎么手动掷骰？”

### 3.2 掷骰

**什么时候掷骰。** 只有结果不确定而且重要时，主持人才会要你掷骰。否则主持人会说可以，或者“可以，但是……”。在你掷骰之前，主持人会说明利害关系和适用的检定，然后停下。你可以掷骰，也可以改变主意：

> **主持人：** 岩架又窄又湿。如果你滑倒，就是掉进河里的一段长长的坠落。可以做一次敏捷（杂技）检定，或者你也可以退回去找楼梯。
>
> **你：** 我试试。

**在仪表盘上掷骰。** 主持人要求掷骰时，页面顶部会出现一个横幅，每种检定一个按钮，例如 *杂技 +4 · 优势*。点击它：骰子会落在页面上，主持人会收到结果。你还可以：

- 点击角色卡上对应的那一行，它会亮起金色；
- 从骰盘里掷出合适的骰子；
- 在横幅里写下你自己的话，如果你想做别的事。

**手动掷骰。** 如果你想自己挑骰子，在横幅的角落打开 **手动**（或在 **设置** 里打开）。检定的按钮会消失，横幅会像主持人那样告诉你该掷什么：*请自己掷杂技，在角色卡上或用骰子。* 点击亮起的角色卡那一行，或者从骰盘里掷出合适的骰子：RPG Engine 会替你掷，加上你的加值，主持人会收到结果。角色卡和骰盘都无法完成的检定，例如遇到 1 要重掷的伤害，仍保留它的按钮。手动 在这个浏览器里会一直保持开启，直到你关闭它。

**整局使用实体骰子。** 当 **骰子** 设置为实体时，主持人会用文字向你要求掷骰，你把掷出的点数写下来：

> [我掷出了 14。]

RPG Engine 会加上你的调整值，并拒绝你的骰子不可能出现的点数。

**自由掷骰。** 点击角色卡上的任意数字，或打开骰盘，就能随手掷着玩。自由掷骰从不计数，也不记录，主持人永远看不到。自由掷出的 20 以后也不会变成真正的 20。

**主持人的掷骰。** 主持人替敌人和其他角色掷骰，也用 RPG Engine。大多数掷骰会显示在你的掷骰栏里。当你不该看到结果时，主持人会暗中掷骰。你随时可以问：

> [刚才那次掷骰是真的吗？]

对于公开的掷骰，主持人会给出数字和理由。对于暗掷，主持人会给出一个指纹，证明这次掷骰在你发问之前就已完成。

**聊天中的掷骰**会用方括号显示，紧跟在它决定的那一刻之后：*[说服 14 + 3 = 17]*。然后故事会讲述结果。

### 3.3 场景与战斗

主持人以**场景**来推进故事：一场战斗、一次交谈、探索、旅行、休息、一次挑战（追逐、竞速、谜题）。你不用管理它们：RPG Engine 靠它们来记录故事的章节。每个场景结束时，游戏会自动存档，这个场景也会进入日志的故事里。

**在战斗中**，主持人会依次讲述所有不属于你的回合，附上每一次掷骰，并**停在你可以做决定的地方**：你的回合、一次反应、一个选择。轮到你时，说出你要做什么：

> 我对门边那个施放圣火术。

仪表盘的 **战斗** 部分会显示回合顺序、轮到谁、你的队伍的生命值，以及敌人看起来伤得多重（未受伤、受伤、重伤、倒下：只用文字，从不用数字）。如果你的角色倒下，死亡豁免会大大地显示在页面上。

**当战斗胜负已定时**，主持人可能会提议用一条消息讲完剩下的部分。

### 3.4 时间、旅行与运转的世界

**时间。** 每个行动在故事里都要花时间，RPG Engine 会记录日期：第 3 天，清晨。主持人按世界的方式报时：黎明、第三声钟响、夜幕降临。两次游戏之间不会流逝时间：你从停下的地方接着玩。

**休息。** 说你要休息，主持人就会应用休息带来的恢复，比如生命值和法术位：

> 我们扎营，进行一次长休。

**旅行。** 说出你想去哪里：

> 我们沿路向北去 Rocca。

RPG Engine 会算出路线、距离，以及按你的速度需要的天数，并把你送到那里。旅程会在途中发生预定的事件时、每天行程结束时以及抵达时停下。出发前你可以问一个地方有多远：

> [Rocca 有多远？步行要多久？]

**世界不等你也在运转。** 反派有带期限的计划和进度钟。每过新的一天，主持人会推进时间所推进的威胁，而你会看到它们的迹象：一则传闻、一道痕迹、小镇里的一点变化。你永远看不到进度钟本身，只能看到它留下的痕迹。

**金钱**用游戏里的货币计算。付款、出售、收款：RPG Engine 会帮你找零。

### 3.5 地图

**世界地图**（仪表盘：**世界**）只显示你的角色知道的地点，以及它们之间的道路、你走过的路径，其余一切都笼罩在迷雾之下。点击一个地点，可以看到你对它的了解和它有多远。

**地点地图**（仪表盘：**场景**，战斗中为 **战斗**）会在主持人为你所在之处绘制地图时出现：墙壁、门、地面，以及谁站在哪里（用棋子表示）。在战斗中轮到你时，你够不到的格子会被遮住，让你一眼看出能去哪里。当主持人问你的角色移动到哪里时，页面会打开地图，你点一个格子，或者写下它，例如 *E4*。

### 3.6 任务、日志与笔记

**任务。** 当你的角色接下一项委托时，它会成为你的 **日志** 里的一个任务：谁委托的、在哪里、期限是什么时候、目标列表，以及它的衡量方式（带剩余时间的期限、进度钟、计数）。用星标标记一个任务来追踪它：它会以小卡片的形式停在 场景 顶部，并显示它的下一个目标。任务由故事来结束，绝不会自己结束。

**故事。** 日志的“故事”标签页把你的战役呈现为时间线：每个场景是一章，附有地点、日期和简短摘要，最新的在最前。

**你的笔记。** 在日志的“笔记”标签页里，你可以写自己的笔记：推测、名字、计划。它们保存在你的电脑上，主持人不会读，除非你 **分享** 某一条。分享的笔记会在主持人的下一条回复时传达给主持人，作为你的想法，而不是事实。你的推测不会因为你写下来就变成真的。要求停止或避开某些内容的笔记，等同于你在牌桌上说过这句话。

### 3.7 你的角色的故事与图片

在你的角色的角色卡上，**描述** 卡片里有一个输入框，用来写你的角色的故事。发送之后，经你同意，主持人会用自己的话把它写进角色里。

至于角色的图片，在聊天里把图片文件交给主持人，并告诉主持人它在你电脑上的位置（PNG、JPEG、WebP 或 SVG，最大 5 MB）：

> [这是我的角色的肖像：C:\Users\me\Pictures\mira.png]

主持人会把它复制进战役，它会出现在仪表盘上你的角色的棋子上。你想换的时候，可以用同样的方法更换。

或者，如果你的电脑能生成图片（见 [图片](#311-pictures)），也可以让它生成肖像：向主持人描述你的角色，或者让主持人来描述。

> [帮我生成一张肖像：灰色头发编成辫子，下巴上有一道疤，眼神疲惫。]

肖像会准确呈现你的角色在游戏里的样子，包括这个世界里种族的特征，山地矮人就是山地矮人，外貌则按你描述的来。大约一分钟后它就会出现在你的角色的棋子上。你的同伴也可以用同样的方式获得肖像。

### 3.8 存档与回到过去

RPG Engine 会在**每个场景结束时**自动保存整个战役。你能对这些存档做什么，取决于 **存档** 设置：

| 存档 | 想存就存 | 回到过去 |
|---|---|---|
| **永久死亡** | 不可以 | 不能；只能重开战役 |
| **检查点** | 不可以 | 回到上一个存档，仅在你的角色死亡时 |
| **自由** | 可以 | 回到任意存档，随时可以 |

无论哪种模式，你都可以**重新开始**：用同一个角色从游戏开头开始，或者从零号团开始，用新的角色。

这一切都可以在聊天里完成（“[我们回到决斗之前吧。]”），也可以在仪表盘的 **存档** 部分完成。

**回到存档后，请开启新聊天。** 你原来玩的那个聊天还记得被撤销的事。和主持人开启一个新聊天（Claude Code 里用 `/clear`，Codex 里用 `/new`），写下“继续”，然后在存档里点击 **我已开启新聊天**，或者在新聊天里告诉主持人。永远不要恢复旧聊天。在你确认之前，主持人不会继续。

### 3.9 游戏时段：停下与回来

**你可以随时结束本次游戏：**

> [今晚就先到这里吧。]

没有“保存并退出”：一切都已经在文件里了。

**关闭**聊天：在 Claude Code 里输入 `/exit`，在 Codex 里输入 `/quit`。仪表盘会安静下来，直到下一次聊天。

**要回来时**，在战役文件夹（`init` 打印出来的那个）里打开终端，在那里启动你的宿主，然后写“继续”。主持人会读取游戏进行到哪里，给你一段简短的回顾，并以正在发生的事开场。开启新聊天不会丢失任何东西：战役保存在它的文件里，不在聊天里。

主持人不会在结束时问例行的问题。只有发现某处出了问题时，才会简短地问你。

### 3.10 主持人的情绪

仪表盘顶部是主持人的头像，一个小机器人。它的表情跟随故事的基调：危险逼近时担忧，遇到大胆的主意时欣喜，剧情转折时惊讶。遇到自然 20 或自然 1 时，它会短暂地做出反应。它从不泄露你还不知道的事：陷阱触发之前，它不会露出笑容。你的队伍的棋子也会显示他们的情绪。聊天关闭时，机器人会睡着。

### 3.11 图片

RPG Engine 可以为你到达的每个地点、你接下的每个任务，以及你遇到的每个人物或每种生物生成一张图片，画成你看到的样子，具体按 **图片** 设置来定；你要求时，还能生成你的角色的肖像。它使用你电脑上已有的东西：

- **Codex**，用你的 ChatGPT 登录：一幅绘画。
- 否则用 **Claude Code**，用你的 Claude 登录：一幅素描。

图片用的是你自己的套餐，不是我们的。**设置** 部分会告诉你，你的电脑能否生成图片；如果不能，会给出设置的步骤。没有图片时，页面会改为显示每类地点的标记。你也可以把自己的图片交给主持人，用于任何地点或角色。

### 3.12 安全：底线、帷幕与停止

- **底线**：游戏中永远不会出现的内容。
- **帷幕**：可以发生，但只在幕后发生的内容。
- **停止**：你可以随时叫停某个内容，不必解释。在故事之外写下：

> [停]

主持人会立刻放弃这个内容，并把它加入你的底线，今后每次游戏都有效。你可以在 **设置** 里查看和修改你的底线与帷幕。

### 3.13 改变主意

每项设置在战役中都可以改：在聊天里（“[把难度调高一点。]”）或在 **设置** 里。主持人会在下一条回复时得知改动。主持人在规则书之外做出的裁决会成为**先例**并被保留，所以下次同样的问题会得到同样的答案。

## 4. 仪表盘分区介绍 <!-- icon: party -->

仪表盘是你自己电脑上的一个页面。主持人在每次聊天开始时给你它的链接。它实时跟随游戏：主持人改动了什么，页面也跟着改变。

只有你玩游戏的那台电脑的浏览器才能打开它：手机或平板不行，即使在同一个 Wi-Fi 下也一样。页面也适应窄窗口：这时各分区会移到底部的栏里，图标会移进菜单。

页面的寿命与聊天相同。关闭聊天后，仍开着的页面会显示*未连接*，角色卡保持原样，主持人的机器人会睡着；在战役里再次开启聊天，等主持人回答之后，页面会自动恢复。

### 顶部

- **主持人的头像**，带有它的情绪。
- 战役的名称、游戏系统、**游戏时间**，以及游戏是否**已连接**（聊天已连上）。
- 各分区：**队伍**、**场景**、**战斗**（仅在战斗期间）、**日志**、**世界**；在这一排的末尾，以图标显示：**存档**、**帮助**、**设置**、**关于**。
- 浅色和深色主题，在右上角。

当主持人问你什么事时，它的横幅会一直停在页面顶部，无论你在哪个分区。

### 队伍

你的角色卡，以及同伴的角色卡。角色卡的每个部分都是一张可以展开和收起的卡片。

- **点击一个数字**可以掷着玩。把鼠标放在数字上，可以看到它的构成（“+5：感知 +3，熟练加值 +2”）。
- **生命值、法术位和使用次数**以条形和圆点显示。
- **状态和效果**连同持续时间一起显示。
- **描述**里是你角色的文字，以及把角色故事发送给主持人的输入框。
- 生命值为 0 时，**死亡豁免**会大大地显示在名字下方。
- 角色卡旁边（窄屏时在下方）：**掷骰记录**，最新的在前，包含你的掷骰和你可以看到的主持人的掷骰。**清空**会清空列表；**恢复**会把它找回来。自由掷骰以虚线和淡色显示。

带有属性数据块的同伴，例如狼，显示的是它的属性数据块，而不是完整的角色卡。

### 场景

你的队伍所在之处：地点的图片和名称、周围的地点、该地点的地图（如果有）、在场的人，以及正在进行的场景和当下发生的事。你关注的任务在顶部。

### 战斗

仅在战斗期间出现。顶部：当前是第几轮、谁在行动、下一个是谁。下方：回合顺序，每个战斗者及其状态，你的队伍用数字，敌人用文字；你的角色手头有什么（护甲等级、生命值、攻击）；该地点的地图，正在行动的那位被圈出。轮到你时，**战斗**链接会闪动金光，无论你在哪个分区。

### 日志

三个标签页：

- **任务**：进行中、已完成和已失败的任务，每个是一张卡片，带有目标、以计时器显示的期限，以及进度钟。星标用来关注任务。
- **故事**：战役的章节，逐场景排列，最新的在前。
- **笔记**：你自己的笔记，在你分享之前是私密的。

### 世界

你的角色所了解的世界地图，其余部分被迷雾覆盖。拖动来移动，滚轮或双指缩放。点击一个地点可打开它的卡片。旁边有一个地点列表，最近的在前。如果有不止一张地图（一座城市、一块大陆、另一个位面），可以用标签页在它们之间切换。

### 骰盘

骰子按钮会打开骰盘：选择骰子和调整值，然后掷出。当同一种骰子有两个或更多时，可以选择计入哪些：**全部**、**最高**（只算最高的）或**最低**（只算最低的）。你选的骰子会保留，直到你按**清空**，所以同一个伤害掷骰每轮只需点一下。当主持人要求掷骰时，骰盘会告诉你该用哪些骰子。

### 存档

你的存档，最新的在前，每个都带有地点、游戏日期和创建时间。**立即存档**（自由存档时可用）、**回到此存档**，以及红色的**重新开始**（分两步确认）。见[存档与回头](#38-saves-and-going-back)。

### 设置

你的设置，分成几组：游戏、学习游戏（导师，以及已经向你讲解过的规则）、骰子和度量、内容边界（底线和帷幕）、图片、语言。点击一个值来选择；它下方是这个值的含义。再往下是页面自己的偏好，只保存在这个浏览器里：主题、骰子的声音、**骰子套装**（树脂、金属、木头、石头）、圆角或直角边缘、手动掷骰。

主持人自己的设置，例如房规和先例，不在这里：它们留在聊天里。

### 帮助与关于

**帮助**：就是本指南。**关于**：RPG Engine 是什么、它的链接、它的许可证，以及游戏系统的署名。

### 游戏之前：设置与零号团

当新战役处于第一步**设置**时，整个页面都用来提问：一次一个问题，每个问题都附有各个值的含义和推荐值。**你来定**把问题交给主持人，唯独底线和帷幕例外，它们永远由你决定；**跳过**则把问题留到以后。最后点**我准备好了**。

### 页面的提示

有时页面会在自己上方显示一条通知：战役文件出了问题（主持人会修复）、游戏离开了（聊天已关闭）、页面正在翻译。

## 5. 游戏系统与房规 <!-- icon: dice -->

### 5.1 什么是游戏系统

游戏系统是一款游戏的全部数据：它的角色卡、数值、生物、物品、法术和规则文本。每个战役使用一个系统。

RPG Engine 会像电子角色卡一样，算出你的角色卡，以及哪些资源会消耗、哪些会恢复，比如生命值和法术位。至于某项特性或某个法术如何生效，则由主持人查阅规则后裁定，就像在牌桌上一样。

### 5.2 内置第五版

RPG Engine 内置 **5e**，来自系统参考文档 5.1（System Reference Document 5.1，即 2014 年规则，在知识共享许可下免费使用）。内容包括：

- SRD 中的种族、职业、子职业、一个背景和一个专长；
- SRD 中的 319 个法术，以及武器、护甲、装备、魔法物品和怪物；
- 规则章节，主持人可以按原文精确查找；
- 完整的角色卡，并已算好：属性调整值、豁免、技能、Classe Armatura、攻击、法术豁免 DC、法术位、生命骰、按等级获得的特性、经验值和升级；
- 能恢复该恢复之物的休息；附带规则文本的状态；专注提醒。

**SRD 之外的内容。** 你可以用 SRD 没有的内容来玩第五版，比如你手上那本书里的职业或怪物。主持人了解这款游戏，能阅读你的手册，也能上网搜索。需要的内容，主持人会写成你战役里的页面，RPG Engine 对这些页面一视同仁。我们随程序提供的内容受许可限制，而主持人所知道的不受限制。

RPG Engine 只内置原创或开放许可的内容：第五版使用的是 CC BY 4.0 许可下的 SRD 5.1。游戏中出现的其他内容，都由你的 AI 或你自己写成战役页面，保存在你的电脑上。它们不属于 RPG Engine，我们也不发布它们。

RPG Engine 兼容第五版。

### 5.3 房规与自定义内容

你不需要改动任何文件。直接告诉主持人：

> [房规：攻击掷出自然 1 时，武器脱手。]
>
> [我想玩血猎人。我有这本书，职业特性如下。]
>
> [在这个战役里，短休需要 10 分钟。]

主持人会用下面几种方式，把它们记录在你的战役中：

- **牌桌约定**，用文字写下，比如上面的武器脱手或短休。主持人把它和战役设置放在一起，之后按它进行。主持人在没有规则书可依时做出的裁定，也以同样方式保存，称为**判例**。
- **新页面**，比如职业、种族或物品。新职业和系统自带的职业一样运作：你的等级、生命骰和特性都会计入。新种族可以以现有种族为基础（“像精灵，再加上……”）；一把有名字的剑可以以长剑为基础。
- **角色卡的新数值**：字段、表格、公式，以及休息后会恢复的计数器。例如战斗大师的卓越骰，短休后会恢复。房规也可以替换系统的某个公式。

如果你已经写好了房规，也可以把它们作为文本文件放进战役的 `rules` 文件夹（见[战役文件夹](#8-for-the-curious-the-campaign-folder)）。主持人会先读这些文件，再看规则书中的同名规则。

### 5.4 添加或导入你自己的游戏系统

目前 RPG Engine 只支持第五版。其他游戏系统将会陆续推出，同时也会提供添加自有系统的方法，或者根据你拥有的游戏手册，把它转成一个系统。见[后续计划](#9-coming-later)。

---

## 6. 扩展 <!-- icon: plus -->

**扩展暂时还不可用。** 扩展会在游戏系统之上为战役增添内容：一个世界、一场冒险、一项功能（比如天气或塔罗牌），或可共享的房规。你可以为每个战役选择使用哪些扩展。第五版计划中的首批扩展是天气和开锁。

## 7. 战役从哪里来，以及它的语言 <!-- icon: world -->

### 7.1 获得世界的三种方式

**随玩随建。** 你在设置阶段给出一个前提，主持人在游戏过程中构建世界：每个地点、人物和阴谋，都在你需要之前才创建，并从此保留。这是最快的玩法：安装、创建，几分钟后你就在创建角色了。凡是编造出来的东西都不会丢失：一旦说出，就被写下来，并且成为事实。

**开局备齐。** 同样的前提，但选择**准备：开局备齐**，主持人会在游戏开始前构建世界的地点、势力、威胁及其计划。第一次游戏开始得更晚，但幕后准备得更充分。

**来自现有的战役或冒险。** 目前没有导入按钮。把你的冒险交给主持人（一份文本，或你的主机能读的 PDF），请它布置好：

> [我有这个冒险的 PDF。请把它设置成我们的战役：读一遍，把里面的地点、人物和秘密写下来。里面的内容一点都别告诉我。]

主持人用你的 AI 主机的工具读取它，并把它写成战役的页面，包括秘密，你会在游戏中逐步发现。Claude Code 能读 PDF；用 Codex 的话，文本或 markdown 文件更稳妥。请在设置阶段、零号团之前完成这一步。

主持人工作时，不要展开它读取或写入内容的详情（在 Claude Code 里是 ctrl+o）：详情会显示冒险的文本，包括秘密。主持人自己会照常保守秘密。

一旦战役有了自己的页面，设置阶段就不再询问前提和准备了。即使是写好的战役，当你去到文本没有涉及的地方，主持人也会创建所需的内容并记录下来。

**一个战役只玩一次。** 想再玩同一个冒险，就创建一个新战役。在一个战役之内，你仍可以按存档设置的允许，回到某个存档或重新开始。

### 7.2 语言

**每个战役一种语言**：主持人的语言。主持人用它写作，仪表盘也跟随它。主持人根据你的书写判断语言，并向你确认。

**仪表盘**内置英语和意大利语（精心校订），以及另外 24 种语言：法语、德语、西班牙语、葡萄牙语（巴西）、荷兰语、瑞典语、挪威语、丹麦语、芬兰语、冰岛语、俄语、乌克兰语、波兰语、捷克语、罗马尼亚语、匈牙利语、希腊语、土耳其语、阿拉伯语、希伯来语、印地语、中文、日语、韩语。阿拉伯语和希伯来语从右向左阅读：页面会镜像翻转，而地图和骰子保持原样。

你在设置里选择的**任何其他语言**，会在你的电脑上由 Codex 或 Claude Code 用你自己的登录在后台翻译，从你当前打开的分区开始。每种语言只做一次，所有战役通用。在翻译完成之前，页面显示英语。设置会告诉你翻译是正在进行、已经完成，还是你的电脑无法进行。

**游戏术语。** 第五版自带来自官方意大利语 SRD 的意大利语术语，所以意大利玩家读到的是 *Classe Armatura*、*tiro salvezza*、*vantaggio*。其他语言则会得到翻译后的系统术语。

**游戏系统自身的文本**（法术、怪物、规则章节）保持英语。主持人阅读它们，并用你的语言讲给你听。

**战役中途更换语言**会保留已经写好的页面不变；主持人会用新语言写新的页面。

## 8. 给好奇者：战役文件夹 <!-- icon: list -->

你从来不需要打开它。如果你打开了，要知道**里面有战役的秘密**：读了它就会剧透。

战役文件夹里有：

- `campaign.yaml`：你的设置；
- `state.yaml`：游戏当前进行到哪里：阶段、日期、正在进行的场景；
- `world/`：每个角色、地点、势力、任务、物品、事件、话题或生物各一页，都是 markdown 文件；
- `rules/`：你的房规文本文件，如果你添加了的话（`init` 不会创建它）；
- `images/`：图片，有了图片之后才有；
- `log.jsonl`：每一次改动，按顺序记录；
- `.saves/`：存档，从第一个开始；
- `.player/`：你在日志里的个人笔记，主持人不会读；
- `sessions/`：由 RPG Engine 维护；
- `AGENTS.md`、`CLAUDE.md`、`.mcp.json`、`.claude/`、`.codex/`、`.gemini/`：这些小文件告诉 AI 主机 RPG Engine 在哪里，并关闭它们的记忆。RPG Engine 会让它们保持最新；请保持原样。

这些页面是普通的 markdown，带有 `[[Rocca]]` 这样的链接，也就是 Obsidian 的格式：主持人的笔记本可以在那里打开。**如果你手动修改了某个页面**，主持人会在下一次回答时得知改动的内容。

**命令行。** 主持人做的一切都通过命令完成，你也可以在战役文件夹里运行这些命令。玩游戏时你从不需要它们，而且许多命令会打印出战役的秘密，比如 `rpg status` 和 `rpg show`。`rpg --help` 会列出全部命令，`rpg roll --help` 会解释其中一个。在聊天开着的时候运行会改动内容的命令是没问题的：主持人会在下一次回答时得知，就像得知手动修改的页面一样。

## 10. 问题与故障 <!-- icon: info -->

### 问题

**我需要懂规则吗？** 不需要。选择教学导师，主持人会边玩边教你，一次一条规则。你随时可以在方括号里提问。

**主持人会作弊吗？** 它无法更改 RPG Engine 掷出的结果，除非难度是故事，而且它从不更改已确立的事实。你可以问任何一次掷骰是不是真的。

**我能作弊吗？** 你可以试试。主持人不会轻信你说的事实：你消息里一行看起来像游戏消息的文字，仍然只是你的话，而且主持人从不确认你对秘密的猜测。

**要花钱吗？** RPG Engine 是免费的。主持人运行在你自己的 Claude 或 ChatGPT 方案上，而一晚的游戏就是一场很长的聊天：在最低档的方案上，你可能在晚上结束前就达到方案的用量上限。图片和翻译用的是同一个方案。

**我能在手机上玩吗？** 不能。主持人运行在你的电脑上，仪表盘只能在那台电脑的浏览器里打开。

**我能和朋友一起玩吗？** 暂时不能：目前是一名玩家、一个角色，外加同伴。多人同桌会随角色功能一起推出。

**下次我能换一个 AI 吗？** 可以。战役保存在它的文件里：在另一个主机里打开它，写下 *继续*。

**如果我关掉浏览器会怎样？** 什么也不会丢。聊天开着时重新打开链接就行；页面会回到游戏当前的位置。

**我能玩我拥有的 D&D 内容吗？** 可以。主持人可以使用你的书、它自己的知识和网络。RPG Engine 内置的内容只限于免费内容；你的游戏用什么，由你决定。

### 故障

**仪表盘打不开。** 向主持人要链接：`[仪表盘的链接是什么？]`。页面只在该战役里有聊天开着时才能用，而且要等主持人在该聊天里第一次回答之后。聊天关闭后，浏览器无法访问页面；仍开着的页面会显示*未连接*。

**主持人好像不懂这个游戏，或者编造工具。** 你的 AI 主机没有加载 RPG Engine。

- 首先，确认你是**在战役文件夹里**启动主机的，并且你选了信任它。
- **Claude Code**：写 `/mcp`。如果 `rpg` 在列表里但失败了，选中它，然后点 **Reconnect**。如果它不在列表里，关闭 Claude Code，在战役文件夹里写 `claude mcp reset-project-choices`，然后重新启动。
- **Codex**：在战役文件夹里的终端中写 `codex mcp list`。如果缺少 `rpg`，说明 Codex 不信任该文件夹：在那里重新启动它，被问到时选择信任。
- 两者通用：如果终端里的 `rpg --version` 提示找不到该命令，请重新安装 RPG Engine（[2.2](#22-install)），并打开一个新终端。

**更新之后，什么都没变。** 正在运行的主持人保留着它启动时的版本。开启一个新聊天，或者在 Claude Code 里重新连接服务器（`/mcp`，然后选 `rpg`，再点 **Reconnect**）。

**主持人还记得我撤销的事。** 你回到了某个存档，却在同一个聊天里继续玩。开启一个新聊天，并在存档里按**我已开启新聊天**。

**主持人又问了我已经在页面上回答过的设置问题。** 告诉它：`[那些我已经在仪表盘上选好了。]`

**没有出现图片。** 打开设置 > 图片：它会告诉你这台电脑能否生成图片，如果不能，还会给出步骤，每条命令旁都有复制按钮。

**页面是英语，但我选了另一种语言。** 它正在后台翻译；设置会告诉你进展如何。如果这台电脑上没有 Codex 或 Claude Code，页面会一直是英语。

**主持人说战役有问题。** 它会自己修复。如果你手动编辑过文件，它可能会问你本意是什么。

**Windows：`npm` 在我的文件夹里失败。** 不要把战役或 RPG Engine 放在含有 `&` 的路径下。

**安装失败，或者 `rpg` 无法启动。** 用 `node --version` 检查你的 Node.js 版本：必须是 22 或更新。如果更旧，请从 [nodejs.org](https://nodejs.org) 安装 LTS 版本，然后重新安装 RPG Engine。

**仪表盘的链接变了。** 另一个程序占用了战役常用的地址，或者 Windows 保留了它。RPG Engine 换了另一个；主持人会给你新的链接。其他一切都不变。
