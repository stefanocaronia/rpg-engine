# RPG Engine：完全ガイド

**RPG Engine**では、**AIをGM**にして、テーブルトークRPGを遊べます。GMとは**チャット**で会話します。RPG Engineは裏側で動き、**世界を記憶し**、**ダイスを振り**、**数値を管理**します。チャットの横にはブラウザーのページ、**ダッシュボード**を開いておきます。キャラクターシート、ダイス、マップ、ジャーナルが並びます。

このガイドはプレイヤー向けです。プログラミングの知識は必要ありません。

## クイックスタート <!-- icon: send -->

1. [nodejs.org](https://nodejs.org)から**Node.js**をインストールします（LTS版）。
2. **AIエージェント**をインストールして、サインインします。AIエージェントとは、GMが動くプログラムです。たとえばClaude CodeやCodexです（[2.4](#24-connect-your-ai)）。
3. ターミナルで、RPG Engineをインストールします：`npm install -g rpg-engine`。
4. キャンペーンを作ります：`rpg init "The Salt Isles"`。
5. 作られたフォルダーに入り（`cd "The Salt Isles"`）、そこでエージェントを起動します。Claude Codeなら`claude`、Codexなら`codex`です。フォルダーを信頼するか聞かれたら、はいと答えます（[2.4](#24-connect-your-ai)）。そして*こんにちは！始めましょう。*と書きます。GMがダッシュボードへのリンクを伝えます。

## 1. RPG Engineとは <!-- icon: about -->

| 誰が | 何をするか |
|---|---|
| **自分** | キャラクターを演じます。何をして、何を言い、何を試みるかを決めます。 |
| **GM**（AI） | 物語を語り、ほかの全員を演じ、何が起こるかを決め、ロールを求めます。 |
| **RPG Engine** | 世界をファイルに保ち、ダイスを振り、ヒットポイント、お金、時間、距離を数え、発見されるまで秘密を守ります。 |

世界は、夜が変わっても、新しいチャットでも、別のAIでも変わりません。

- **語られたことは真実のままです。**倒された悪役は倒されたままです。
- **ダイスは本物です。**GMはダイスを曲げられません。ただし、最も易しい難易度を選んだ場合は例外です。
- **秘密は秘密のままです。**キャラクターが知らないことを、GMが伝えることはありません。
- **世界は動きます。**休息や旅のあいだにも脅威は進み、その兆しが見えます。
- **キャンペーンはコンピューター上のフォルダーです。**いつでも中断して、あとで続きを遊べます。

現在、RPG Engineが遊べるゲームシステムは、無料のSystem Reference Document 5.1にもとづく**第5版**です。ほかのシステムも今後追加されます（[今後の予定](#9-coming-later)）。

## 2. はじめに <!-- icon: path -->

### 2.1 必要なもの

- Windows、macOS、Linuxのいずれかが動くコンピューターと、ウェブブラウザー。
- **Node.js 22**以降（[nodejs.org](https://nodejs.org)）。RPG Engineのインストールに使う`npm`も付いてきます。
- **ターミナル**：Windowsではターミナル、またはPowerShell。macOSではターミナル。フォルダーでターミナルを開くには、フォルダーを右クリックして**ターミナルで開く**（Windows）、または**サービス > フォルダに新規ターミナル**（macOS）を選びます。
- GM用の**AIエージェント**（[2.4](#24-connect-your-ai)）。使うモデルは、提供されている中で**最大のもの**にします。小さいモデルは、言いくるめられて秘密を明かしたり、ルールを曲げたりしやすくなります。

### 2.2 インストール

```text
npm install -g rpg-engine
```

`rpg --version`で、正しくインストールできたか確認できます。`rpg`を使うのは、キャンペーンを作るときに1回だけです。その後は、エージェントがRPG Engineを自動で起動します。

### 2.3 キャンペーンを作る

ゲームを置いているフォルダーでターミナルを開きます（開き方は[2.1](#21-what-you-need)を参照）。

```text
rpg init "The Salt Isles"
```

これでフォルダー`The Salt Isles`が作られ、新しいキャンペーンが入ります。`cd "The Salt Isles"`で中に入ります。場所を覚えておいてください。遊ぶたびにここに戻ります。ほかの設定はあとで、チャットかダッシュボードで決めます。`rpg init --help`で、今のうちに選べるオプションが一覧できます。たとえば`--language it`や`--difficulty hard`です。

GMにキャンペーンを作ってもらうことはできません。`init`の前は、RPG Engineがどこにあるかをエージェントが知らないからです。

### 2.4 AIをつなぐ

GMは**AIエージェント**の中で動きます。AIエージェントとは、ターミナルまたはデスクトップで動くAIアプリで、コンピューター上のファイルを扱えるものです。Claude CodeやCodexがその例です。claude.aiやChatGPTのような通常のチャットや、スマートフォンのアプリでは足りません。GMは、コンピューター上のキャンペーンのファイルに触れる必要があるからです。エージェントごとに、プランとログインが必要です。Claude Codeは有料のClaudeプラン、CodexはChatGPTのログインです。インストールは1回だけで、それぞれのページから行います：[Claude Code](https://code.claude.com/docs/en/setup)、[Codex](https://learn.chatgpt.com/docs/codex/cli)。

- **Claude Code**：キャンペーンのフォルダーで`claude`と書きます。フォルダーを信頼するか聞かれたら、**Yes, I trust this folder**を選びます。注意：最初に選ばれているのは*No, exit*です。
- **Codex**：キャンペーンのフォルダーで`codex`と書き、フォルダーを信頼するか聞かれたら、はいと答えます。デスクトップアプリでは、ゲームのチャットでメモリーがオフになっているか、設定で確認します。
- **ほかのエージェント**：キャンペーンのフォルダーで起動し、MCPサーバー`rpg mcp`を渡します。RPG Engineは標準的なMCPサーバーです。MCPに対応したエージェントなら、ローカルのものも含めて、どれでもGMになれます。

動作確認とテストは**Claude Code**で行っています。**Codex**は接続と確認が済んでいますが、キャンペーンを最後まで遊んだことはまだありません。`init`は**Gemini CLI**の設定も行います。キャンペーンでは、エージェント自身のメモリーをオフにします。ゲームの内容はファイルの中にあるので、セーブに戻ると本当にその時点に戻れます。

### 2.5 最初のチャット

*こんにちは！始めましょう。*など、何でも書いてください。チャットごとの最初の返答で、GMは**ダッシュボードへのリンク**を伝えます。`http://127.0.0.1:4750`のような形です。開いて、チャットの横に置いておきます。

GMのメッセージの合間に、エージェントは使っているツールを表示します。その詳細は開かないでください（Claude Codeではctrl+o）。秘密が表示されることがあります。

新しいキャンペーンは、ダッシュボードの上部に表示される3つの段階を進みます。**1 設定**（遊び方の決定）、**2 セッションゼロ**（プレイの中でキャラクターを作る）、**3 プレイ**です。

### 2.6 設定：遊び方を決める

GMは、まだ決まっていないことだけを、数問ずつ尋ねます。ダッシュボードの**設定**のステップには、同じ質問がカードとして表示されます。「おまかせ」と書けば、GMが選びます。あとからいつでも、チャットか**設定**で変更できます。

| 設定 | 決めること | 値 |
|---|---|---|
| **メンター** | GMがルールをどれだけ教えるか | オフ、ヒント、チュートリアル |
| **難易度** | 世界の厳しさ | ストーリー、易しい、普通、難しい、過酷 |
| **致死性** | 戦闘で倒れることの意味 | 物語重視（死なない）、叙事詩（重要な場面のみ）、ダイス |
| **セーブ** | いつ戻れるか | パーマデス、チェックポイント、自由（[3.8](#38-saves-and-going-back)） |
| **厳しさ** | 食料、明かり、旅をどこまで厳密に扱うか | なめらか、ルール準拠、シミュレーション |
| **ダイス** | 誰がダイスを振るか | デジタル、物理 |
| **単位** | 距離と重さ | メートル法、ヤード・ポンド法 |
| **仲間** | 誰が一緒に旅をするか | なし、一緒に作る、GMが作る、プレイ中に出会う |
| **画像** | 場所、クエスト、出会う相手の画像 | なし、リクエスト時、新しい場所、クエストと出会う相手（[3.11](#311-pictures)） |
| **ライン**と**ヴェール** | 決して登場しないこと、画面外でだけ起こること | リスト |
| **言語** | ゲームとダッシュボードの言語 | 自由 |

第5版では、**成長方式**も加わります。経験点か、マイルストーンです。

世界が書かれていない場合、GMは**前提**（ジャンル、雰囲気、いくつかの要素を、自分の言葉で）と**準備**も尋ねます。世界を進行に合わせてその場で作るか、最初にすべて作るかです。

**GMの文体**は尋ねられませんが、チャットか**設定**で変えられます。**文章**（簡潔、文学的、パルプ、皮肉）、作られる**物語**（状況、アーク、エピソード、ミステリー）、**文体を似せる**作家、そのほか**自分の言葉**での指定ができます。

### 2.7 セッションゼロ：キャラクター作り

テーブルを囲むときと同じように、GMと一緒にキャラクターを作ります。すべての選択は自分のものです。GMに任せたいときは、そう頼みます。しっかりしたイメージでも、ぼんやりしたイメージでも、何もなくても大丈夫です。能力値の決め方は、ダイスを振る前にGMが説明します。キャラクターの物語は必須ではありません。物語を伝えると、GMが自分の言葉で書き起こします。そのあと、GMがキャラクターの画像を作るか尋ねます（[3.7](#37-your-characters-story-and-picture)）。キャラクターシートはRPG Engineが計算します。計算する必要はありません。

## 3. プレイする <!-- icon: chat -->

### 3.1 GMと話す

キャラクターが何をするか、何を言うかを、自分の言葉で書きます。

> 宿の主人に、今夜ほかに誰が通ったかを尋ねる。

物語の外で話すときは、角かっこで囲みます。*[組みつきはどう処理しますか？]* GMも角かっこで答えます。

やろうとすることを伝えると、GMが何が起こるかを語ります。GMがキャラクターの行動を代わりに決めることはなく、エンジンの話をすることもありません。ダッシュボードの使い方は、GMに尋ねられます。

### 3.2 ロール

GMがロールを求めるのは、結果が不確かで、かつ重要なときだけです。何がかかっているかを、先に伝えます。そのあとは次のとおりです。

- **ダッシュボード**では、判定ごとのボタンがバナーに表示されます。たとえば*軽業 +4 · 有利*です。クリックすると、ページ上でダイスが転がり、GMが結果を受け取ります。光っているキャラクターシートの行をクリックしたり、ダイストレイからダイスを振ったり、バナーに別の内容を書いたりもできます。
- **手動**は、バナーの隅か**設定**で選びます。バナーが何を振るか伝えるので、キャラクターシートかダイストレイから振ります。
- **物理ダイス**は、ダイスの設定を物理にしたときの方式です。振った出目を*[14が出た。]*と書くと、RPG Engineが修正値を加えます。

**フリーロール**：キャラクターシートの数字をクリックするか、ダイストレイを開けば、遊びで振れます。結果には影響せず、GMにも見えません。

**GMのロール**は、ロール欄に表示されます。ただし秘密のロールは除きます。*[今のロールは本物でしたか？]*と、いつでも尋ねられます。秘密のロールについては、尋ねる前に振られていたことを示す指紋を、GMが示します。

### 3.3 シーンと戦闘

物語は**シーン**で進みます。戦闘、会話、探索、移動、休息などです。シーンの終わりごとに、ゲームは自動でセーブされ、そのシーンはジャーナルに記録されます。

戦闘では、自分以外のターンはすべてGMが語り、自分が決める場面で止まります。**戦闘**には、ターンの順番、パーティのヒットポイント、敵の傷つき具合が言葉で表示されます。キャラクターが倒れると、死亡セーブ（死亡判定）が大きく表示されます。

### 3.4 時間、旅、動く世界

RPG Engineは日付を管理します。セッションの合間には時間は経ちません。*長時間の休息を取る*と伝えれば、休息で回復すべきものが回復します。*北の道をたどってロッカへ向かう*と行き先を伝えれば、RPG Engineが道のり、距離、日数を計算し、途中で何かが起こればそこで止まります。お金はゲーム内の硬貨で数え、おつりも含みます。

悪役には期限つきの計画があります。新しい日になるたびに、GMは時間が進めた脅威を動かします。見えるのはその兆しで、時計そのものは見えません。

### 3.5 マップ

**ワールド**には、キャラクターが知っている場所、その間の道、歩いた道のりが表示され、ほかは霧に覆われています。**シーン**には、今いる場所のマップがあれば表示され、誰がどこにいるかも分かります。戦闘中の自分のターンでは、届かないマスにヴェールがかかります。GMがどこへ動くか尋ねたら、マスをタッチするか、*E4*のように書きます。

### 3.6 クエスト、ジャーナル、メモ

キャラクターが引き受けた仕事は、**ジャーナル**にクエストとして載ります。目標、期限、進み具合を測るクロックも記されます。星をつけると、シーンの上部に表示され続けます。ジャーナルには、シーンごとの**物語**も記され、**メモ**も保管されます。メモは非公開です。**共有**したメモだけ、GMに伝わります。GMには、事実ではなく、キャラクターの考えとして届きます。

### 3.7 キャラクターの物語と画像

キャラクターシートの**説明**カードに、キャラクターの物語を書く欄があります。承諾すると、GMが書き込みます。画像は、PNG、JPEG、WebP、SVG（5MBまで）のファイルを、コンピューター上の場所とともにGMに渡すか、肖像画を作ってもらいます（[3.11](#311-pictures)）：*[肖像画を作って。三つ編みの白髪で、あごに傷がある。]*

### 3.8 セーブと戻ること

RPG Engineは、シーンの終わりごとにキャンペーン全体をセーブします。そのほかは**セーブ**の設定で決まります。

| セーブ | 好きなときにセーブ | 戻る |
|---|---|---|
| **パーマデス** | できない | 戻れない |
| **チェックポイント** | できない | キャラクターが死んだときだけ、最後のセーブへ |
| **自由** | できる | 任意のセーブへ |

どのモードでも、プレイの最初か、セッションゼロから**やり直す**ことができます。チャットか**セーブ**で行います。

戻ったあとは、**新しいチャットを開いてください**。古いチャットは、取り消されたことを覚えています。新しいチャットで*続きから*と書き、セーブの**新しいチャットを開いた**を押します。

### 3.9 セッション：中断と再開

いつでも中断できます：*[今夜はここまでにしましょう。]* すべてすでにファイルに保存されています。再開するには、キャンペーンのフォルダーでエージェントを起動し、*続きから*と書きます。GMが短くあらすじを伝えて、続きを進めます。

### 3.10 GMの気分

ダッシュボード上部のロボットはGMです。表情は物語の雰囲気に合わせて変わり、まだ知らないことを明かすことはありません。チャットが閉じているときは眠っています。

### 3.11 画像

RPG Engineは、たどり着いた場所、引き受けたクエスト、出会った相手の画像を作れます。**画像**の設定に従います。頼めば、キャラクターの肖像画も作れます。使うのはコンピューター上のものと自分のログインです。**Codex**があれば**Codex**が描き、なければ**Claude Code**が描きます。このコンピューターで作れるか、作れない場合の設定方法は、**設定**で確認できます。自分で用意した画像をGMに渡すこともいつでもできます。

### 3.12 安全：ライン、ヴェール、ストップ

**ライン**は、ゲームに決して登場しません。**ヴェール**は、画面外でだけ起こります。いつでも*[ストップ]*と書けます。GMはその内容をすぐにやめ、ラインに加えます。

### 3.13 気が変わったとき

どの設定も、チャットか**設定**で変えられます。GMがルールブックにない裁定をしたときは、**先例**として残ります。次に同じ質問があれば、同じ答えになります。

## 4. ダッシュボード <!-- icon: party -->

自分のコンピューター上のページです。そのコンピューターのブラウザーでしか開けず、チャットが開いているあいだだけ動きます。チャットが閉じると*Not connected*と表示され、次のチャットで自動的に戻ります。

- **パーティ**：自分と仲間のキャラクターシート。数字をクリックするとロールできます。カーソルを重ねると、その数字の内訳が見えます。横にはロールが並びます。
- **シーン**：今いる場所、その画像とマップ、そこにいる者、起きていること。
- **戦闘**：戦闘中だけ表示されます。ターン、戦っている者、手元にあるもの。
- **ジャーナル**：クエスト、物語、メモ。
- **ワールド**：キャラクターが知っているとおりの世界のマップ。
- **ダイストレイ**：ダイスと修正値を選んで、振ります。
- **セーブ**、**ヘルプ**、**設定**、**概要**：並びの端にアイコンで表示されます。設定には、ページ自体の好みも入っています。テーマ、ダイスの音、ダイスのセットです。

GMが何か尋ねているときは、どのセクションにいても、バナーが上部に残ります。

## 5. ゲームシステムとハウスルール <!-- icon: dice -->

### 5.1 ゲームシステムとは

1つのゲームのデータです。キャラクターシート、数値、クリーチャー、アイテム、呪文、ルールのテキストが含まれます。キャンペーンごとに、1つのシステムを遊びます。RPG Engineは、キャラクターシートと、消費されるもの、回復するものを計算します。特技がどう働くかは、テーブルで遊ぶときと同じように、GMがルールを読んで決めます。

### 5.2 第5版（収録済み）

SRD 5.1の種族、クラス、サブクラス、背景、特技が入っています。319の呪文、武器、防具、魔法のアイテム、モンスターも入っています。ルールの章は、GMが正確な文面で読みます。キャラクターシートは、すべて計算されます。

SRDにない内容も、持っている書籍から遊べます。GMがキャンペーンのページとして書き起こし、RPG Engineは自前のものとして扱います。RPG Engineが同梱するのは公開されている内容だけです。GMが知っていることに制限はありません。

### 5.3 ハウスルールと独自の追加

GMに頼みます：*[ハウスルール：攻撃で出目1が出たら、武器を落とす。]* GMはそれをテーブルの取り決めとして覚えます。必要なら、ページやキャラクターシートの数値を書き加えます。すでに文章にしたハウスルールは、キャンペーンの`rules`フォルダーにテキストファイルとして置けます。

### 5.4 独自のゲームシステムの追加とインポート

まだできません。現在、RPG Engineが遊べるのは第5版だけです（[今後の予定](#9-coming-later)）。

## 6. 拡張 <!-- icon: plus -->

まだありません。拡張は、ゲームシステムの上に、キャンペーンへ何かを加えるものになる予定です。世界、アドベンチャー、天候のような機能、共有できるハウスルールなどです。

## 7. キャンペーンの成り立ちと言語 <!-- icon: world -->

### 7.1 世界を用意する3つの方法

- **その場で作る**：前提をもとに、GMが場所、人物、筋書きを、必要になる直前に作って保存します。
- **最初に準備する**：同じですが、世界はプレイの前に作っておきます。
- **自分のアドベンチャーから**：テキストかPDFをGMに渡し、セットアップを頼みます：*[このアドベンチャーを私たちのキャンペーンとして準備して。中身は何も教えないで。]* GMが場所、キャラクター、秘密を書き起こします。インポートのボタンはまだありません。

キャンペーンは1回だけ遊びます。同じアドベンチャーをもう一度遊ぶときは、新しいキャンペーンを作ります。

### 7.2 言語

キャンペーンごとに1つの言語で、GMの言語です。ダッシュボードもそれに従います。ダッシュボードには26の言語が収録されています。それ以外の言語は、コンピューター上でCodexかClaude Codeが翻訳します。どちらもなければ、チャットでGMが翻訳します。第5版のイタリア語の用語は、公式のイタリア語版SRDにもとづきます。ルールのテキストは英語のままで、GMが自分の言語で語ります。

## 8. 番外編：キャンペーンフォルダ <!-- icon: list -->

開く必要はありません。キャンペーンの秘密が入っています。中には次のものがあります。`campaign.yaml`（設定）、`state.yaml`（ゲームの現在の状態）、`world/`（キャラクター、場所、クエストなどを1つずつまとめたマークダウンのページ）、`rules/`（ハウスルール）、`images/`、`log.jsonl`（すべての変更の記録）、`.saves/`、`.player/`（メモ）、そして AI エージェントに RPG Engine の場所を伝える小さなファイルです。ページは Obsidian の形式です。ページを手で変更すると、GM は次の返答で変更に気づきます。

RPG Engine はこのフォルダの中だけで動きます。ゲームの読み書きはここだけで行い、ほかのファイルには触れません。フォルダの外に置くのは、専用のデータフォルダ（ダッシュボードの翻訳や、許可した場合の Codex や Claude Code）と、絵を描いている間の一時フォルダだけです。ほかにエージェントがパソコンで何かをしたいときは、先に確認します。

GM が使うコマンドは、キャンペーンフォルダでも実行できます。`rpg --help` で一覧を見られます。多くのコマンドはキャンペーンの秘密を表示します。

## 10. 質問と困ったとき <!-- icon: info -->

### 質問

**ルールを知っている必要はありますか？**いいえ。メンターにチュートリアルを選び、知りたいときはいつでも角かっこで尋ねてください。

**GMはズルをできますか？**RPG Engineが振ったロールは変えられません。すでに決まった事実も変えられません。ただし、難易度がストーリーの場合は例外です。

**お金はかかりますか？**RPG Engineは無料です。GMは、エージェントのプランか、自分のコンピューター上のローカルモデルで動きます。1晩のプレイは長いチャットになります。最小のプランでは、夜が終わる前にプランの上限に達することがあります。画像と翻訳も、同じプランを使います。

**スマートフォンで遊べますか？**いいえ。GMはコンピューター上で動き、ダッシュボードもそこでしか開けません。

**友達と遊べますか？**まだできません。現在は、プレイヤー1人に、キャラクター1人と仲間です（[今後の予定](#9-coming-later)）。

**次回は別のAIを使えますか？**はい。キャンペーンを別のエージェントで開き、*続きから*と書いてください。

### 困ったとき

**ダッシュボードが開きません。**GMに尋ねてください：`[ダッシュボードのリンクは？]`。ダッシュボードが動くのは、そのキャンペーンでチャットが開いている間だけで、GMの最初の返答のあとです。

**GMがゲームを知らないようです。**エージェントがRPG Engineを読み込めていません。キャンペーンのフォルダーで起動したか、フォルダーを信頼したかを確認してください。Claude Codeでは`/mcp`と書いて、`rpg`を再接続します。Codexでは、キャンペーンのフォルダーで`codex mcp list`を実行し、`rpg`が表示される必要があります。`rpg --version`が見つからない場合は、RPG Engineをもう一度インストールしてください（[2.2](#22-install)）。

**更新するには。**`npm install -g rpg-engine`をもう一度実行し、新しいチャットを開きます。動いているGMは、起動したときのバージョンのままです。

**取り消したことをGMが覚えています。**新しいチャットを開き、セーブの**新しいチャットを開いた**を押してください。

**画像が表示されません。**設定 > 画像で、このコンピューターで作れるか、その方法を確認できます。

**インストールに失敗する、または`rpg`が起動しません。**`node --version`が22以降を示す必要があります。Windowsでは、RPG Engineとキャンペーンを、`&`を含むパスに置かないでください。

**ダッシュボードのリンクが変わりました。**ほかのプログラムが、いつものアドレスを使っています。新しいリンクはGMが伝えます。
