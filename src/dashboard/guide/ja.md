# RPG Engine：完全ガイド

**RPG Engine**では、**AIをGMにして**テーブルトークRPGを遊べます。

GMとは**チャット**で会話します。GMは物語を語り、ほかの登場人物をすべて演じ、起きたことを裁定します。

RPG Engineは裏側で動きます。**世界を記憶**し、**ダイスを振り**、**記録をつけます**。

チャットのとなりには、ブラウザーでページを開いておきます。それが**ダッシュボード**です。キャラクターのキャラクターシート、ダイス、マップ、ジャーナルが見られます。

このガイドはプレイヤー向けです。プログラミングの知識は必要ありません。

## クイックスタート <!-- icon: send -->

1. [nodejs.org](https://nodejs.org)から**Node.js**をインストールします（LTS版）。
2. GMが動くAIアプリ、**Claude Code**または**Codex**をインストールし、サインインします（[2.4](#24-connect-your-ai)）。
3. ターミナルを開き、RPG Engineをインストールします：`npm install -g rpg-engine`
4. ターミナルでキャンペーンを作ります：`rpg init "The Salt Isles"`
5. できたフォルダでClaude CodeまたはCodexを開き、*こんにちは！始めましょう。* と書きます。GMがダッシュボードのリンクを教えてくれます。チャットの横で開いてください。

以降の章で、各手順とプレイの仕方を説明します。

## 1. RPG Engineとは <!-- icon: about -->

### 誰が何をするか

| 誰が | 何をするか |
|---|---|
| **自分** | キャラクターを演じます。キャラクターの行動、言葉、挑戦を伝えます。 |
| **GM**（AI） | 物語を語り、そのほかのキャラクターを全員演じ、何が起きるかを決め、ロールを求めます。 |
| **RPG Engine** | すべてをファイルに記憶し、ダイスを振り、ヒットポイント、お金、時間、距離を数え、発見されるまで秘密を守ります。 |

AIは物語を語るのが得意ですが、覚えておくのは苦手です。放っておくと、誰にお金を貸していたか、矢が何本残っているか、橋が二回前のセッションで燃えたことまで忘れてしまいます。RPG Engineがそのすべてを保管するので、世界は夜をまたいでも変わりません。新しいチャットでも、別のAIでも同じです。

### 遊んでいる感覚

テーブルで話すように、チャットに書きます。

> そっとドアを押し開けて、中をのぞきます。

GMが見えるものを答え、選ぶ番が来たところで止まります。結果が不確かで重要なときは、GMが何がかかっているかを伝え、ロールを求めます。ダッシュボードにロールのボタンが現れます。クリックするとページ上にダイスが落ち、GMが結果を語ります。

### ほかとの違い

- **世界は残り続けます。** 語られたことは真実のままです。倒した悪役は倒れたままです。
- **ダイスは本物です。** GMはダイスを曲げられません（最も易しい難易度を選んだ場合を除きます）。
- **秘密は秘密のままです。** キャラクターが知らないことは、頼んでもGMは教えません。
- **世界は自分がいなくても動きます。** 休息や移動の間にも脅威は進み、その兆しが見えます。
- **たくさんの夜、ひとつの物語。** キャンペーンはパソコン上のフォルダです。いつでも中断して、後で続けられます。

### 今遊べるゲーム

RPG Engineは、どんなテーブルトークRPGにも使えるように作られています。現在対応しているゲームシステムは、**第5版**（無料のSystem Reference Document 5.1）だけです。ほかのゲームは今後対応します。[ゲームシステム](#5-game-systems-and-house-rules)と[今後の予定](#9-coming-later)を見てください。

## 2. はじめに <!-- icon: path -->

### 2.1 必要なもの

- Windows、macOS、Linuxのいずれかが動くパソコン。
- **Node.js 22**以降。[nodejs.org](https://nodejs.org)から入手します。「LTS」版で問題ありません。Node.jsには`npm`が付いていて、RPG Engineのインストールに使います。
- **ターミナル**。コマンドを入力するウィンドウです。Windowsでは「ターミナル」アプリかPowerShell、macOSでは「ターミナル」を使います。RPG Engineのインストール、キャンペーンの作成、Claude CodeやCodexの起動に使います。
- **AIホスト**。GMが動くアプリです。**Claude Code**か**Codex**を、プランとログインも含めて用意します。[2.4](#24-connect-your-ai)を参照してください。
- AIホストが提供する**最大のモデル**。小さいモデルはだまされやすく、私たちのテストでは、本物のGMだと名乗るプレイヤーに秘密を話してしまいました。
- ダッシュボード用のウェブブラウザ。

AIホストのログインは、ほかの場面でも使われます。RPG Engineは、場所、クエスト、キャラクターの絵を描くときや、ダッシュボードを未対応の言語に翻訳するときに、このログインをパソコン上で使います。[画像](#311-pictures)と[言語](#72-languages)を参照してください。

**フォルダでターミナルを開く。** 多くの手順に「キャンペーンフォルダで」とあります。Windowsでは、エクスプローラーでフォルダを右クリックして**ターミナルで開く**を選びます。macOSでは、Finderでフォルダを右クリックして**サービス > フォルダに新規ターミナル**を選びます。すでにターミナルが開いている場合は、`cd`に続けてフォルダのパスを入力します。例：`cd "C:\Users\me\Games\The Salt Isles"`

### 2.2 インストール

ターミナルを開いて、次を入力します。

```text
npm install -g rpg-engine
```

これで`rpg`コマンドが使えるようになります。うまくいったか確認するには、次を入力します。

```text
rpg --version
```

`rpg`を使うのは、キャンペーンを作るときの1回だけです。その後はGMと話すだけです。AIホストが同じ`rpg`コマンドで、RPG Engineを自動的に起動します。

### 2.3 キャンペーンを作る

キャンペーンはフォルダです。ゲームを置いているフォルダでターミナルを開き、次を入力します。

```text
rpg init "The Salt Isles"
```

すると`The Salt Isles`フォルダが作られ、中に新しいキャンペーンができます。次にすることも表示されます。

```text
Created the campaign "The Salt Isles" in C:\Users\me\Games\The Salt Isles.
To play, open Claude Code or Codex in this folder and say hello: the master asks you the rest.

For the master: Still to agree with the player: ...
```

*For the master*以降の行はGM向けで、GMがチャットで読みます。プレイヤーが何かする必要はありません。フォルダの場所は覚えておいてください。遊ぶたびにここへ戻ってきます。フォルダ名を付けずに`rpg init`を実行すると、いま開いているフォルダがキャンペーンになります。

`init`は、キャンペーンに必要なものをすべて作ります。設定、ワールド用のフォルダ、そして、RPG Engineを使うことと、キャンペーンの外に独自の記憶を持たないことをAIホストに伝える小さなファイルです。

いま何かを選ぶ必要はありません。残りはGMがチャットで尋ねます。ダッシュボードで選ぶこともできます。すでに決めていることがあれば、ここで指定できます。

```text
rpg init salt-isles --name "The Salt Isles" --language en --system 5e --difficulty normal --lethality dice
```

これで`salt-isles`フォルダが作られ、中にキャンペーン*The Salt Isles*ができます。フォルダ名は空白なし、キャンペーン名は好きなものにできます。

| オプション | 設定する内容 | 値 |
|---|---|---|
| `--name` | キャンペーン名 | 自由。省略するとフォルダ名 |
| `--language` | ゲームの言語 | `en`、`it`、`fr`などのコード |
| `--system` | ゲームシステム | `5e`（現時点ではこれだけ） |
| `--difficulty` | ワールドの厳しさ | `story`、`easy`、`normal`、`hard`、`brutal` |
| `--lethality` | 戦闘で倒れたときの扱い | `narrative`、`epic`、`dice` |

`rpg init --help`でも一覧を見られます。キャンペーンを別のキャンペーンのフォルダの中に作ることはできません。

GMにキャンペーンの作成を頼むことはできません。`init`の前のフォルダには、RPG Engineの場所をAIホストに伝えるものが何もないからです。

### 2.4 AIをつなぐ

RPG Engineは**Claude Code**と**Codex**で動きます。MCPツールを使うほかのAIアプリでも動く可能性はありますが、保証はしません。

**AIホストのインストール。** Claude CodeとCodexはターミナルで動きます。スマートフォンのClaudeアプリやChatGPTアプリとは別物です。それぞれに専用のプランとログインが必要です。Claude Codeは有料のClaudeプラン、CodexはChatGPTのログインを使います。インストールとサインインは、それぞれの公式ページに従ってください：[Claude Code](https://code.claude.com/docs/en/setup)と[Codex](https://learn.chatgpt.com/docs/codex/cli)。これは1回だけで、すべてのキャンペーンで使えます。

**Claude Code。** キャンペーンフォルダでターミナルを開き、`claude`と入力します。初回は、フォルダを信頼するかどうかを尋ねられ、このフォルダがゲームのツール（`mcp__rpg`）を許可することも表示されます。**Yes, I trust this folder**を選んでください。注意：最初に選ばれているのは*No, exit*なので、そのままEnterを押すとClaude Codeが閉じます。これで準備は完了です。キャンペーンがすでに、RPG Engineとそのツールを使うこと、そして記憶機能をオフにすることをClaude Codeに伝えています。

**Codex。** キャンペーンフォルダでターミナルを開き、`codex`と入力します。フォルダを信頼するか尋ねられたら、はいと答えてください。キャンペーン自身の設定が、RPG Engineの場所、ツールの許可、記憶機能のオフをCodexに伝えます。Codexは、信頼したフォルダの設定しか読みません。デスクトップアプリでは、ゲームのチャットで記憶機能（memories）がオフになっていることを確認してください。

**記憶機能が重要な理由。** キャンペーンの内容はファイルに保存されます。AIホストが独自に記憶していると、セーブに戻っても本当には戻りません。取り消したはずのことをGMが覚えたままになるからです。

### 2.5 最初のチャット

何でもいいので書いてみましょう。たとえば次のように書きます。

> こんにちは！始めましょう。

GMがゲームの現状を読み込んで答えます。チャットごとの最初の返答で、GMが**ダッシュボードのリンク**（`http://127.0.0.1:4750`のようなもの）を伝えます。ブラウザで開き、ゲームの間ずっとチャットの横に置いておきましょう。キャンペーンごとのリンクは、チャットが変わっても同じです。ほかのプログラムが使っている場合だけ、GMが新しいリンクを伝えます。

GMのメッセージの合間に、AIホストがGMの使っているツールを短い行で表示します。その詳細は開かないでください（Claude Codeではctrl+o）。GMが書いた内容が、秘密も含めて見えてしまうことがあります。

新しいキャンペーンは、人間のGMがいるゲームと同じように、3つの段階を進みます。ダッシュボードの上部には*1 設定 · 2 セッションゼロ · 3 プレイ*と表示されます。

1. **設定**：遊び方を選びます。物語の外で行います。
2. **セッションゼロ**：プレイしながらキャラクターを作ります。
3. **プレイ**：物語を進めます。

### 2.6 設定：遊び方を選ぶ

GMは、まだ決まっていないことだけを、何問かずつ尋ねます。「お任せ」と書けば、GMが選んで、選んだ内容を伝えます。ダッシュボードを開いている場合は、最初のステップの**設定**に同じ質問がカードで表示されます。1度に1問ずつで、各値には意味の説明が付き、よく使われる値には**おすすめ**の印が付きます。そこで選べば、GMはチャットで改めて尋ねません。**スキップ**すると、その質問は後回しになります。言葉でしか決められないことは、チャットで決めます。新しいワールドの前提、言語、画像です。画像は、パソコンで作れる場合だけGMが尋ねます。そのため、ページの質問は下の表より少なくなります。

表をすべて覚える必要はありません。調べるためのものです。どの項目も、あとからチャットかダッシュボードの**設定**で変えられます。変更は、GMの次の返答から反映されます。

| 設定 | 決める内容 | 値 | おすすめ |
|---|---|---|---|
| **メンター**（「このゲームにどのくらい慣れていますか？」という質問） | 物語の外で、GMがルールをどのくらい教えるか | **オフ**（物語だけ。知りたいときは角括弧で質問）、**ヒント**（重要な選択の前や、ルールが見過ごされたときに短いアドバイス）、**チュートリアル**（各ルールを初登場時に説明し、毎回のロールの計算式をすべて示し、戦闘後に短い振り返りをする） | 答えから決まる：初めて→チュートリアル、少し→ヒント、慣れている→オフ |
| **難易度** | ワールドの厳しさ。戦闘、敵の戦術、手がかり、財宝、脅威が進む速さ | ストーリー、イージー、ノーマル、ハード、過酷 | |
| **致死性** | 戦闘で倒れたときの扱い | **物語優先**（キャラクターは死なない）、**英雄的**（物語上重要なときだけ死ぬ）、**ダイス**（ダイスが決める） | 難易度に従う：ストーリー→物語優先、イージー→英雄的、ノーマル以上→ダイス |
| **セーブ** | いつ戻れるか | **パーマデス**（戻れない。キャンペーンを最初からやり直すだけ）、**チェックポイント**（直前のシーン終了時に戻れる。キャラクターが死んだときだけ）、**自由**（どのセーブにも戻れて、頼めばいつでもセーブできる） | チェックポイント |
| **厳しさ** | 食料、明かり、疲労、荷物の重さ、呪文の構成要素、旅を、どこまで厳密にルール通りに扱うか | **なめらか**（GMが省略する）、**ルール**（書かれた通り。松明は燃え尽き、食料はなくなる）、**シミュレーション**（ルール以上。摩耗、腐敗、天候） | なめらか |
| **ダイス** | キャラクターのダイスを誰が振るか | **デジタル**（RPG Engineがページ上で振る）、**物理**（自分で振って出目を伝える） | |
| **単位** | 物語の中の距離と重さ | メートル法、ヤード・ポンド法 | |
| **仲間** | 誰と一緒に旅をするか | なし、セッションゼロで一緒に作る、GMが作る、プレイ中に出会う | |
| **画像** | 場所とクエストの画像。頼めばキャラクターの肖像も | なし、依頼時のみ、新しい場所とクエスト | 1回だけ尋ねる。パソコンで作れる場合のみ |
| **ライン** | ゲームに決して出さないこと | リスト、またはなし | |
| **ヴェール** | 起きてもよいが、画面の外でだけ起きること | リスト、またはなし | |
| **言語** | ゲームとダッシュボードの言語 | 自由 | 書き方から判断し、確認する |

ゲームシステムが独自の設定を加えることもあります。第5版では**成長方式**が加わります。キャラクターのレベルアップを、**経験点**で行うか、物語の**マイルストーン**で行うかを選びます。

**難易度がプレイでどう影響するか。** ストーリー：弱くて単純な敵、わかりやすい手がかり、何でも豊富。GM自身のロールを手加減することもあります。イージー：単純な敵、潤沢な資源。ノーマル：賢明な敵、1つの結論につき3つの手がかり、標準的な価格と財宝。ハード：賢い敵、わかりにくい手がかり、乏しい資源、素早く動く脅威。過酷：待ち伏せ、撤退、倒れた者へのとどめを行う敵、非常に乏しい資源、最も厳しい休息。戦闘は常に、現在のパーティに合わせた規模になります。

**書かれたワールドがない場合**は、設定でさらに2つ尋ねられます。

- **前提**：ジャンル、雰囲気、ワールドのいくつかの要素を、自分の言葉で。例：*「ローファンタジー。陰鬱だが希望もある。川沿いの町、幽霊が出る浅瀬、丘陵の教団。」*
- **準備**：**その場で**（必要になる直前に、GMがワールドの各部分を作る。おすすめ）か、**最初にすべて**。

その後、GMがキャンペーンの名前を提案します。不足がなくなり、準備ができたと伝えると、ゲームはセッションゼロに進みます。

### 2.7 セッションゼロ：キャラクター作り

セッションゼロもプレイの一部です。テーブルを囲むときと同じように、GMと一緒にキャラクターを作ります。

- **選択はすべて自分のものです**。GMに任せたいと伝えた場合は別です。固まったアイデア（「神殿を出たハーフエルフの聖職者」）でも、漠然としたアイデア（「人を癒やすけれど、優しくはない人」）でも、白紙（「お任せ。あとで変えさせて」）でも構いません。
- **能力値。** ダイスを振る前に、GMが方法と救済策を伝えます。第5版では、標準配列、ポイントバイ、4d6の下位1つを除外、のいずれかです。合意した方法は、テーブルの取り決めとして残ります。
- **キャラクターの背景**は必須ではありません。書いた場合、GMは本人の言葉のまま書き留め、1度読み返して確認し、登場する人物や場所をワールドに結び付けます。ダッシュボードで書くこともできます（[パーティ](#party)を参照）。
- **人格**（第5版）：特徴、理想、絆、欠点。背景の表から選んでも、自分で作っても構いません。
- **絵。** キャラクターができると、GMが絵を頼みます。パソコン上のファイルか、特徴の説明からパソコン上で作る肖像です（[キャラクターの絵](#37-your-characters-story-and-picture)を参照）。

シートの数値は、選択をもとにRPG Engineが計算します。計算は一切必要ありません。キャラクターができて確認すると、物語が始まります。

## 3. 遊び方 <!-- icon: chat -->

### 3.1 GMと話す

キャラクターの行動やセリフを、自分の言葉で書きます。短くても大丈夫です。

> 宿の主人に、今夜ほかに誰が通ったか尋ねる。
>
> 「もめ事を起こしに来たんじゃない」と、剣から手を離して言う。
>
> 屋根に登って待つ。

**物語の外**の発言は、角括弧で囲んで書きます。

> [組みつきはどう扱いますか？]
>
> [このラウンド、まだリアクションを使えますか？]
>
> [今夜はここまでにします。]

GMも角括弧で答え、そのあと物語に戻ります。

**やろうとすることを伝えるのがプレイヤー、何が起きるかを決めるのがGMです。** ワールドの論理や、すでに決まった事実に反することは起きません。GMが物語の中でそう伝え、可能なことを提案します。

**GMがキャラクターの行動を勝手に決めることはありません。** 発言、感情、選択を代わりに決めることはなく、迷ったときは尋ねます。

**GMがエンジンの話をすることはありません。** 記録を取っているかと尋ねても、GMらしく答えます。「すべて覚えています。次回はここから再開しましょう。」

**ダッシュボードの使い方は、GMに尋ねられます。** GMはページのことを知っています。「呪文はどこで見られますか？」「手動で振るにはどうしますか？」

### 3.2 ロール

**ロールが行われるとき。** GMがロールを求めるのは、結果が不確かで、しかも重要なときだけです。それ以外は「はい」か「はい、ただし」で進みます。ロールの前に、GMは何がかかっているか、どの判定が合うかを伝えて、そこで止まります。ロールするか、考え直すかを選べます。

> **GM:** 足場は狭く、濡れています。滑れば、川へ長い距離を落ちることになります。【敏捷力】（軽業）判定をするか、引き返して階段を探すこともできます。
>
> **自分:** やってみます。

**ダッシュボードで振る。** GMが求めると、ページの上部にバナーが現れ、判定ごとにボタンが表示されます。たとえば*軽業 +4 · 有利*です。クリックすると、ページ上にダイスが落ち、結果がGMに伝わります。ほかにも次の方法があります。

- シートの該当する行をクリックする（金色に光ります）。
- ダイストレイから適切なダイスを投げる。
- ほかのことをしたい場合は、バナーに自分の言葉を書く。

**手動で振る。** ダイスを自分で選びたい場合は、バナーの隅にある**手動**をオンにします（**設定**でもできます）。判定のボタンが消え、バナーには、GMが言うように何を振るかが表示されます。*シートまたはダイスで、自分で軽業をロールしてください。*光っているシートの行をクリックするか、ダイストレイから適切なダイスを投げます。RPG Engineがダイスを振り、ボーナスを加え、結果がGMに伝わります。1の目を振り直すダメージなど、シートでもダイストレイでも行えない判定には、ボタンが残ります。手動は、オフにするまでこのブラウザでオンのままです。

**ゲーム全体で物理ダイスを使う。** **ダイス**設定を物理にすると、GMは言葉でロールを求め、振った出目を自分で書いて伝えます。

> [14が出ました。]

RPG Engineが修正値を加えます。手持ちのダイスで出ない目は受け付けません。

**フリーロール。** シートの任意の数値をクリックするか、ダイストレイを開けば、遊びで振れます。フリーロールは結果に影響せず、記録もされず、GMにも見えません。フリーロールの20が、あとで本物になることはありません。

**GMのロール。** 敵などのためのロールも、GMはRPG Engineで振ります。ほとんどのロールは、ロール欄に表示されます。結果を見せてはいけないときは、GMが秘密にロールします。いつでも尋ねられます。

> [さっきのロールは本物でしたか？]

表示されたロールなら、GMが数値と理由を伝えます。秘密のロールなら、質問より前にロールされたことを証明する指紋（フィンガープリント）を示します。

**チャットのロール**は、結果を決める場面の直後に角括弧で表示されます。*[説得 14 + 3 = 17]*のように。そのあと、物語が結果を語ります。

### 3.3 シーンと戦闘

GMは物語を**シーン**で進めます。戦闘、会話、探索、移動、休息、チャレンジ（追跡、競走、謎解き）などです。プレイヤーが管理する必要はありません。シーンは、RPG Engineが物語を章ごとに記録するための仕組みです。シーンが終わるたびにゲームは自動でセーブされ、そのシーンはジャーナルのストーリーに加わります。

**戦闘では**、GMがプレイヤー以外のターンをすべて、ロールも含めて順に語り、**プレイヤーが決められる場面で止まります**。自分のターン、リアクション、選択の場面です。自分のターンには、やることを伝えます。

> ドアのそばの相手に聖なる炎を唱える。

ダッシュボードの**戦闘**には、ターン順、いま誰のターンか、パーティのヒットポイント、敵の負傷の度合いが表示されます。敵の状態は数値ではなく言葉で、無傷、負傷、瀕死、戦闘不能のように示されます。キャラクターが倒れると、死亡セーヴィングスローがページに大きく表示されます。

**戦闘の勝敗がすでに決まっているとき**は、GMが残りを1つのメッセージにまとめて語ることを提案する場合があります。

### 3.4 時間、旅、動くワールド

**時間。** すべての行動には物語の中で時間がかかり、RPG Engineが日付を管理します。たとえば3日目の早朝です。GMは、そのワールドでの時間の数え方で伝えます。夜明け、3つ目の鐘、日没などです。セッションの合間に時間は流れません。止めたところから再開します。

**休息。** 休むと伝えれば、GMが休息で回復するもの（ヒットポイントや呪文スロットなど）を反映します。

> 野営して、ロングレストを取る。

**旅。** 行きたい場所を伝えます。

> 北の道を通ってロッカへ向かう。

RPG Engineが道筋、距離、歩く速さに応じた日数を計算し、そこまで移動します。旅が止まるのは、道中で予定されていた出来事が起きたとき、1日の移動が終わるとき、到着したときです。出発する前に、場所までの距離を尋ねることもできます。

> [ロッカまでどのくらいですか？徒歩だとどのくらいかかりますか？]

**ワールドはプレイヤーがいなくても動きます。** 悪役には、期限とクロックのある計画があります。新しい日が来るたびに、GMは時間が進めた脅威を動かし、その兆しが見えてきます。噂、痕跡、町の変化などです。クロックそのものは見えず、残された兆しだけが見えます。

**お金**は、ゲーム内の硬貨で数えます。支払い、売却、受け取りでは、RPG Engineがおつりを計算します。

### 3.5 マップ

**ワールドのマップ**（ダッシュボード：**ワールド**）には、キャラクターが知っている場所だけが、場所をつなぐ道、歩いた足跡とともに表示されます。それ以外はすべて霧に覆われています。場所をクリックすると、知っている情報と、そこまでの距離がわかります。

**場所のマップ**（ダッシュボード：**シーン**、戦闘中は**戦闘**）は、いる場所についてGMがマップを描いたときに表示されます。壁、ドア、地面、そして誰がどこにいるかがトークンで示されます。戦闘中の自分のターンでは、行けないマスにヴェールがかかるので、動ける範囲がひと目でわかります。GMがキャラクターの移動先を尋ねると、ページにマップが開くので、マスにタッチするか、*E4*のようにマスを書いて伝えます。

### 3.6 クエスト、ジャーナル、メモ

**クエスト。** キャラクターが依頼を引き受けると、**ジャーナル**にクエストとして記録されます。依頼者、場所、期限、目標のリスト、進み具合を測るもの（残り時間つきの期限、クロック、カウント）が載ります。星印を付けると追跡でき、次の目標とともに、シーンの上部に小さく表示されます。クエストが終わるのは物語が終わらせたときだけで、自動では終わりません。

**ストーリー。** ジャーナルのストーリータブは、キャンペーンを時系列で並べたものです。シーンごとに1章で、場所、日付、短い要約が付き、新しいものが先頭に来ます。

**自分のメモ。** ジャーナルのメモタブには、推理、名前、計画などを自由に書けます。メモはパソコンに保存され、**共有**しない限りGMは読みません。共有したメモは、GMの次の返答で、プレイヤーの考えとして伝わります。事実としては扱われません。推理は、書いたからといって真実にはなりません。特定の内容を止めたり避けたりするよう求めるメモは、テーブルで口頭で伝えたのと同じ扱いになります。

### 3.7 キャラクターの背景と絵

キャラクターのシートの**説明**カードには、キャラクターの背景を書くボックスがあります。送信すると、了承したあとで、GMが背景を自分の言葉でキャラクターに書き込みます。

キャラクターの絵は、絵のファイルをパソコン上の場所を添えてチャットでGMに渡します（PNG、JPEG、WebP、SVG、5 MBまで）。

> [キャラクターの肖像です：C:\Users\me\Pictures\mira.png]

GMがキャンペーンにコピーし、ダッシュボードのキャラクターのトークンに表示されます。変えたいときはいつでも、同じ方法で変更できます。

パソコンで画像を作れる場合は、肖像を作ってもらうこともできます（[画像](#311-pictures)を参照）。キャラクターの特徴をGMに伝えるか、GMに描写してもらいます。

> [肖像を作ってください：三つ編みにした白髪、あごの傷、疲れた目。]

肖像には、ゲーム内のキャラクターの姿がそのまま描かれます。このワールドでのその種族らしい姿で、たとえばヒルドワーフならヒルドワーフらしく、伝えた特徴も反映されます。1分ほどで、キャラクターのトークンに表示されます。仲間の肖像も同じ方法で作れます。

### 3.8 セーブと巻き戻し

RPG Engineは、**シーンが終わるたび**に、キャンペーン全体を自動でセーブします。そのセーブをどう使えるかは、**セーブ**設定で決まります。

| セーブ | 好きなときにセーブ | 戻る |
|---|---|---|
| **パーマデス** | できない | 戻れない。キャンペーンを最初からやり直すだけ |
| **チェックポイント** | できない | 直前のセーブへ。キャラクターが死んだときだけ |
| **自由** | できる | どのセーブへも、いつでも |

どのモードでも**やり直し**ができます。同じキャラクターでプレイの最初から、または新しいキャラクターでセッションゼロからです。

これらはすべて、チャット（「[決闘の前に戻りましょう。]」）か、ダッシュボードの**セーブ**で行えます。

**戻ったあとは、新しいチャットを開いてください。** プレイしていたチャットは、取り消された内容を覚えたままです。GMと新しいチャットを開き（Claude Codeでは`/clear`、Codexでは`/new`）、*continue*と書いてから、セーブの**新しいチャットを開いた**を押すか、新しいチャットでGMに伝えます。古いチャットを再開してはいけません。確認するまで、GMは先へ進みません。

### 3.9 セッション：中断と再開

**セッションはいつでも終えられます。**

> [今夜はここまでにします。]

「セーブして終了」という操作はありません。すべてがすでにファイルに保存されています。

チャットを**閉じる**には、Claude Codeでは`/exit`、Codexでは`/quit`と入力します。ダッシュボードは、次のチャットまで静かになります。

**再開する**には、キャンペーンフォルダ（`init`が表示したフォルダ）でターミナルを開き、そこでAIホストを起動して*continue*と書きます。GMがゲームの現状を読み込み、短いあらすじを伝えて、何かが起きている場面から始めます。新しいチャットでも失われるものはありません。キャンペーンはチャットではなく、ファイルの中にあります。

GMが終わりに、お決まりの質問をすることはありません。うまくいかなかったことに気づいた場合だけ、簡単に尋ねます。

### 3.10 GMの気分

ダッシュボードの上部には、GMのアバターである小さなロボットがいます。顔つきは物語の雰囲気に合わせて変わります。危険が迫れば心配そうに、大胆なアイデアには喜び、意外な展開には驚きます。出目20や出目1のときも、一瞬反応します。まだ知らないことは決して表に出しません。罠が作動する前にニヤリとすることはありません。パーティのトークンにも、それぞれの気分が表示されます。チャットが閉じているときは、ロボットは眠っています。

### 3.11 画像

RPG Engineは、**画像**設定に従って、訪れた場所や引き受けたクエストごとに画像を作れます。頼めば、キャラクターの肖像も作ります。パソコンにすでにあるものを使います。

- **Codex**：ChatGPTのログインで、絵画風の画像。
- それ以外は**Claude Code**：Claudeのログインで、線画。

画像の作成には、私たちではなく自分のプランが使われます。パソコンで画像を作れるかどうかは**設定**に表示され、作れない場合は設定の手順も表示されます。画像がない場合、ページには場所の種類ごとのマークが表示されます。どの場所やキャラクターにも、自分で用意した画像をGMに渡せます。

### 3.12 安全：ライン、ヴェール、ストップ

- **ライン**：ゲームに決して出さないこと。
- **ヴェール**：起きてもよいが、画面の外でだけ起きること。
- **ストップ**：どんな内容でも、理由を説明せずにいつでも止められます。物語の外で書きます。

> [stop]

GMはすぐにその内容をやめ、以降のすべてのセッションのために、ラインに追加します。ラインとヴェールは、**設定**で確認や変更ができます。

### 3.13 気が変わったとき

どの設定も、キャンペーンの途中で変えられます。チャット（「[もっと難しくしましょう。]」）か**設定**で変更します。変更は、GMの次の返答で伝わります。GMが本のルールにないことを裁定した場合、それは**先例**として保存されるので、次に同じ質問があれば同じ答えになります。

## 4. ダッシュボードの各セクション <!-- icon: party -->

ダッシュボードは、自分のパソコン上のページです。リンクは、チャットのはじめごとにGMが教えます。ゲームにライブで追従し、GMが何かを変えると、ページも変わります。

開けるのは、遊んでいるパソコンのブラウザだけです。同じWi-Fiでも、スマートフォンやタブレットでは開けません。ページは狭いウィンドウにも合わせられます。その場合、セクションは下部のバーに、アイコンはメニューに移ります。

ページが生きているのはチャットの間です。チャットを閉じると、開いたままのページには*接続なし*と、最後の状態のシートが表示され、GMのロボットは眠ります。キャンペーンでまたチャットを開き、GMが答えれば、ページは自動で戻ります。

### 上部

- **GMのアバター**と、その表情。
- キャンペーンの名前、ゲームシステム、**ゲーム内時間**、ゲームが**接続中**かどうか（チャットがつながっているか）。
- セクション：**パーティ**、**シーン**、**戦闘**（戦闘中のみ）、**ジャーナル**、**ワールド**。行の末尾にアイコンで：**セーブ**、**ヘルプ**、**設定**、**概要**。
- ライトテーマとダークテーマ（右上）。

GMが何かを尋ねているときは、どのセクションにいても、そのバナーがページの上部に残ります。

### パーティ

キャラクターのシートと、仲間のシートです。シートの各部分はカードで、開閉できます。

- **数字をクリック**すると、遊びでロールできます。数字にポインタを合わせると、その内訳が見えます（「+5：判断力 +3、習熟 +2」）。
- **ヒットポイント、スロット、使用回数**は、バーと点で表示されます。
- **状態と効果**は、持続時間とともに表示されます。
- **説明**には、キャラクターの文章と、キャラクターの物語をGMに送るボックスがあります。
- ヒットポイントが0になると、名前の下に**死亡セーヴィングスロー**が大きく表示されます。
- シートの横（狭い画面では下）には、**ロール**が新しい順に並びます。自分のロールと、見てよいGMのロールです。**クリア**でリストを空にし、**元に戻す**で復活します。フリーロールは破線で薄く表示されます。

狼のように能力値ブロックを持つ仲間は、完全なシートの代わりに能力値ブロックが表示されます。

### シーン

パーティのいる場所です。場所の画像と名前、周囲の場所、場所にマップがあればそのマップ、そこにいる者たち、そして今起きていることを含む進行中のシーンが表示されます。追跡中のクエストは上部にあります。

### 戦闘

戦闘中だけ表示されます。上部には、ラウンド、行動中の者、次の者。その下には、ターンの順番、各戦闘員の状態（パーティは数字、敵は言葉）、キャラクターの手元にあるもの（アーマークラス、ヒットポイント、攻撃）、場所のマップ（行動中の者に輪が付きます）が表示されます。自分のターンには、どこにいても、戦闘のリンクが金色に脈打ちます。

### ジャーナル

三つのタブがあります。

- **クエスト**：進行中、完了、失敗のクエストが、目標、タイマーで示される期限、クロックとともにカードで表示されます。星でクエストを追跡します。
- **ストーリー**：キャンペーンの章がシーンごとに並び、新しいものが先頭です。
- **メモ**：自分のメモ。共有するまで非公開です。

### ワールド

キャラクターが知っている形のワールドマップで、そのほかは霧に覆われています。ドラッグで移動し、ホイールかピンチで拡大縮小します。場所をクリックするとカードが開きます。場所のリストが近い順に横に並びます。マップが複数ある場合（都市、大陸、別の次元）は、タブで切り替えます。

### ダイストレイ

ダイスのボタンでトレイを開きます。ダイスと修正値を選んで振ります。同じ種類のダイスが二つ以上あるときは、どれを数えるか選べます。**すべて**、**高い方**（最も高いものだけ）、**低い方**（最も低いものだけ）です。選んだダイスは、**クリア**を押すまで残るので、毎ラウンド同じダメージロールがワンクリックです。GMがロールを求めている間は、どのダイスが当てはまるかをトレイが示します。

### セーブ

セーブが新しい順に並び、それぞれに場所、ゲーム内の日付、作成時刻が付きます。**今すぐセーブ**（フリーのセーブ時）、**ここに戻る**、そして赤い**最初からやり直す**（二段階）があります。[セーブと戻ること](#38-saves-and-going-back)を見てください。

### 設定

設定はグループに分かれています。ゲーム、ゲームの学習（メンターと、すでに説明されたルール）、ダイスと単位、制限（ラインとヴェール）、画像、言語です。値をクリックして選ぶと、その下に意味が表示されます。その後にページ自身の設定があり、このブラウザにだけ保存されます。テーマ、ダイスの音、**ダイスセット**（樹脂、金属、木、石）、角の丸みと鋭さ、手で振ることです。

ハウスルールや先例など、GM自身の設定はここにはありません。チャットの中にあります。

### ヘルプと概要

**ヘルプ**：このガイド。**概要**：RPG Engineとは何か、リンク、ライセンス、ゲームシステムのクレジット。

### プレイ前：設定とセッションゼロ

新しいキャンペーンが最初の段階の**設定**にある間は、ページ全体が質問を表示します。一度にひとつで、各値の意味とおすすめが付きます。**自分で決める**を押すと質問をGMに任せます。ただし、ラインとヴェールは常に自分のものです。**スキップ**を押すと後回しになります。最後に**準備完了**を押します。

### ページからのメッセージ

ページが上に通知を重ねて表示することがあります。キャンペーンのファイルの問題（GMが直します）、ゲームが不在（チャットが閉じています）、ページが翻訳中、などです。

## 5. ゲームシステムとハウスルール <!-- icon: dice -->

### 5.1 ゲームシステムとは

ゲームシステムは、ひとつのゲームのデータです。シート、数字、クリーチャー、アイテム、呪文、ルールの文章が含まれます。各キャンペーンは、ひとつのシステムで遊びます。

RPG Engineは、デジタルのキャラクターシートと同じように、キャラクターシートと、消費して戻るもの、たとえばヒットポイントや呪文スロットを計算します。特技や呪文がどう働くかは、GMがルールを読み、テーブルと同じように裁定します。

### 5.2 第5版（同梱）

RPG Engineには**5e**が同梱されています。System Reference Document 5.1（2014年のルール、Creative Commonsで無料）に基づきます。含まれるものは次の通りです。

- SRDの種族、クラス、サブクラス、背景、特技。
- 319の呪文、武器、防具、装備、魔法のアイテム、SRDのモンスター。
- ルールの章。GMが正確な文面で調べます。
- 計算済みの完全なキャラクターシート：能力値修正、セーヴィングスロー、技能、アーマークラス、攻撃、呪文セーヴ難度、スロット、ヒット・ダイス、レベル別の特徴、経験値、レベルアップ。
- 本来回復すべきものを回復する休息、ルール文付きの状態、精神集中のリマインダー。

**SRDを超える内容。** SRDにない内容、たとえば持っている本のクラスやモンスターを使って、第5版を遊べます。GMはゲームを知っていて、手持ちの資料を読み、Webを検索できます。必要なものをキャンペーンのページとして書き、RPG Engineはそれらも同じように扱います。同梱できるものはライセンスで限られますが、GMが知っていることに制限はありません。

RPG Engineは第5版と互換性があります。

### 5.3 ハウスルールと独自の追加

ファイルに触れる必要はありません。GMに頼んでください。

> [ハウスルール：攻撃で出目1が出たら、武器を落とす。]
>
> [ブラッドハンターを遊びたいです。本は持っています。クラスの特徴はこれです。]
>
> [このキャンペーンでは、ショート・レストは10分かかります。]

GMは、次のいずれかの形でキャンペーンに記録します。

- **テーブルの取り決め**。言葉によるもので、上の武器を落とすことやショート・レストがその例です。GMはキャンペーンの設定とともに保管し、以後それに従います。GMが本にないところで下した裁定も、同じように**先例**として残ります。
- **新しいページ**。たとえばクラス、種族、アイテムです。新しいクラスはシステムのクラスと同じように働き、レベル、ヒット・ダイス、特徴が数えられます。新しい種族は既存の種族を土台にでき（「エルフと同じで、さらに…」）、名前付きの剣はロングソードを土台にできます。
- **シートの新しい数字**：欄、表、計算式、休息で回復するカウンターです。たとえば、ショート・レストで戻るバトルマスターの上級ダイスです。ハウスルールで、システムの計算式のひとつを置き換えることもできます。

すでに書き出したハウスルールがあるなら、キャンペーンの`rules`フォルダにテキストファイルとして置くこともできます（[キャンペーンフォルダ](#8-for-the-curious-the-campaign-folder)を見てください）。GMは、同じ名前の本のルールより先にそれを読みます。

### 5.4 独自のゲームシステムの追加と取り込み

現在、RPG Engineで遊べるのは第5版だけです。ほかのゲームシステムは今後対応します。自分のシステムを追加したり、持っているゲームをそのルールブックから取り込んだりする方法も追加されます。[今後の予定](#9-coming-later)を見てください。

## 6. 拡張 <!-- icon: plus -->

**拡張はまだ使えません。** 拡張は、ゲームシステムの上でキャンペーンに何かを加えます。世界、冒険、天候やタロットのような機能、共有するハウスルールなどです。どれを使うかは、キャンペーンごとに選べるようになります。第5版向けに最初に予定されているのは、天候と鍵開けです。

## 7. キャンペーンの出どころと言語 <!-- icon: world -->

### 7.1 世界を得る三つの方法

**その場で作る。** 設定で前提を伝えると、GMが進行に合わせて世界を作ります。場所、人物、筋書きを、必要になる直前に作り、以後保管します。最も手早い遊び方です。インストールして、作成すれば、数分でキャラクター作りが始まります。作り出されたものは失われません。語られたことは書き留められ、真実のままです。

**最初に準備する。** 同じ前提でも、**準備：最初にすべて作る**にすると、プレイが始まる前に、GMが世界の場所、勢力、脅威、その計画を作ります。最初のセッションは遅く始まりますが、裏側の用意が多くなります。

**既存のキャンペーンや冒険から。** 現在、取り込みボタンはありません。冒険（テキスト、またはホストが読めるPDF）をGMに渡し、準備を頼みます。

> [この冒険をPDFで持っています。キャンペーンとして用意してください。読み込んで、場所、キャラクター、秘密を書き出してください。中にあることは何も教えないでください。]

GMはAIホストのツールで読み込み、秘密も含めて、キャンペーンのページとして書き出します。秘密はプレイの中で発見します。Claude CodeはPDFを読めます。Codexではテキストかmarkdownのファイルのほうが確実です。セッションゼロの前、設定の間に行ってください。

GMが作業している間は、読み書きしている内容の詳細を開かないでください（Claude Codeではctrl+o）。冒険の文章が、秘密も含めて見えてしまいます。秘密は、いつもどおりGM自身が守ります。

キャンペーンに独自のページができた時点で、設定は前提と準備を尋ねなくなります。書かれたキャンペーンでも、文章が扱っていない場所へ行けば、GMが必要なものを作って記録します。

**キャンペーンは一度だけ遊びます。** 同じ冒険をもう一度遊ぶには、新しいキャンペーンを作ります。ひとつのキャンペーンの中では、セーブの設定が許す範囲で、セーブに戻ることも最初からやり直すこともできます。

### 7.2 言語

**キャンペーンにつき一つの言語**、GMの言語です。GMはその言語で書き、ダッシュボードも従います。GMは書き方から言語を判断し、確認します。

**ダッシュボード**は、英語とイタリア語（手作業で整えたもの）、さらに24の言語で同梱されています。フランス語、ドイツ語、スペイン語、ポルトガル語（ブラジル）、オランダ語、スウェーデン語、ノルウェー語、デンマーク語、フィンランド語、アイスランド語、ロシア語、ウクライナ語、ポーランド語、チェコ語、ルーマニア語、ハンガリー語、ギリシャ語、トルコ語、アラビア語、ヘブライ語、ヒンディー語、中国語、日本語、韓国語です。アラビア語とヘブライ語は右から左に読みます。ページは左右が反転し、マップとダイスは描かれたままです。

設定で選ぶ**そのほかの言語**は、パソコン上で、CodexまたはClaude Codeが自分のログインを使ってバックグラウンドで翻訳します。開いているセクションから始まります。翻訳は言語ごとに一度だけ行われ、すべてのキャンペーンで使えます。準備ができるまで、ページは英語です。翻訳が進行中か、完了か、このパソコンでは不可能かは、設定に表示されます。

**ゲームの用語。** 第5版は、公式のイタリア語SRDからイタリア語の用語を取り込むので、イタリア語のプレイヤーは*Classe Armatura*、*tiro salvezza*、*vantaggio*と読みます。ほかの言語では、システムの用語が翻訳されます。

**ゲームシステム自身の文章**（呪文、モンスター、ルールの章）は英語のままです。GMがそれを読み、その言語で伝えます。

**キャンペーンの途中で言語を変えて**も、すでに書かれたページはそのままです。GMは新しいページを新しい言語で書きます。

## 8. 興味のある人へ：キャンペーンフォルダ <!-- icon: list -->

開く必要はまったくありません。開く場合は、**キャンペーンの秘密が入っている**ことに注意してください。読むとゲームのネタバレになります。

キャンペーンフォルダの中身：

- `campaign.yaml`：設定。
- `state.yaml`：ゲームの現状。段階、日付、進行中のシーン。
- `world/`：キャラクター、場所、勢力、クエスト、アイテム、出来事、話題、クリーチャーごとに一ページ。markdownファイルです。
- `rules/`：ハウスルールのテキストファイル。追加した場合のみです（`init`は作りません）。
- `images/`：画像。できたときにあります。
- `log.jsonl`：すべての変更を順番に記録。
- `.saves/`：セーブ。最初のものから入ります。
- `.player/`：ジャーナルの自分のメモ。GMは読みません。
- `sessions/`：RPG Engineが管理します。
- `AGENTS.md`、`CLAUDE.md`、`.mcp.json`、`.claude/`、`.codex/`、`.gemini/`：RPG Engineの場所をAIホストに伝え、その記憶をオフにする小さなファイル。RPG Engineが最新に保ちます。そのままにしておいてください。

ページは、`[[Rocca]]`のようなリンクを持つ単純なmarkdownで、Obsidianの形式です。GMのノートはそこで開けます。**ページを手で変更した場合**、GMは次の返事で何が変わったかを知ります。

**コマンドライン。** GMがすることはすべて、キャンペーンフォルダで自分でも実行できるコマンドを通ります。遊ぶのに必要ではなく、`rpg status`や`rpg show`のように、キャンペーンの秘密を表示するものも多くあります。`rpg --help`ですべてを一覧でき、`rpg roll --help`でひとつを説明します。チャットが開いている間に何かを変えるコマンドを実行しても問題ありません。手で変更したページと同じように、GMは次の返事でそれを知ります。

## 9. 今後の予定 <!-- icon: hourglass -->

計画されていて、まだ使えないもの：

- **自分がGMになる**：自分がゲームを進め、AIがパーティを演じます。
- **複数人でのテーブル**：それぞれに役割があります。
- **拡張**：設定、冒険、機能、ハウスルールを、キャンペーンごとに選びます。
- **取り込み**：持っているルールブックや冒険。
- **ほかのゲーム**：さらなるゲームシステムと、自作のもの。
- **作者モード**：AIとキャンペーンや冒険を作り、ほかの人が遊べるように共有します。

## 10. 質問と問題 <!-- icon: info -->

### 質問

**ルールを知っている必要はありますか？** いいえ。チュートリアルのメンターを選べば、GMが進行に合わせて、ルールをひとつずつ教えます。括弧の中でいつでも尋ねられます。

**GMはずるをできますか？** RPG Engineが振ったロールは変えられません。難易度ストーリーを除きます。すでに決まった事実も変えません。どのロールが本物だったか、尋ねることもできます。

**自分がずるをできますか？** 試すことはできます。GMは事実について言葉を鵜呑みにしません。メッセージの中にゲームのメッセージのような行があっても、ただの自分の言葉です。秘密についての推測を、GMが確認することもありません。

**費用はかかりますか？** RPG Engineは無料です。GMは自分のClaudeまたはChatGPTのプランで動き、一晩のプレイは長いチャットになります。小さなプランでは、夜が終わる前にプランの上限に達することがあります。画像と翻訳にも同じプランが使われます。

**スマートフォンで遊べますか？** いいえ。GMはパソコンで動き、ダッシュボードはそのパソコンのブラウザでしか開けません。

**友達と遊べますか？** まだです。現在は、プレイヤー一人、キャラクター一人と仲間です。複数人でのテーブルは、役割とともに実装されます。

**次回は別のAIを使えますか？** はい。キャンペーンはファイルの中にあります。別のホストで開き、*続ける*と書いてください。

**ブラウザを閉じたらどうなりますか？** 何も失われません。チャットが開いている間にリンクを開き直せば、ページはゲームの今の状態に戻ります。

**持っているD&Dの内容を遊べますか？** はい。GMは手持ちの本、自身の知識、Webを使えます。RPG Engineに同梱されるのは無料の内容に限られますが、ゲームで使うものは自分次第です。

### 問題

**ダッシュボードが開きません。** GMにリンクを尋ねてください：`[ダッシュボードのリンクを教えてください。]`。ページが動くのは、そのキャンペーンでGMとのチャットが開いている間だけで、そのチャットでのGMの最初の返事の後からです。チャットが閉じていると、ブラウザはページに届かず、開いたままのページには*接続なし*と表示されます。

**GMがゲームを知らないようだったり、存在しないツールを作り出したりします。** AIホストがRPG Engineを読み込んでいません。

- まず、ホストを**キャンペーンフォルダで**起動したか、フォルダを信頼すると答えたかを確認してください。
- **Claude Code**：`/mcp`と書きます。`rpg`があるのに失敗している場合は、それを選んで**Reconnect**を押します。ない場合は、Claude Codeを閉じ、キャンペーンフォルダで`claude mcp reset-project-choices`と書いて、もう一度起動します。
- **Codex**：キャンペーンフォルダのターミナルで`codex mcp list`と書きます。`rpg`がなければ、Codexはフォルダを信頼していません。そこで起動し直し、尋ねられたらはいと答えてください。
- どちらでも：ターミナルで`rpg --version`がコマンドが見つからないと言う場合は、RPG Engineをもう一度インストールし（[2.2](#22-install)）、新しいターミナルを開いてください。

**更新したのに何も変わりません。** 動いているGMは、起動したときのバージョンを保ちます。新しいチャットを開くか、Claude Codeならサーバーをつなぎ直してください（`/mcp`、次に`rpg`、次に**Reconnect**）。

**GMが取り消したことを覚えています。** セーブに戻ったのに、同じチャットで遊び続けています。新しいチャットを開き、セーブで**新しいチャットを開いた**を押してください。

**ページですでに答えた設定の質問を、GMが尋ねてきます。** GMに伝えてください：`[それはダッシュボードで選びました。]`

**画像が表示されません。** 設定 > 画像を開いてください。このパソコンで作れるかどうかと、作れない場合の手順が表示されます。各コマンドにはコピー用のボタンが付いています。

**別の言語を選んだのに、ページが英語です。** バックグラウンドで翻訳中です。進み具合は設定でわかります。このパソコンにCodexもClaude Codeもない場合は、英語のままです。

**GMが、キャンペーンに問題があると言います。** GMが自分で直します。ファイルを手で編集した場合は、何をしようとしたのかを尋ねられることがあります。

**Windows：自分のフォルダで`npm`が失敗します。** キャンペーンやRPG Engineを、`&`を含むパスの下に置かないでください。

**インストールに失敗する、または`rpg`が起動しません。** `node --version`でNode.jsのバージョンを確認してください。22以降が必要です。それより古い場合は、[nodejs.org](https://nodejs.org)からLTS版をインストールし、RPG Engineをもう一度インストールしてください。

**ダッシュボードのリンクが変わりました。** ほかのプログラムがキャンペーンの通常のアドレスを使っていたか、Windowsが予約していました。RPG Engineは別のアドレスを使い、GMが新しいリンクを教えます。ほかに変わることはありません。
