# RPG Engine：完全ガイド

**RPG Engine**では、**AIをGMにして**テーブルトークRPGを遊べます。

GMとは**チャット**で会話します。GMは物語を語り、ほかの登場人物をすべて演じ、起きたことを裁定します。

RPG Engineは裏側で動きます。**世界を記憶**し、**ダイスを振り**、**記録をつけます**。

チャットのとなりには、ブラウザーでページを開いておきます。それが**ダッシュボード**です。キャラクターのキャラクターシート、ダイス、マップ、ジャーナルが見られます。

このガイドはプレイヤー向けです。プログラミングの知識は必要ありません。

## クイックスタート <!-- icon: send -->

1. [nodejs.org](https://nodejs.org)から**Node.js**をインストールします（LTS版）。
2. GMが動くAIアプリ、**Claude Code**または**Codex**をインストールし、サインインします（[2.4](#24-connect-your-ai)）。
3. ターミナルを開き、RPG Engineをインストールします：`npm install -g rpg-engine`
4. ターミナルでキャンペーンを作ります：`rpg init "The Salt Isles"`
5. できたフォルダでClaude CodeまたはCodexを開き、*こんにちは！始めましょう。* と書きます。GMがダッシュボードのリンクを教えてくれます。チャットの横で開いてください。

以降の章で、各手順とプレイの仕方を説明します。

## 1. RPG Engineとは <!-- icon: about -->

### 誰が何をするか

| 誰が | 何をするか |
|---|---|
| **自分** | キャラクターを演じます。キャラクターの行動、言葉、挑戦を伝えます。 |
| **GM**（AI） | 物語を語り、そのほかのキャラクターを全員演じ、何が起きるかを決め、ロールを求めます。 |
| **RPG Engine** | すべてをファイルに記憶し、ダイスを振り、ヒットポイント、お金、時間、距離を数え、発見されるまで秘密を守ります。 |

AIは物語を語るのが得意ですが、覚えておくのは苦手です。放っておくと、誰にお金を貸していたか、矢が何本残っているか、橋が二回前のセッションで燃えたことまで忘れてしまいます。RPG Engineがそのすべてを保管するので、世界は夜をまたいでも変わりません。新しいチャットでも、別のAIでも同じです。

### 遊んでいる感覚

テーブルで話すように、チャットに書きます。

> そっとドアを押し開けて、中をのぞきます。

GMが見えるものを答え、選ぶ番が来たところで止まります。結果が不確かで重要なときは、GMが何がかかっているかを伝え、ロールを求めます。ダッシュボードにロールのボタンが現れます。クリックするとページ上にダイスが落ち、GMが結果を語ります。

### ほかとの違い

- **世界は残り続けます。** 語られたことは真実のままです。倒した悪役は倒れたままです。
- **ダイスは本物です。** GMはダイスを曲げられません（最も易しい難易度を選んだ場合を除きます）。
- **秘密は秘密のままです。** キャラクターが知らないことは、頼んでもGMは教えません。
- **世界は自分がいなくても動きます。** 休息や移動の間にも脅威は進み、その兆しが見えます。
- **たくさんの夜、ひとつの物語。** キャンペーンはパソコン上のフォルダです。いつでも中断して、後で続けられます。

### 今遊べるゲーム

RPG Engineは、どんなテーブルトークRPGにも使えるように作られています。現在対応しているゲームシステムは、**第5版**（無料のSystem Reference Document 5.1）だけです。ほかのゲームは今後対応します。[ゲームシステム](#5-game-systems-and-house-rules)と[今後の予定](#9-coming-later)を見てください。

## 2. はじめに <!-- icon: path -->

### 2.1 必要なもの

- Windows、macOS、Linux のいずれかのパソコン。
- **Node.js 22** 以降。[nodejs.org](https://nodejs.org) から入手できます。「LTS」版で問題ありません。RPG Engine をインストールする `npm` も一緒に入ります。
- **ターミナル**。コマンドを入力するウィンドウです。Windows ではターミナルアプリか PowerShell、macOS ではターミナルです。RPG Engine のインストール、キャンペーンの作成、Claude Code や Codex の起動に使います。
- **AIホスト**。GMが動くアプリです。**Claude Code** か **Codex** を、プランとログインも含めて用意します。[2.4](#24-connect-your-ai) を参照してください。
- AIホストが提供する**最大のモデル**。小さなモデルはだまされやすく、テストでは、本物のGMだと名乗るプレイヤーに秘密を話してしまいました。
- ダッシュボードを開くための Web ブラウザ。

AIホストのログインは、ほかにも使われます。RPG Engine はそれをパソコン上で使い、場所、クエスト、出会った相手、キャラクターの絵を描き、同梱されていない言語にダッシュボードを翻訳します。[画像](#311-pictures)と[言語](#72-languages)を参照してください。

**フォルダでターミナルを開く。** 多くの手順に「キャンペーンフォルダで」とあります。Windows では、エクスプローラーでフォルダを右クリックし、**ターミナルで開く**を選びます。macOS では、Finder でフォルダを右クリックし、**サービス > フォルダに新規ターミナル**を選びます。すでに開いているターミナルなら、`cd` とフォルダのパスを入力します。例：`cd "C:\Users\me\Games\The Salt Isles"`

### 2.2 インストール

ターミナルを開いて、次を入力します。

```text
npm install -g rpg-engine
```

これで `rpg` コマンドが使えるようになります。動作の確認は次のとおりです。

```text
rpg --version
```

`rpg` を使うのは、キャンペーンごとに作成するときの1回だけです。その後はGMと話すだけです。AIホストが同じ `rpg` コマンドで RPG Engine を自動的に起動します。

### 2.3 キャンペーンを作る

キャンペーンはフォルダです。ゲームを置いているフォルダでターミナルを開き、次を入力します。

```text
rpg init "The Salt Isles"
```

`The Salt Isles` フォルダが作られ、中に新しいキャンペーンができます。次にすることも表示されます。

```text
Created the campaign "The Salt Isles" in C:\Users\me\Games\The Salt Isles.
To play, open Claude Code or Codex in this folder and say hello: the master asks you the rest.

For the master: Still to agree with the player: ...
```

*For the master* 以降の行はGM向けで、GMがチャットで読みます。プレイヤーは何もしなくて大丈夫です。フォルダの場所は覚えておいてください。遊ぶたびにここへ戻ってきます。フォルダ名を付けずに `rpg init` を実行すると、今いるフォルダがキャンペーンになります。

`init` は、キャンペーンに必要なものをすべて作ります。設定、ワールド用のフォルダ、そして AIホストに RPG Engine を使わせ、キャンペーン外の記憶を持たせないための小さなファイルです。

今、何かを選ぶ必要はありません。残りはGMがチャットで尋ねます。ダッシュボードで選んでもかまいません。すでに決めていることがあれば、ここで指定できます。

```text
rpg init salt-isles --name "The Salt Isles" --language en --system 5e --difficulty normal --lethality dice
```

これで `salt-isles` フォルダが作られ、中にキャンペーン *The Salt Isles* ができます。フォルダ名は空白なし、キャンペーン名は自由です。

| オプション | 設定する内容 | 値 |
|---|---|---|
| `--name` | キャンペーンの名前 | 自由。省略するとフォルダ名 |
| `--language` | ゲームの言語 | `en`、`it`、`fr` などのコード |
| `--system` | ゲームシステム | `5e`（現時点ではこれだけ） |
| `--difficulty` | 世界の厳しさ | `story`、`easy`、`normal`、`hard`、`brutal` |
| `--lethality` | 戦闘で倒れることの意味 | `narrative`、`epic`、`dice` |

`rpg init --help` でも一覧を確認できます。キャンペーンを、ほかのキャンペーンのフォルダの中に作ることはできません。

GMにキャンペーンの作成を頼むことはできません。`init` の前のフォルダには、RPG Engine の場所を AIホストに伝えるものがないためです。

### 2.4 AIとつなぐ

RPG Engine は **Claude Code** と **Codex** で動きます。MCP ツールを使えるほかの AI アプリでも動くかもしれませんが、保証はしません。

**ホストのインストール。** Claude Code と Codex はターミナルで動きます。スマートフォンの Claude アプリや ChatGPT アプリではありません。どちらも専用のプランとログインが必要です。Claude Code は有料の Claude プラン、Codex は ChatGPT のログインです。インストールとサインインは各公式ページに従ってください：[Claude Code](https://code.claude.com/docs/en/setup)、[Codex](https://learn.chatgpt.com/docs/codex/cli)。この作業は1回だけで、すべてのキャンペーンで使えます。

**Claude Code。** キャンペーンフォルダでターミナルを開き、`claude` と入力します。初回は、フォルダを信頼するかどうかを尋ねられ、ゲームのツール（`mcp__rpg`）をこのフォルダで許可する旨が表示されます。**Yes, I trust this folder** を選んでください。注意：最初から選ばれているのは *No, exit* なので、そのまま Enter を押すと Claude Code が終了します。これで準備は完了です。キャンペーンがすでに、RPG Engine とそのツールを使い、記憶をオフにするよう Claude Code に伝えています。

**Codex。** キャンペーンフォルダでターミナルを開き、`codex` と入力します。フォルダを信頼するかどうかを尋ねられたら、はいと答えてください。キャンペーン自身の設定が、RPG Engine の場所を Codex に伝え、そのツールを許可し、記憶をオフにします。Codex はその設定を、信頼したフォルダでしか読みません。デスクトップアプリでは、ゲームのチャットで記憶（メモリ）がオフになっていることを確認してください。

**記憶が問題になる理由。** キャンペーンはファイルの中にあります。ホストが独自に何かを覚えていると、セーブに戻っても本当には戻れません。取り消したはずの出来事をGMが覚えたままになるからです。

### 2.5 最初のチャット

何でもいいので書いてみましょう。たとえば次のようにします。

> こんにちは！ 始めましょう。

GMがゲームの現在の状況を読み込んで答えます。チャットごとの最初の返答には、**ダッシュボードへのリンク**（`http://127.0.0.1:4750` のようなもの）が付きます。ブラウザで開き、ゲーム中はチャットの横に置いておきましょう。キャンペーンごとにリンクは変わらず、次のチャットでも同じです。ただし、ほかのプログラムがそのリンクを使っている場合は、GMが新しいリンクを知らせます。

GMのメッセージの合間に、AIホストがGMの使っているツールを短い行で表示します。その詳細は開かないでください（Claude Code では ctrl+o）。GMが書いた内容が、秘密も含めて見えてしまうことがあります。

新しいキャンペーンは、人間のGMがいるゲームと同じように、3つの段階を進みます。ダッシュボードの上部には *1 設定 · 2 セッションゼロ · 3 プレイ* と表示されます。

1. **設定**：どう遊ぶかを選びます。物語の外での作業です。
2. **セッションゼロ**：キャラクターを作ります。プレイの一部として行います。
3. **プレイ**：物語を遊びます。

### 2.6 設定：遊び方を選ぶ

GMは、まだ決まっていないことだけを、数問ずつ尋ねます。「任せる」と書くと、GMが選び、何を選んだかを伝えます。ダッシュボードを開いていれば、最初のステップの**設定**に、同じ質問がカードとして表示されます。1回に1問で、各値にはその意味が付き、標準的なものには**おすすめ**の印が付きます。そこで選べば、GMがチャットで同じことを尋ねることはありません。**スキップ**を押すと、その質問は後回しになります。言葉でしか決められないことは、チャットで決めます。新しい世界の前提、言語、そして画像です。画像については、パソコンで作れる場合にだけGMが尋ねます。そのため、ページに出る質問は、下の表の項目より少なくなります。

表は調べるためのもので、読み込む必要はありません。どの項目も、あとからチャットかダッシュボードの**設定**で変えられます。変更は、GMの次の返答から反映されます。

| 設定 | 決めること | 値 | おすすめ |
|---|---|---|---|
| **メンター**（「このゲームにどのくらい慣れていますか？」という質問） | 物語の外で、GMがルールをどのくらい教えるか | **オフ**（物語だけ。知りたいときはかっこの中で質問）、**ヒント**（大事な選択の前や、ルールを見落としそうなときに短いアドバイス）、**チュートリアル**（各ルールを初めて使うときに説明し、ロールの計算をすべて示し、戦闘のあとに短い振り返りをする） | 答えから決まる：遊んだことがない → チュートリアル、少しある → ヒント、よく知っている → オフ |
| **難易度** | 世界の厳しさ：戦闘、敵の戦術、手がかり、財宝、脅威が進む速さ | ストーリー、イージー、ノーマル、ハード、ブルータル | |
| **致死性** | 戦闘で倒れることの意味 | **ナラティブ**（キャラクターは死なない）、**エピック**（物語上の意味がある場合だけ死ぬ）、**ダイス**（ダイスが決める） | 難易度に従う：ストーリー → ナラティブ、イージー → エピック、ノーマル以上 → ダイス |
| **セーブ** | いつ戻れるか | **パーマデス**（戻れない。キャンペーンを最初からやり直すだけ）、**チェックポイント**（直近のシーン終了時に戻る。キャラクターが死んだときのみ）、**フリー**（どのセーブにも戻れ、頼めばいつでもセーブできる） | チェックポイント |
| **厳しさ** | 食料、明かり、疲労、荷物の重さ、呪文の構成要素、旅を、ルールにどこまで厳密に従うか | **スムーズ**（GMが省略する）、**ルール**（ルールどおり：松明は燃え尽き、保存食は尽きる）、**シミュレーション**（ルール以上：摩耗、腐敗、天候） | スムーズ |
| **ダイス** | キャラクターのダイスを誰が振るか | **デジタル**（RPG Engine がページ上で振る）、**物理**（自分で振り、出目を伝える） | |
| **単位** | 物語の中の距離と重さ | メートル法、ヤード・ポンド法 | |
| **仲間** | 誰が一緒に旅をするか | なし、セッションゼロで一緒に作る、GMが作る、プレイ中に出会う | |
| **画像** | 場所、クエスト、出会った相手の絵と、頼んだときのキャラクターの肖像 | なし、頼んだとき、新しい場所・クエスト・出会った相手 | 1回だけ尋ねる。パソコンで作れる場合のみ |
| **ライン** | ゲームに決して登場させないこと | 一覧、またはなし | |
| **ヴェール** | 起こってもよいが、画面の外でだけ起こること | 一覧、またはなし | |
| **言語** | ゲームとダッシュボードの言語 | 自由 | 書き方から判断し、確認する |

ゲームシステムが独自の設定を加えることもあります。第5版では**成長**が加わります。キャラクターのレベルアップの方法で、**経験点**か、物語の**マイルストーン**から選びます。

**難易度がプレイで意味すること。** ストーリー：弱くて単純な敵、わかりやすい手がかり、あらゆるものが豊富。GMが自分のロールを甘くすることもあります。イージー：単純な敵、潤沢な資源。ノーマル：分別のある敵、どの結論にも3つの手がかり、標準的な価格と財宝。ハード：賢い敵、わかりにくい手がかり、乏しい資源、速く進む脅威。ブルータル：待ち伏せ、撤退、倒れた者へのとどめを行う敵、極めて乏しい資源、最も厳しい休息。戦闘は常に、その時点のパーティに合わせた規模になります。

**ワールドが書かれていない場合**は、設定でさらに2つを尋ねます。

- **前提**：ジャンル、トーン、ワールドのいくつかの要素を、自分の言葉で。例：*「ローファンタジー。暗いが希望はある。川沿いの町、幽霊の出る浅瀬、丘陵の教団。」*
- **準備**：**その場で**（必要になる直前に、GMがワールドの各部分を作る。おすすめ）か、**最初にすべて**。

そのあと、GMがキャンペーンの名前を提案します。足りないものがなくなり、準備ができたと伝えると、ゲームはセッションゼロに進みます。

### 2.7 セッションゼロ：キャラクターを作る

セッションゼロはプレイの一部です。テーブルで遊ぶときと同じように、GMと一緒にキャラクターを作ります。

- **選択はすべて自由**です。GMに任せたいときは、そう頼みます。しっかりしたイメージ（「神殿を離れたハーフエルフの聖職者」）でも、ぼんやりしたもの（「癒やし手だけど、優しくはない人」）でも、何もなし（「お任せで。あとで直させて」）でもかまいません。
- **能力値。** ダイスを振る前に、GMが方法とセーフティネットを説明します。第5版では、標準配列、ポイント購入、4d6 の下位1個を除外、のいずれかです。決めた方法は、テーブルの取り決めとして残ります。
- **キャラクターの物語**は必須ではありません。書く場合は、GMがその言葉に沿って書き起こし、1回読み返し、登場する人や場所をワールドに結び付けます。ダッシュボードで書くこともできます（[パーティ](#party)を参照）。
- **パーソナリティ**（第5版）：特徴、理想、絆、弱点。背景の表から選ぶことも、自分で決めることもできます。
- **絵。** キャラクターができあがると、GMが絵を用意するか尋ねます。パソコン上のファイルを使うか、説明をもとにパソコンで肖像を作ります（[キャラクターの絵](#37-your-characters-story-and-picture)を参照）。

シートの数値は、選択に基づいて RPG Engine が計算します。自分で計算する必要はありません。キャラクターが完成し、確認すると、物語が始まります。

## 3. 遊び方 <!-- icon: chat -->

### 3.1 GMと話す

キャラクターの行動やセリフを、自分の言葉で書きます。短くてもかまいません。

> 宿の主人に、今夜ほかに誰が通ったか尋ねる。
>
> 「揉め事は起こしませんよ」と言い、剣から手を離す。
>
> 屋根に登って待つ。

**物語の外**のことは、角かっこの中に書きます。

> [組み付きはどう処理しますか？]
>
> [このラウンド、まだリアクションは使えますか？]
>
> [今夜はここまでにしましょう。]

GMもかっこの中で答え、その後、物語に戻ります。

**やろうとすることを伝えるのはプレイヤー、何が起こるかを伝えるのはGM**です。世界の論理や、すでに決まった事実に反することは起こりません。GMは物語の中でそれを伝え、可能なことを提案します。

**GMは、キャラクターの行動を勝手に決めません。** 話させたり、感じさせたり、選ばせたりはしません。迷ったときは尋ねます。

**GMはエンジンの話をしません。** 状況を把握しているか尋ねると、GMらしく答えます。「すべて把握しています。次回はここから続けましょう。」

**ダッシュボードの使い方をGMに尋ねられます。** GMはページを把握しています。「呪文はどこで見られますか？」「手動でロールするには？」

### 3.2 ロール

**ロールが行われるとき。** GMがロールを求めるのは、結果が不確かで、かつ重要なときだけです。それ以外は「できます」か「できます、ただし……」と答えます。ロールの前に、GMは何がかかっているか、どの判定が合うかを伝えて、そこで止まります。ロールするか、考えを変えるかを選べます。

> **GM：** 足場は狭く、濡れています。滑ると、川まで長く落ちます。敏捷力（軽業）の判定をするか、戻って階段を探すこともできます。
>
> **自分：** やってみます。

**ダッシュボードでロールする。** GMが求めると、ページの上部にバナーが現れ、判定ごとのボタンが並びます。たとえば *軽業 +4 · 有利* です。押すと、ページ上にダイスが落ち、結果がGMに伝わります。ほかにもできることがあります。

- シートの該当する行をクリックする。行が金色に光ります。
- ダイストレイから適切なダイスを振る。
- 別のことをしたいときは、バナーに自分の言葉を書く。

**手動でロールする。** ダイスを自分で選びたいときは、バナーの隅にある**手動**をオンにします（**設定**からもできます）。判定のボタンが消え、バナーには、GMが言うような形でロールの内容が表示されます：*軽業を、シートかダイスで自分でロールしてください。* 光っているシートの行をクリックするか、ダイストレイから適切なダイスを振ります。RPG Engine がそれを振って、ボーナスを足し、結果をGMに伝えます。シートでもダイストレイでもできない判定（1の目を振り直すダメージなど）には、ボタンが残ります。**手動**は、オフにするまで、このブラウザでオンのままです。

**ゲーム全体で物理ダイスを使う。** **ダイス**の設定を物理にすると、GMは言葉でロールを求め、振った出目を書いて伝えます。

> [14が出ました。]

RPG Engine が修正値を加え、そのダイスで出ない出目は受け付けません。

**フリーロール。** シートの数値をクリックするか、ダイストレイを開くと、遊びでロールできます。フリーロールは何にも数えられず、記録もされず、GMにも見えません。フリーロールで出た20が、あとで本物になることはありません。

**GMのロール。** 敵やほかの相手のロールも、GMが RPG Engine で振ります。ほとんどのロールは、ロール欄に表示されます。結果を見せてはいけないときは、GMが秘密でロールします。いつでも尋ねられます。

> [さっきのロールは本物ですか？]

表示されたロールなら、GMが数値と理由を答えます。秘密のロールなら、質問より前にロールされたことを証明するフィンガープリントを示します。

**チャットでのロール**は、結果を決めた直後に、かっこで表示されます：*[説得 14 + 3 = 17]*。そのあと、物語が結果を語ります。

### 3.3 シーンと戦闘

GMは、物語を**シーン**で進めます。戦闘、会話、探索、旅、休息、チャレンジ（追跡、レース、パズル）などです。プレイヤーが管理する必要はありません。シーンは、RPG Engine が物語の章を管理するための仕組みです。シーンが終わるたびに、ゲームは自動的にセーブされ、そのシーンはジャーナルの物語に入ります。

**戦闘中**、GMは、自分以外のターンをすべて、ロールも含めて続けて語り、**決断できるところで止まります**。自分のターン、リアクション、選択です。自分のターンには、やることを伝えます。

> 扉のそばにいる相手に聖なる炎を唱える。

ダッシュボードの**戦闘**には、ターンの順番、今は誰のターンか、パーティのヒットポイント、敵の負傷の様子が表示されます（無傷、負傷、重傷、戦闘不能。数値ではなく言葉で表します）。キャラクターが倒れると、死亡セーブがページに大きく表示されます。

**戦闘の勝敗がすでに決まっているとき**は、GMが残りを1つのメッセージにまとめて語ることを提案する場合があります。

### 3.4 時間、旅、動き続ける世界

**時間。** 物語の中では、あらゆる行動に時間がかかり、RPG Engine が日付を管理します：3日目、早朝。GMは、世界の流儀で時間を語ります。夜明け、三の鐘、日暮れ。セッションの合間に時間は進まず、止めたところから再開します。

**休息。** 休むと伝えれば、GMが、ヒットポイントや呪文スロットなど、休息で回復するものを反映します。

> 野営して、ロングレストを取る。

**旅。** 行きたい場所を伝えます。

> 北の道を通ってロッカへ向かう。

RPG Engine が、歩く速さに合わせて道のり、距離、日数を計算し、そこへ移動させます。旅は、道中で予定された出来事が起こったとき、1日の移動の終わり、到着時に止まります。出発前に、場所までの距離を尋ねることもできます。

> [ロッカまでどのくらい遠くて、徒歩だとどのくらいかかりますか？]

**世界はプレイヤーなしでも動きます。** 悪役には、期限のある計画とクロックがあります。新しい日になるたびに、GMは時間が進めた脅威を動かし、その兆しが見えます。噂、痕跡、町の変化などです。クロックそのものは見えません。見えるのは、それが残したものだけです。

**お金**はゲーム内の硬貨で数えます。支払い、売却、報酬の受け取りでは、RPG Engine がお釣りを計算します。

### 3.5 マップ

**ワールドマップ**（ダッシュボード：**ワールド**）には、キャラクターが知っている場所だけが、その間の道、歩いてきた跡とともに表示されます。それ以外は霧に覆われています。場所をクリックすると、わかっていることと、そこまでの距離が見られます。

**場所のマップ**（ダッシュボード：**シーン**、戦闘中は**戦闘**）は、今いる場所のマップをGMが描いたときに表示されます。壁、扉、地面、そして誰がどこにいるかがトークンで示されます。戦闘中の自分のターンには、届かないマスにヴェールがかかるので、動ける場所が一目でわかります。GMがキャラクターの移動先を尋ねると、ページがマップを開くので、マスをタッチするか、*E4* のように書いて伝えます。

### 3.6 クエスト、ジャーナル、メモ

**クエスト。** キャラクターが依頼を引き受けると、**ジャーナル**にクエストとして記録されます。誰が、どこで、いつまでに依頼したか、目標のリスト、進み具合（残り時間のある期限、クロック、カウント）が載ります。星を付けるとそのクエストを追いかけられ、次の目標と一緒に、シーンの上部に小さく表示されます。クエストが終わるのは、物語が終わらせたときだけです。自動で終わることはありません。

**ストーリー。** ジャーナルのストーリータブは、キャンペーンを年表にしたものです。シーンごとに1章で、場所、日付、短い要約が付き、新しいものが先頭に来ます。

**メモ。** ジャーナルのメモタブには、自分用のメモを書けます。推理、名前、計画などです。メモはパソコンに残り、**共有**しない限りGMは読みません。共有したメモは、GMの次の返答に、プレイヤーの考えとして届きます。事実としては扱われません。推理は、書いただけでは真実になりません。ある内容を止める、避けるよう求めるメモは、テーブルで口頭で伝えたものとして扱われます。

### 3.7 キャラクターの物語と絵

キャラクターのシートの**説明**カードには、キャラクターの物語を書く欄があります。送信すると、了承を伝えたあとで、GMがそれを自分の言葉でキャラクターに書き込みます。

キャラクターの絵は、画像ファイルを、パソコン上の場所を添えてチャットでGMに渡します（PNG、JPEG、WebP、SVG、5 MBまで）。

> [キャラクターの肖像です：C:\Users\me\Pictures\mira.png]

GMがそれをキャンペーンにコピーし、ダッシュボードのキャラクターのトークンに表示されます。変えたいときは、いつでも同じ方法で変えられます。

絵を作ってもらうこともできます（パソコンで画像を作れる場合。[画像](#311-pictures)を参照）。キャラクターをGMに説明するか、GMに説明してもらいます。

> [肖像を作ってください：三つ編みの白髪、あごに傷、疲れた目。]

肖像には、ゲーム内のキャラクターの姿がそのまま描かれます。この世界の種族としての姿で、丘ドワーフなら丘ドワーフとして、説明した外見で描かれます。1分ほどで、キャラクターのトークンに表示されます。仲間も同じ方法で肖像を用意できます。

### 3.8 セーブと巻き戻し

RPG Engine は、**シーンが終わるたびに**、キャンペーン全体を自動でセーブします。そのセーブで何ができるかは、**セーブ**の設定で決まります。

| セーブ | 好きなときにセーブ | 戻る |
|---|---|---|
| **パーマデス** | できない | 戻れない。キャンペーンを最初からやり直すだけ |
| **チェックポイント** | できない | 直近のセーブへ。キャラクターが死んだときのみ |
| **フリー** | できる | どのセーブへも、いつでも |

どのモードでも**やり直し**はできます。同じキャラクターでプレイの最初から、または新しいキャラクターでセッションゼロからです。

これらはすべて、チャット（「[決闘の前に戻りましょう。]」）か、ダッシュボードの**セーブ**で行えます。

**戻ったあとは、新しいチャットを開いてください。** それまで遊んでいたチャットは、取り消したことを覚えています。GMとの新しいチャットを開き（Claude Code では `/clear`、Codex では `/new`）、*続ける* と書き、セーブの**新しいチャットを開いた**を押すか、新しいチャットでGMに伝えます。古いチャットを再開してはいけません。確認するまで、GMは先へ進みません。

### 3.9 セッション：やめるときと再開するとき

**セッションはいつでも終わらせられます。**

> [今夜はここまでにしましょう。]

「セーブして終了」という操作はありません。すべてはすでにファイルに保存されています。

チャットを**閉じる**には、Claude Code では `/exit`、Codex では `/quit` と入力します。ダッシュボードは、次のチャットまで静かになります。

**再開する**には、キャンペーンフォルダ（`init` が表示したフォルダ）でターミナルを開き、そこでホストを起動して、*続ける* と書きます。GMはゲームの現在の状況を読み込み、短いあらすじを語り、何かが起こる場面から始めます。新しいチャットでも、失われるものはありません。キャンペーンはチャットではなく、ファイルの中にあるからです。

GMは、終わりに定型の質問をしません。うまく動かなかったことに気づいたときだけ、短く尋ねます。

### 3.10 GMの表情

ダッシュボードの上部には、GMのアバターである小さなロボットがいます。表情は物語のトーンに合わせて変わります。危険が迫れば心配そうに、大胆な案には喜び、どんでん返しには驚きます。出目20や出目1には、一瞬反応します。まだ知らないことは決して表に出さず、罠が作動する前ににやりとすることはありません。パーティのトークンにも、それぞれの気分が表れます。チャットが閉じられると、ロボットは眠ります。

### 3.11 画像

RPG Engine は、たどり着いた場所、引き受けたクエスト、出会ったキャラクターや生き物ごとに、見たとおりの絵を作らせることができます。**画像**の設定に従い、頼んだときにはキャラクターの肖像も作ります。パソコンにすでにあるものを使います。

- **Codex**（ChatGPT のログイン）：描いた絵。
- それ以外は **Claude Code**（Claude のログイン）：ドローイング。

絵の作成には、こちらではなく自分のプランが使われます。パソコンで画像を作れるかどうかと、作れない場合の設定手順は、**設定**に表示されます。画像がない場合、ページには場所の種類ごとのマークが表示されます。どの場所やキャラクターにも、自分で用意した絵をGMに渡すことができます。

### 3.12 安全：ライン、ヴェール、ストップ

- **ライン**：ゲームに決して登場させないこと。
- **ヴェール**：起こってもよいが、画面の外でだけ起こること。
- **ストップ**：いつでも、理由を説明せずに、ある内容を止められます。物語の外で書きます。

> [stop]

GMはすぐにその内容をやめ、今後のすべてのセッションのために、ラインに加えます。ラインとヴェールは、**設定**で確認も変更もできます。

### 3.13 考えを変える

どの設定も、キャンペーンの途中で変えられます。チャット（「[もっと難しくしましょう。]」）でも、**設定**でもかまいません。変更は、GMの次の返答で伝わります。GMが本のルールによらず下した裁定は**先例**となって記録されるので、同じ質問には次も同じ答えが返ります。

## 4. ダッシュボードの各セクション <!-- icon: party -->

ダッシュボードは、自分のパソコン上のページです。リンクは、チャットのはじめごとにGMが教えます。ゲームにライブで追従し、GMが何かを変えると、ページも変わります。

開けるのは、遊んでいるパソコンのブラウザだけです。同じWi-Fiでも、スマートフォンやタブレットでは開けません。ページは狭いウィンドウにも合わせられます。その場合、セクションは下部のバーに、アイコンはメニューに移ります。

ページが生きているのはチャットの間です。チャットを閉じると、開いたままのページには*接続なし*と、最後の状態のシートが表示され、GMのロボットは眠ります。キャンペーンでまたチャットを開き、GMが答えれば、ページは自動で戻ります。

### 上部

- **GMのアバター**と、その表情。
- キャンペーンの名前、ゲームシステム、**ゲーム内時間**、ゲームが**接続中**かどうか（チャットがつながっているか）。
- セクション：**パーティ**、**シーン**、**戦闘**（戦闘中のみ）、**ジャーナル**、**ワールド**。行の末尾にアイコンで：**セーブ**、**ヘルプ**、**設定**、**概要**。
- ライトテーマとダークテーマ（右上）。

GMが何かを尋ねているときは、どのセクションにいても、そのバナーがページの上部に残ります。

### パーティ

キャラクターのシートと、仲間のシートです。シートの各部分はカードで、開閉できます。

- **数字をクリック**すると、遊びでロールできます。数字にポインタを合わせると、その内訳が見えます（「+5：判断力 +3、習熟 +2」）。
- **ヒットポイント、スロット、使用回数**は、バーと点で表示されます。
- **状態と効果**は、持続時間とともに表示されます。
- **説明**には、キャラクターの文章と、キャラクターの物語をGMに送るボックスがあります。
- ヒットポイントが0になると、名前の下に**死亡セーヴィングスロー**が大きく表示されます。
- シートの横（狭い画面では下）には、**ロール**が新しい順に並びます。自分のロールと、見てよいGMのロールです。**クリア**でリストを空にし、**元に戻す**で復活します。フリーロールは破線で薄く表示されます。

狼のように能力値ブロックを持つ仲間は、完全なシートの代わりに能力値ブロックが表示されます。

### シーン

パーティのいる場所です。場所の画像と名前、周囲の場所、場所にマップがあればそのマップ、そこにいる者たち、そして今起きていることを含む進行中のシーンが表示されます。追跡中のクエストは上部にあります。

### 戦闘

戦闘中だけ表示されます。上部には、ラウンド、行動中の者、次の者。その下には、ターンの順番、各戦闘員の状態（パーティは数字、敵は言葉）、キャラクターの手元にあるもの（アーマークラス、ヒットポイント、攻撃）、場所のマップ（行動中の者に輪が付きます）が表示されます。自分のターンには、どこにいても、戦闘のリンクが金色に脈打ちます。

### ジャーナル

三つのタブがあります。

- **クエスト**：進行中、完了、失敗のクエストが、目標、タイマーで示される期限、クロックとともにカードで表示されます。星でクエストを追跡します。
- **ストーリー**：キャンペーンの章がシーンごとに並び、新しいものが先頭です。
- **メモ**：自分のメモ。共有するまで非公開です。

### ワールド

キャラクターが知っている形のワールドマップで、そのほかは霧に覆われています。ドラッグで移動し、ホイールかピンチで拡大縮小します。場所をクリックするとカードが開きます。場所のリストが近い順に横に並びます。マップが複数ある場合（都市、大陸、別の次元）は、タブで切り替えます。

### ダイストレイ

ダイスのボタンでトレイを開きます。ダイスと修正値を選んで振ります。同じ種類のダイスが二つ以上あるときは、どれを数えるか選べます。**すべて**、**高い方**（最も高いものだけ）、**低い方**（最も低いものだけ）です。選んだダイスは、**クリア**を押すまで残るので、毎ラウンド同じダメージロールがワンクリックです。GMがロールを求めている間は、どのダイスが当てはまるかをトレイが示します。

### セーブ

セーブが新しい順に並び、それぞれに場所、ゲーム内の日付、作成時刻が付きます。**今すぐセーブ**（フリーのセーブ時）、**ここに戻る**、そして赤い**最初からやり直す**（二段階）があります。[セーブと戻ること](#38-saves-and-going-back)を見てください。

### 設定

設定はグループに分かれています。ゲーム、ゲームの学習（メンターと、すでに説明されたルール）、ダイスと単位、制限（ラインとヴェール）、画像、言語です。値をクリックして選ぶと、その下に意味が表示されます。その後にページ自身の設定があり、このブラウザにだけ保存されます。テーマ、ダイスの音、**ダイスセット**（樹脂、金属、木、石）、角の丸みと鋭さ、手で振ることです。

ハウスルールや先例など、GM自身の設定はここにはありません。チャットの中にあります。

### ヘルプと概要

**ヘルプ**：このガイド。**概要**：RPG Engineとは何か、リンク、ライセンス、ゲームシステムのクレジット。

### プレイ前：設定とセッションゼロ

新しいキャンペーンが最初の段階の**設定**にある間は、ページ全体が質問を表示します。一度にひとつで、各値の意味とおすすめが付きます。**自分で決める**を押すと質問をGMに任せます。ただし、ラインとヴェールは常に自分のものです。**スキップ**を押すと後回しになります。最後に**準備完了**を押します。

### ページからのメッセージ

ページが上に通知を重ねて表示することがあります。キャンペーンのファイルの問題（GMが直します）、ゲームが不在（チャットが閉じています）、ページが翻訳中、などです。

## 5. ゲームシステムとハウスルール <!-- icon: dice -->

### 5.1 ゲームシステムとは

ゲームシステムとは、1つのゲームのデータです。キャラクターシート、数値、クリーチャー、アイテム、呪文、ルールの文章がそろっています。1つのキャンペーンでは、1つのシステムを遊びます。

RPG Engine は、デジタルのキャラクターシートと同じように、キャラクターシートの計算と、消費して戻るもの（ヒットポイントや呪文スロットなど）の管理を行います。特技や呪文がどう働くかは、テーブルで遊ぶときと同じように、GMがルールを読んで判断します。

### 5.2 第5版を同梱

RPG Engine には、システム・リファレンス・ドキュメント 5.1（2014年版のルール。クリエイティブ・コモンズで無料公開）にもとづく **5e** が入っています。内容は次のとおりです。

- SRDの種族、クラス、サブクラス、背景、特技
- SRDの319の呪文、武器、防具、装備品、魔法のアイテム、モンスター
- ルールの章（GMは正確な文章を引いて調べます）
- 計算済みの完全なキャラクターシート：能力値の修正値、セーブ、技能、Classe Armatura、攻撃、呪文セーブ難易度、スロット、ヒットダイス、レベルごとの特徴、経験点とレベルアップ
- 戻るべきものを戻す休息、ルール文つきの状態異常、精神集中のリマインダー

**SRDにない内容。** 手持ちの書籍のクラスやモンスターなど、SRDにない内容を第5版で遊ぶこともできます。GMはゲームを知っていて、所有するルールブックを読み、ウェブも検索できます。必要なものはキャンペーンのページとして書き、RPG Engine はそれも同じように扱います。同梱できる内容はライセンスで限られますが、GMが知っていることに限りはありません。

RPG Engine に同梱するのは、オリジナルまたはオープンライセンスの内容だけです。第5版では、CC BY 4.0 のSRD 5.1です。それ以外の内容がゲームに登場する場合は、AI か本人が、パソコン上のキャンペーンのページとして書いたものです。RPG Engine の一部ではなく、配布もしていません。

RPG Engine は第5版と互換性があります。

### 5.3 ハウスルールと独自の追加

ファイルを触る必要はありません。GMに頼むだけです。

> [ハウスルール：攻撃の出目1で武器を落とす。]
>
> [ブラッドハンターで遊びたい。本はあるので、クラスの特徴はこれです。]
>
> [このキャンペーンでは、ショートレストは10分にする。]

GMは、次のいずれかの方法でキャンペーンに記録します。

- **テーブルの取り決め**：言葉で決めたもの。上の武器を落とすルールやショートレストなどです。GMはキャンペーンの設定と一緒に保管し、以後はそれに従って進めます。GMが本に頼らずに下した裁定も、**先例**として同じように保管します。
- **新しいページ**：クラス、種族、アイテムなどです。新しいクラスはシステムのクラスと同じように働き、レベル、ヒットダイス、特徴が数えられます。新しい種族は既存の種族をもとにできます（「エルフと同じで、さらに…」）。名前つきの剣は、ロングソードをもとにできます。
- **キャラクターシートの新しい数値**：項目、表、計算式、休息で戻るカウンターなどです。たとえば、ショートレストで戻るバトルマスターの上級ダイスがあります。ハウスルールで、システムの計算式を置き換えることもできます。

すでに書き出したハウスルールがあれば、テキストファイルとしてキャンペーンの `rules` フォルダに置くこともできます（[キャンペーンフォルダ](#8-for-the-curious-the-campaign-folder)を参照）。GMは、同じ名前の本のルールより先に、そのファイルを読みます。

### 5.4 独自のゲームシステムの追加と取り込み

現在、RPG Engine が遊べるのは第5版だけです。ほかのゲームシステムも追加される予定で、独自のシステムを追加する方法や、手持ちのゲームをルールブックからシステムに変える方法も用意される予定です。[今後の予定](#9-coming-later)を参照してください。

## 6. 拡張 <!-- icon: plus -->

**拡張はまだ使えません。** 拡張は、ゲームシステムの上でキャンペーンに何かを加えます。世界、冒険、天候やタロットのような機能、共有するハウスルールなどです。どれを使うかは、キャンペーンごとに選べるようになります。第5版向けに最初に予定されているのは、天候と鍵開けです。

## 7. キャンペーンの出どころと言語 <!-- icon: world -->

### 7.1 世界を得る三つの方法

**その場で作る。** 設定で前提を伝えると、GMが進行に合わせて世界を作ります。場所、人物、筋書きを、必要になる直前に作り、以後保管します。最も手早い遊び方です。インストールして、作成すれば、数分でキャラクター作りが始まります。作り出されたものは失われません。語られたことは書き留められ、真実のままです。

**最初に準備する。** 同じ前提でも、**準備：最初にすべて作る**にすると、プレイが始まる前に、GMが世界の場所、勢力、脅威、その計画を作ります。最初のセッションは遅く始まりますが、裏側の用意が多くなります。

**既存のキャンペーンや冒険から。** 現在、取り込みボタンはありません。冒険（テキスト、またはホストが読めるPDF）をGMに渡し、準備を頼みます。

> [この冒険をPDFで持っています。キャンペーンとして用意してください。読み込んで、場所、キャラクター、秘密を書き出してください。中にあることは何も教えないでください。]

GMはAIホストのツールで読み込み、秘密も含めて、キャンペーンのページとして書き出します。秘密はプレイの中で発見します。Claude CodeはPDFを読めます。Codexではテキストかmarkdownのファイルのほうが確実です。セッションゼロの前、設定の間に行ってください。

GMが作業している間は、読み書きしている内容の詳細を開かないでください（Claude Codeではctrl+o）。冒険の文章が、秘密も含めて見えてしまいます。秘密は、いつもどおりGM自身が守ります。

キャンペーンに独自のページができた時点で、設定は前提と準備を尋ねなくなります。書かれたキャンペーンでも、文章が扱っていない場所へ行けば、GMが必要なものを作って記録します。

**キャンペーンは一度だけ遊びます。** 同じ冒険をもう一度遊ぶには、新しいキャンペーンを作ります。ひとつのキャンペーンの中では、セーブの設定が許す範囲で、セーブに戻ることも最初からやり直すこともできます。

### 7.2 言語

**キャンペーンにつき一つの言語**、GMの言語です。GMはその言語で書き、ダッシュボードも従います。GMは書き方から言語を判断し、確認します。

**ダッシュボード**は、英語とイタリア語（手作業で整えたもの）、さらに24の言語で同梱されています。フランス語、ドイツ語、スペイン語、ポルトガル語（ブラジル）、オランダ語、スウェーデン語、ノルウェー語、デンマーク語、フィンランド語、アイスランド語、ロシア語、ウクライナ語、ポーランド語、チェコ語、ルーマニア語、ハンガリー語、ギリシャ語、トルコ語、アラビア語、ヘブライ語、ヒンディー語、中国語、日本語、韓国語です。アラビア語とヘブライ語は右から左に読みます。ページは左右が反転し、マップとダイスは描かれたままです。

設定で選ぶ**そのほかの言語**は、パソコン上で、CodexまたはClaude Codeが自分のログインを使ってバックグラウンドで翻訳します。開いているセクションから始まります。翻訳は言語ごとに一度だけ行われ、すべてのキャンペーンで使えます。準備ができるまで、ページは英語です。翻訳が進行中か、完了か、このパソコンでは不可能かは、設定に表示されます。

**ゲームの用語。** 第5版は、公式のイタリア語SRDからイタリア語の用語を取り込むので、イタリア語のプレイヤーは*Classe Armatura*、*tiro salvezza*、*vantaggio*と読みます。ほかの言語では、システムの用語が翻訳されます。

**ゲームシステム自身の文章**（呪文、モンスター、ルールの章）は英語のままです。GMがそれを読み、その言語で伝えます。

**キャンペーンの途中で言語を変えて**も、すでに書かれたページはそのままです。GMは新しいページを新しい言語で書きます。

## 8. 興味のある人へ：キャンペーンフォルダ <!-- icon: list -->

開く必要はまったくありません。開く場合は、**キャンペーンの秘密が入っている**ことに注意してください。読むとゲームのネタバレになります。

キャンペーンフォルダの中身：

- `campaign.yaml`：設定。
- `state.yaml`：ゲームの現状。段階、日付、進行中のシーン。
- `world/`：キャラクター、場所、勢力、クエスト、アイテム、出来事、話題、クリーチャーごとに一ページ。markdownファイルです。
- `rules/`：ハウスルールのテキストファイル。追加した場合のみです（`init`は作りません）。
- `images/`：画像。できたときにあります。
- `log.jsonl`：すべての変更を順番に記録。
- `.saves/`：セーブ。最初のものから入ります。
- `.player/`：ジャーナルの自分のメモ。GMは読みません。
- `sessions/`：RPG Engineが管理します。
- `AGENTS.md`、`CLAUDE.md`、`.mcp.json`、`.claude/`、`.codex/`、`.gemini/`：RPG Engineの場所をAIホストに伝え、その記憶をオフにする小さなファイル。RPG Engineが最新に保ちます。そのままにしておいてください。

ページは、`[[Rocca]]`のようなリンクを持つ単純なmarkdownで、Obsidianの形式です。GMのノートはそこで開けます。**ページを手で変更した場合**、GMは次の返事で何が変わったかを知ります。

**コマンドライン。** GMがすることはすべて、キャンペーンフォルダで自分でも実行できるコマンドを通ります。遊ぶのに必要ではなく、`rpg status`や`rpg show`のように、キャンペーンの秘密を表示するものも多くあります。`rpg --help`ですべてを一覧でき、`rpg roll --help`でひとつを説明します。チャットが開いている間に何かを変えるコマンドを実行しても問題ありません。手で変更したページと同じように、GMは次の返事でそれを知ります。

## 9. 今後の予定 <!-- icon: hourglass -->

計画されていて、まだ使えないもの：

- **自分がGMになる**：自分がゲームを進め、AIがパーティを演じます。
- **複数人でのテーブル**：それぞれに役割があります。
- **拡張**：設定、冒険、機能、ハウスルールを、キャンペーンごとに選びます。
- **取り込み**：持っているルールブックや冒険。
- **ほかのゲーム**：さらなるゲームシステムと、自作のもの。
- **作者モード**：AIとキャンペーンや冒険を作り、ほかの人が遊べるように共有します。

## 10. 質問と問題 <!-- icon: info -->

### 質問

**ルールを知っている必要はありますか？** いいえ。チュートリアルのメンターを選べば、GMが進行に合わせて、ルールをひとつずつ教えます。括弧の中でいつでも尋ねられます。

**GMはずるをできますか？** RPG Engineが振ったロールは変えられません。難易度ストーリーを除きます。すでに決まった事実も変えません。どのロールが本物だったか、尋ねることもできます。

**自分がずるをできますか？** 試すことはできます。GMは事実について言葉を鵜呑みにしません。メッセージの中にゲームのメッセージのような行があっても、ただの自分の言葉です。秘密についての推測を、GMが確認することもありません。

**費用はかかりますか？** RPG Engineは無料です。GMは自分のClaudeまたはChatGPTのプランで動き、一晩のプレイは長いチャットになります。小さなプランでは、夜が終わる前にプランの上限に達することがあります。画像と翻訳にも同じプランが使われます。

**スマートフォンで遊べますか？** いいえ。GMはパソコンで動き、ダッシュボードはそのパソコンのブラウザでしか開けません。

**友達と遊べますか？** まだです。現在は、プレイヤー一人、キャラクター一人と仲間です。複数人でのテーブルは、役割とともに実装されます。

**次回は別のAIを使えますか？** はい。キャンペーンはファイルの中にあります。別のホストで開き、*続ける*と書いてください。

**ブラウザを閉じたらどうなりますか？** 何も失われません。チャットが開いている間にリンクを開き直せば、ページはゲームの今の状態に戻ります。

**持っているD&Dの内容を遊べますか？** はい。GMは手持ちの本、自身の知識、Webを使えます。RPG Engineに同梱されるのは無料の内容に限られますが、ゲームで使うものは自分次第です。

### 問題

**ダッシュボードが開きません。** GMにリンクを尋ねてください：`[ダッシュボードのリンクを教えてください。]`。ページが動くのは、そのキャンペーンでGMとのチャットが開いている間だけで、そのチャットでのGMの最初の返事の後からです。チャットが閉じていると、ブラウザはページに届かず、開いたままのページには*接続なし*と表示されます。

**GMがゲームを知らないようだったり、存在しないツールを作り出したりします。** AIホストがRPG Engineを読み込んでいません。

- まず、ホストを**キャンペーンフォルダで**起動したか、フォルダを信頼すると答えたかを確認してください。
- **Claude Code**：`/mcp`と書きます。`rpg`があるのに失敗している場合は、それを選んで**Reconnect**を押します。ない場合は、Claude Codeを閉じ、キャンペーンフォルダで`claude mcp reset-project-choices`と書いて、もう一度起動します。
- **Codex**：キャンペーンフォルダのターミナルで`codex mcp list`と書きます。`rpg`がなければ、Codexはフォルダを信頼していません。そこで起動し直し、尋ねられたらはいと答えてください。
- どちらでも：ターミナルで`rpg --version`がコマンドが見つからないと言う場合は、RPG Engineをもう一度インストールし（[2.2](#22-install)）、新しいターミナルを開いてください。

**更新したのに何も変わりません。** 動いているGMは、起動したときのバージョンを保ちます。新しいチャットを開くか、Claude Codeならサーバーをつなぎ直してください（`/mcp`、次に`rpg`、次に**Reconnect**）。

**GMが取り消したことを覚えています。** セーブに戻ったのに、同じチャットで遊び続けています。新しいチャットを開き、セーブで**新しいチャットを開いた**を押してください。

**ページですでに答えた設定の質問を、GMが尋ねてきます。** GMに伝えてください：`[それはダッシュボードで選びました。]`

**画像が表示されません。** 設定 > 画像を開いてください。このパソコンで作れるかどうかと、作れない場合の手順が表示されます。各コマンドにはコピー用のボタンが付いています。

**別の言語を選んだのに、ページが英語です。** バックグラウンドで翻訳中です。進み具合は設定でわかります。このパソコンにCodexもClaude Codeもない場合は、英語のままです。

**GMが、キャンペーンに問題があると言います。** GMが自分で直します。ファイルを手で編集した場合は、何をしようとしたのかを尋ねられることがあります。

**Windows：自分のフォルダで`npm`が失敗します。** キャンペーンやRPG Engineを、`&`を含むパスの下に置かないでください。

**インストールに失敗する、または`rpg`が起動しません。** `node --version`でNode.jsのバージョンを確認してください。22以降が必要です。それより古い場合は、[nodejs.org](https://nodejs.org)からLTS版をインストールし、RPG Engineをもう一度インストールしてください。

**ダッシュボードのリンクが変わりました。** ほかのプログラムがキャンペーンの通常のアドレスを使っていたか、Windowsが予約していました。RPG Engineは別のアドレスを使い、GMが新しいリンクを教えます。ほかに変わることはありません。
