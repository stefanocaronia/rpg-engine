# RPG Engine：完全ガイド

**RPG Engine**では、**AIをGM**にして、テーブルトークRPGを遊べます。GMとは**チャット**で会話します。RPG Engineは裏側で動き、**世界を記憶し**、**ダイスを振り**、**数値を管理**します。チャットの横にはブラウザーのページ、**ダッシュボード**を開いておきます。キャラクターシート、ダイス、マップ、ジャーナルが並びます。

このガイドはプレイヤー向けです。プログラミングの知識は必要ありません。

## クイックスタート <!-- icon: send -->

1. [nodejs.org](https://nodejs.org)から**Node.js**をインストールします（LTS版）。
2. **AIエージェント**をインストールして、サインインします。AIエージェントとは、GMが動くプログラムです。たとえばClaude CodeやCodexです（[2.4](#24-connect-your-ai)）。
3. ターミナルで、RPG Engineをインストールします：`npm install -g rpg-engine`。
4. キャンペーンを作ります：`rpg init "The Salt Isles"`。
5. 作られたフォルダーに入り（`cd "The Salt Isles"`）、そこでエージェントを起動します。Claude Codeなら`claude`、Codexなら`codex`です。フォルダーを信頼するか聞かれたら、はいと答えます（[2.4](#24-connect-your-ai)）。そして*こんにちは！始めましょう。*と書きます。GMがダッシュボードへのリンクを伝えます。

## 1. RPG Engineとは <!-- icon: about -->

| 誰が | 何をするか |
|---|---|
| **自分** | キャラクターを演じます。何をして、何を言い、何を試みるかを決めます。 |
| **GM**（AI） | 物語を語り、ほかの全員を演じ、何が起こるかを決め、ロールを求めます。 |
| **RPG Engine** | 世界をファイルに保ち、ダイスを振り、ヒットポイント、お金、時間、距離を数え、発見されるまで秘密を守ります。 |

世界は、夜が変わっても、新しいチャットでも、別のAIでも変わりません。

- **語られたことは真実のままです。**倒された悪役は倒されたままです。
- **ダイスは本物です。**GMはダイスを曲げられません。ただし、最も易しい難易度を選んだ場合は例外です。
- **秘密は秘密のままです。**キャラクターが知らないことを、GMが伝えることはありません。
- **世界は動きます。**休息や旅のあいだにも脅威は進み、その兆しが見えます。
- **キャンペーンはコンピューター上のフォルダーです。**いつでも中断して、あとで続きを遊べます。

現在、RPG Engineが遊べるゲームシステムは、無料のSystem Reference Document 5.1にもとづく**第5版**です。ほかのシステムも今後追加されます（[今後の予定](#9-coming-later)）。

## 2. はじめに <!-- icon: path -->

### 2.1 必要なもの

- Windows、macOS、Linuxのいずれかが動くパソコンと、ウェブブラウザ。
- **Node.js 22** 以降。[nodejs.org](https://nodejs.org) から入手します。Node.jsには `npm` が付いていて、RPG Engineのインストールに使います。
- **ターミナル**：Windowsではターミナル（Terminal）またはPowerShell、macOSではターミナル。フォルダでターミナルを開くには、Windowsではフォルダを右クリックして **ターミナルで開く** を選びます。macOSでは **サービス > フォルダに新規ターミナル** を選びます。
- GMになる **AIエージェント**（[2.4](#24-connect-your-ai)）。使うのは、そのAIエージェントが提供する **最大のモデル** です。小さなモデルは、口車に乗せられて秘密を明かしたり、ルールを曲げたりしやすくなります。

### 2.2 インストール

```text
npm install -g rpg-engine
```

`rpg --version` で、インストールできたか確認できます。`rpg` を使うのは、キャンペーンを作るときの一度だけです。その後は、AIエージェントが自動でRPG Engineを起動します。

### 2.3 キャンペーンを作る

ゲームを置いておくフォルダでターミナルを開きます（開き方は [2.1](#21-what-you-need)）。

```text
rpg init "The Salt Isles"
```

これで `The Salt Isles` というフォルダができ、新しいキャンペーンが入ります。`cd "The Salt Isles"` でフォルダに移動します。場所は覚えておいてください。遊ぶたびに、ここへ戻ってきます。そのほかの設定は、あとでチャットやダッシュボードで決められます。今すぐ選びたいときは、`rpg init --help` でオプションを確認できます。たとえば `--language it` や `--difficulty hard` があります。

キャンペーンの作成をGMに任せることはできません。`init` の前は、RPG Engineがどこにあるか、AIエージェントにはわからないからです。

### 2.4 AIをつなぐ

GMは **AIエージェント** の中で動きます。AIエージェントとは、パソコン上のファイルを扱えるAIアプリのことで、ターミナルでもデスクトップでも使えます。たとえば Claude Code や Codex です。claude.ai や ChatGPT のような普通のチャットや、スマートフォンのアプリでは足りません。GMは、パソコンにあるキャンペーンのファイルにアクセスする必要があるからです。エージェントごとに、プランとログインが必要です。Claude Code は有料のClaudeプラン、Codex は ChatGPT のログインです。インストールは、それぞれのページから一度だけ行います：[Claude Code](https://code.claude.com/docs/en/setup)、[Codex](https://learn.chatgpt.com/docs/codex/cli)。

- **Claude Code**：キャンペーンのフォルダで `claude` と入力します。フォルダを信頼するか聞かれたら、**Yes, I trust this folder** を選びます。最初に選ばれているのは *No, exit* なので、注意してください。キャンペーンには小さなフック `rpg --listen` もあります。この質問には表示されません。ダッシュボードで操作すると、すぐにGMへ伝えるしくみです。
- **Codex**：キャンペーンのフォルダで `codex` と入力します。フォルダを信頼するか聞かれたら、yes と答えます。デスクトップアプリでは、設定で、ゲームのチャットのメモリーがオフになっているか確認してください。
- **ほかのエージェント**：キャンペーンのフォルダで起動し、MCPサーバー `rpg mcp` を渡します。RPG Engineは標準的なMCPサーバーです。MCPに対応したエージェントなら、ローカルで動くものも含めて、どれでもGMにできます。

プレイとテストは **Claude Code** で行っています。**Codex** は接続と動作の確認まで済んでいますが、キャンペーン全体をまだ遊び通してはいません。キャンペーンでは、エージェント自身のメモリーをオフにします。ゲームの内容はファイルに残るので、セーブに戻ると、本当にその時点に戻れます。

### 2.5 最初のチャット

何か書いてみましょう。たとえば *こんにちは！始めましょう。* です。チャットを始めるたび、GMは最初の返事で **ダッシュボードのリンク** を伝えます。`http://127.0.0.1:4750` のような形です。そのリンクを開いて、チャットの横に置いておきます。

GMのメッセージの合間に、AIエージェントが使っているツールが表示されます。その詳細は開かないでください（Claude Code では ctrl+o）。秘密が表示されることがあります。

新しいキャンペーンは、3つの段階を進みます。ダッシュボードの上部に表示されます。**1 設定**（遊び方を決める）、**2 セッションゼロ**（プレイの中でキャラクターを作る）、**3 プレイ**です。

### 2.6 設定：遊び方を決める

GMは、まだ決まっていないことだけを、数問ずつ質問します。ダッシュボードの **設定** の段階にも、同じ質問がカードで表示されます。「おまかせ」と書けば、GMが選びます。すべて、あとからチャットや **設定** で変えられます。

| 設定 | 決めること | 値 |
|---|---|---|
| **メンター** | GMがルールをどれだけ教えるか | オフ、ヒント、チュートリアル |
| **難易度** | 世界の厳しさ | ストーリー、イージー、ノーマル、ハード、ブルータル |
| **致死性** | 戦闘で倒れることの意味 | 物語重視（死なない）、叙事詩（重要な場面だけ）、ダイス |
| **セーブ** | いつ戻れるか | 永久死、チェックポイント、自由（[3.8](#38-saves-and-going-back)） |
| **厳しさ** | 食料、明かり、旅をどこまでルールどおりに扱うか | なめらか、ルール、シミュレーション |
| **ダイス** | ダイスを誰が振るか | デジタル、物理 |
| **単位** | 距離と重さ | メートル法、ヤード・ポンド法 |
| **キャラクターの声** | 出会うキャラクターの台詞を誰が言うか。GMがすべて言う、重要な場面だけキャラクター自身が（知っていることだけを知る者として、GMの判断で）言う、またはいつもキャラクター自身が言う（主要なキャラクターだけ、または全員。時間も費用も増えます。AIアプリが対応している場合） | GM、ときどき、主要キャラクター、全員 |
| **仲間** | 誰が一緒に旅をするか | なし、一緒に作る、GMが作る、プレイ中に出会う |
| **画像** | 場所、クエスト、出会った相手の画像 | なし、リクエスト時、新しい場所、クエストと出会った相手（[3.11](#311-pictures)） |
| **ライン** と **ヴェール** | 決して登場させないことと、画面の外でだけ起こること | リスト |
| **言語** | ゲームとダッシュボードの言語 | 自由 |

第5版では、**成長方式** も加わります。経験点またはマイルストーンです。

世界が書かれていない場合、GMは **前提**（ジャンル、雰囲気、いくつかの要素を、自分の言葉で）と **準備** も質問します。準備では、進めながら世界をその場で作るか、最初にすべて作るかを選びます。

**GMの文体** は質問されませんが、チャットや **設定** で変えられます。**文章**（簡潔、文学的、パルプ、皮肉）、GMが考える **物語**（状況、アーク、エピソード、ミステリー）、**文体の手本** にする作家、そのほか **自分の言葉** での指定ができます。

### 2.7 セッションゼロ：キャラクターを作る

テーブルを囲むときと同じように、GMと一緒にキャラクターを作ります。選択はすべて自分のものです。GMに任せたいときは、そう頼みます。しっかりしたアイデアでも、漠然としたものでも、何もなくても大丈夫です。能力値の決め方は、ダイスを振る前にGMが説明します。キャラクターの物語は必須ではありません。物語を伝えれば、GMは伝えた言葉で書きます。そのあと、GMがキャラクターの画像を尋ねます（[3.7](#37-your-characters-story-and-picture)）。キャラクターシートはRPG Engineが計算するので、計算は不要です。

## 3. プレイする <!-- icon: chat -->

### 3.1 GMと話す

キャラクターの行動やセリフを、自分の言葉で書きます。

> 宿の主人に、今夜ほかに誰が通ったか尋ねる。

物語の外で話すときは、角かっこ［ ］ではなく半角の角かっこで囲みます：*[組みつきのルールはどうなっていますか？]* GMも角かっこで答えます。

プレイヤーは試みることを伝え、GMは何が起こるかを伝えます。GMがキャラクターの行動を勝手に決めることはなく、エンジンについて語ることもありません。ダッシュボードの使い方は、GMに尋ねられます。

**ダッシュボードから行動する**：キャラクターシートの名前（武器、呪文、持ち物など）をクリックし、次に対象を選びます。話しかけたい相手をクリックする方法もあります。ダッシュボードが文を作ります。たとえば *フードの盗賊1にメイスで攻撃する。* のような文です。**GMに伝える**を押す前に、内容を変更できます。GMはチャットで言われた内容として受け取り、ほかの行動と同じように裁定します。お使いのAIアプリが自動では受け取れない場合は、**コピー**で文を用意し、チャットに貼り付けます。

### 3.2 ロール

GMがロールを求めるのは、結果が不確かで、しかも重要なときだけです。先に、何がかかっているかも伝えます。そのあとは次のとおりです。

- **ダッシュボードで**：バナーに判定ごとのボタンが表示されます。たとえば *軽業 +4 · 有利* のように表示されます。クリックすると、ページ上にダイスが落ち、GMが結果を受け取ります。光っているキャラクターシートの行をクリックする、ダイストレイからダイスを振る、バナーに別の内容を書く、といった方法もあります。
- **手動**（バナーの隅、または**設定**で選択）：バナーに振るべきロールが表示されます。キャラクターシートかダイストレイから振ります。
- **物理ダイス**（ダイスの設定が物理のとき）：出た目を書きます。*[14が出た。]* RPG Engineが修正値を加えます。

**フリーロール**：キャラクターシートの数字をクリックするか、ダイストレイを開くと、遊びでロールできます。結果は数に入らず、GMにも見えません。

**GMのロール**は、秘密のものを除き、ロール欄に表示されます。いつでも *[今のロールは本物でしたか？]* と尋ねられます。秘密のロールについては、尋ねる前にロールが行われたことを示す指紋をGMが示します。

### 3.3 シーンと戦闘

物語は**シーン**で進みます。戦闘、会話、探索、移動、休息などです。シーンの終わりごとに、ゲームは自動でセーブされ、そのシーンはジャーナルに記録されます。

戦闘では、GMが自分のキャラクター以外のターンをすべて語り、プレイヤーが決める場面で止まります。**シーン**の上部には、今誰のターンか、次は誰かが表示されます。マップの横には、キャラクターのカードが表示されます。ターンの順番、パーティのヒットポイント、敵の傷つき具合（言葉で表示）は、ページの横に表示されたままです。キャラクターが倒れると、死亡セーブがページに大きく表示されます。

### 3.4 時間、旅、動く世界

RPG Engineが日付を管理します。セッションの合間に時間は流れません。*長い休息をとる* と伝え、GMが認めると、休息で回復すべきものが回復します。短い休息では、ヒットダイスを何個使うかをGMがダッシュボードで尋ねることがあります。1個ずつ振り、回復量を確認し、好きなところでやめられます。行き先を伝えます。たとえば *北の道を通ってロッカへ向かう* と伝えると、RPG Engineが道のり、距離、日数を計算します。途中で何かが起こると、そこで止まります。お金はゲーム内の硬貨で数え、おつりも出ます。

悪役には期限つきの計画があります。新しい日が来るたびに、GMは時間が進めた脅威を動かします。プレイヤーに見えるのはその兆しだけで、時計そのものは見えません。

### 3.5 マップ

**ワールド**には、キャラクターが知っている場所、場所をつなぐ道、歩いてきた道のりが表示されます。ほかの部分は霧に覆われています。**シーン**には、今いる場所のマップがあれば表示され、誰がどこにいるかもわかります。戦闘中の自分のターンでは、行けないマスが覆われます。GMにどこへ移動するか尋ねられたら、マスをタッチするか、*E4* のように書きます。

### 3.6 クエスト、ジャーナル、メモ

キャラクターが引き受けた任務は、**ジャーナル**でクエストになります。目標、期限、測るものも記されます。星をつけると、シーンの上部に表示されたままになります。ジャーナルには**物語**もシーンごとに記され、**メモ**も保管されます。メモは非公開です。**共有**したメモだけは、GMが事実ではなく、キャラクターの考えとして受け取ります。**仲間**では、仲間の日記が読めます。仲間は、一日の終わりやクエストの終わりなどに、考えや気持ちを数行書きます。

### 3.7 キャラクターの物語と絵

キャラクターシートの**説明**カードには、キャラクターの物語を書く欄があります。GMは、同意を得てから書き込みます。絵を使うには、パソコン上の保存場所を添えてファイル（PNG、JPEG、WebP、SVG、5 MBまで）をGMに渡すか、肖像を作ってもらいます（[3.11](#311-pictures)）：*[肖像を作って。三つ編みにした白髪で、あごに傷がある。]*

### 3.8 セーブと巻き戻し

RPG Engineは、シーンが終わるたびにキャンペーン全体をセーブします。そのほかは、**セーブ**の設定で決まります。

| セーブ | 好きなときにセーブ | 戻る |
|---|---|---|
| **permadeath** | できない | 戻れない |
| **checkpoint** | できない | 最後のセーブへ（キャラクターが死亡したときのみ） |
| **free** | できる | どのセーブにも |

どのモードでも、**最初からやり直す**ことができます。プレイの始まりからでも、セッションゼロからでも可能です。チャットか**セーブ**で行います。

戻ったあとは、**新しいチャットを開きます**。古いチャットは、取り消された内容を覚えているためです。新しいチャットで *続ける* と書き、セーブで**新しいチャットを開いた**を押します。

### 3.9 セッション：中断と再開

いつでも中断できます：*[今夜はここまでにしましょう。]* すべてすでにファイルに保存されています。再開するには、キャンペーンのフォルダでエージェントを起動し、*続ける* と書きます。GMが短いあらすじを伝え、続きを進めます。

### 3.10 GMの気分

ダッシュボードの上にいるロボットがGMです。表情は物語の雰囲気に合わせて変わり、まだ知らないことは決して明かしません。チャットを閉じると、眠ります。

### 3.11 絵

RPG Engineは、到着した場所、引き受けたクエスト、出会った相手の絵を作れます。作るかどうかは**絵**の設定で決まります。頼めば、キャラクターの肖像も作ります。お使いのCodexまたはClaude Codeを、自分のログインで、契約プランとその制限の範囲内で使います。**Codex**があれば描くのはCodexで、なければ**Claude Code**が描きます。このパソコンで作れるかどうか、作れない場合の設定方法は、**設定**で確認できます。自分で用意した絵をGMに渡すこともいつでもできます。

### 3.12 安全：ライン、ヴェール、ストップ

**ライン**はゲームに決して登場しません。**ヴェール**は画面の外でのみ起こります。いつでも *[ストップ]* と書けます。GMはその内容をすぐにやめ、ラインに加えます。

### 3.13 考えを変える

設定はすべて、チャットか**設定**で変更できます。GMがルールブックにない裁定をした場合、それは**前例**になります。次に同じ質問をすれば、同じ答えが返ります。

## 4. ダッシュボード <!-- icon: party -->

自分のパソコン上にあるページです。そのパソコンのブラウザでのみ開け、チャットが開いている間だけ動きます。チャットを閉じると *Not connected* と表示されます。次のチャットを開くと、自動で戻ります。

- **パーティ**：自分のキャラクターシートと、仲間のキャラクターシート。数字をクリックするとロールできます。カーソルを重ねると、数字の由来がわかります。横にはロールが表示されます。
- **シーン**：今いる場所、その絵とマップ、そこにいる相手、起きていること。戦闘中はターンと、キャラクターのカードも表示されます。
- **ジャーナル**：クエスト、物語、仲間の日記、メモ。
- **ワールド**：キャラクターが知っている範囲の世界マップ。
- **ダイストレイ**：ダイスと修正値を選んで振ります。
- **セーブ**、**ヘルプ**、**設定**、**概要**：列の末尾にアイコンで並びます。設定には、ページ自体の好みも含まれます。テーマ、ダイスの音、ダイスのセットです。

GMから問いかけられると、どのセクションを開いていても、そのバナーが上部に表示されたままになります。

## 5. ゲームシステムとハウスルール <!-- icon: dice -->

### 5.1 ゲームシステムとは

1つのゲームのデータです。キャラクターシート、数値、クリーチャー、アイテム、呪文、ルールのテキストが含まれます。キャンペーンごとに、遊ぶシステムは1つです。RPG Engineは、キャラクターシートの計算と、消費したものや戻ってくるものの管理を行います。特技がどう働くかは、GMがルールを読んで判断します。実際のテーブルと同じです。

### 5.2 第5版を収録

SRD 5.1の種族、クラス、サブクラス、背景、特技。319種の呪文、武器、防具、魔法のアイテム、モンスター。GMが正確な文面で読むルール各章。計算済みの完全なキャラクターシート。

SRDにない内容も、お持ちの書籍から遊べます。GMがキャンペーンのページとして書き起こし、RPG Engineが自前のデータと同じように扱います。RPG Engineが収録するのはオープンコンテンツだけです。GMが知っている範囲に制限はありません。

お手持ちのマニュアルを、ライブラリにできます。GMに場所を伝えるか、*[マニュアルは D:\Books\5e にあります。]* 、Packages › Library でそのフォルダを追加します。そして、コンピューターに表示されるウィンドウで、一度だけ「はい」を選びます。RPG Engineはこのコンピューター上でマニュアルを読みます。各キャンペーンは、そこで有効にしたフォルダを使います。GMはルールを判断するとき、SRDの次にそれらを検索し、書名とページを示します。テキストの形式か、テキストを選択できるPDFが最適です。スキャンしたPDFは、ページの画像から読み取ります。Windowsのみの対応で、数分かかり、誤りも少しあります。RPG Engineがマニュアルを変更することはありません。テキストをどこかへ送ることも、キャンペーンにコピーすることもありません。

### 5.3 ハウスルールと独自の追加

GMに頼みます：*[ハウスルール：攻撃の出目1で武器を落とす。]* GMはそれをテーブルの取り決めとして記録します。必要なら、ページを書くか、キャラクターシートの数値を書きます。すでに文章になっているハウスルールは、テキストファイルにして、キャンペーンの `rules` フォルダに入れられます。

### 5.4 独自のゲームシステムの追加・インポート

まだできません。現在、RPG Engineが遊べるのは第5版だけです（[今後の予定](#9-coming-later)）。

## 7. キャンペーンのもとと言語 <!-- icon: world -->

### 7.1 世界を用意する3つの方法

- **その場で作る**：前提をもとに、場所、人物、筋書きを、必要になる直前にGMが作り、記録しておきます。
- **最初に準備する**：同じ方法で、プレイの前に世界を作っておきます。
- **手持ちのアドベンチャーや本から**：ファイルをGMに渡します。*[このアドベンチャーをキャンペーンとして取り込んでください：D:\Books\adventure.pdf。中身は何も教えないでください。]* テキスト、EPUB、Word文書、テキストを選択できるPDFなら、きれいに読み込めます。スキャンしたPDFはページの画像から読み取りますが、Windowsのみで、時間がかかり、いくつか間違いも出ます。自分のCodexかClaude Codeがチャットの外で読み込みます。なければ、チャットのGMが自分のプランで読み込みます。どちらの場合も、文書全体がOpenAIまたはAnthropicに送られ、アカウントの規約と学習に関する設定が適用されます。進み具合はダッシュボードに表示されます。小説からの場合は、どこから始めるかGMが提案します。場所、キャラクター、秘密はGMが書きます。

キャンペーンは1回だけ遊びます。同じアドベンチャーをもう一度遊ぶには、新しいキャンペーンを作ります。

### 7.2 言語

言語はキャンペーンごとに1つで、GMの言語です。ダッシュボードもそれに合わせます。ダッシュボードは26言語に対応しています。それ以外の言語は、CodexかClaude Codeがパソコン上で翻訳します。なければ、チャットのGMが翻訳します。第5版のイタリア語の用語は、公式のイタリア語版SRDによります。ルールの本文は英語のままで、GMが使用言語で語ります。

## 8. 興味のある方へ：キャンペーンフォルダー <!-- icon: list -->

開く必要はありません。キャンペーンの秘密が入っています。中身は次のとおりです。`campaign.yaml`（設定）、`state.yaml`（ゲームの現在の状態）、`world/`（キャラクター、場所、クエストなどごとにmarkdownのページをひとつずつ）、`rules/`（ハウスルール）、`images/`、`log.jsonl`（すべての変更）、`.saves/`、`.player/`（メモ）、そしてAIエージェントにRPG Engine の場所を伝える小さなファイル。ページはObsidianの形式です。ページを手で変更すると、GMは次の返答の時点でそれを知ります。

RPG Engine はこのフォルダーの中にとどまります。ゲームの読み書きはここだけで行い、ほかのファイルには触れません。マニュアルのフォルダーは読むだけです。この外に置くのは、専用のデータフォルダー（ダッシュボードの翻訳、マニュアルから読み取ったテキスト、許可した場合のCodexやClaude Code）と、画像を描く間の一時フォルダーだけです。エージェントがコンピューター上でほかのことをしたいときは、先に確認があります。

GMが使うコマンドは、すべてキャンペーンフォルダーでも実行できます。`rpg --help` で一覧が出ます。多くは、キャンペーンの秘密を表示します。

## 10. 質問と困ったとき <!-- icon: info -->

### 質問

**ルールを知っている必要はありますか？** いいえ。メンターをtutorialにして、聞きたいときに角括弧で質問してください。

**GMはズルをしますか？** RPG Engineが出したロールは、難易度がstoryのとき以外は変えられません。すでに決まった事実も変えられません。

**お金はかかりますか？** RPG Engineは無料です。GMは、エージェントのプランか、自分のパソコンのローカルモデルで動きます。1晩の遊びは長いチャットになります。小さいプランでは、夜の終わる前にプランの上限に達することがあります。画像、翻訳、取り込みも同じプランを使います。RPG Engine自体はAPIキーを使いません。APIキーは呼び出しごとに課金されます。エージェントには、キーではなく、アカウントでサインインしてください。

**スマートフォンで遊べますか？** いいえ。GMはパソコン上で動き、ダッシュボードもそこでしか開けません。

**友達と遊べますか？** まだできません。今は、プレイヤー1人、キャラクター1人と、仲間までです（[近日対応](#9-coming-later)）。

**次回は別のAIを使えますか？** はい。別のエージェントでキャンペーンを開き、*続ける*と書いてください。

### 困ったとき

**ダッシュボードが開きません。** GMに聞いてください：`[ダッシュボードのリンクを教えてください。]` リンクが使えるのは、そのキャンペーンでチャットが開いている間だけで、GMの最初の返答のあとからです。

**GMがゲームを知らないようです。** エージェントがRPG Engineを読み込んでいません。キャンペーンのフォルダで起動したか、フォルダを信頼したか確認してください。Claude Codeでは`/mcp`と書いて、`rpg`に再接続します。Codexでは、キャンペーンのフォルダで`codex mcp list`を実行すると、`rpg`が表示されるはずです。`rpg --version`が見つからない場合は、RPG Engineをもう一度インストールしてください（[2.2](#22-install)）。

**更新。** `npm install -g rpg-engine`をもう一度実行し、新しいチャットを開きます。動いているGMは、起動したときのバージョンのままです。

**取り消したことをGMが覚えています。** 新しいチャットを開き、セーブの**新しいチャットを開いた**を押してください。

**画像が表示されません。** 設定 > 画像で、このパソコンで作れるかどうかと、その方法を確認できます。

**インストールに失敗する、または`rpg`が起動しません。** `node --version`が22以降を示す必要があります。Windowsでは、RPG Engineとキャンペーンを、`&`を含むパスに置かないでください。

**ダッシュボードのリンクが変わりました。** 別のプログラムがいつものアドレスを使っています。GMが新しいリンクを伝えます。
