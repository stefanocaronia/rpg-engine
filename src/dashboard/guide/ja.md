# RPG Engine：完全ガイド

**RPG Engine**では、**AIをGM**にして、テーブルトークRPGを遊べます。GMとは**チャット**で会話します。RPG Engineは裏側で動き、**世界を記憶し**、**ダイスを振り**、**数値を管理**します。チャットの横にはブラウザーのページ、**ダッシュボード**を開いておきます。キャラクターシート、ダイス、マップ、ジャーナルが並びます。

このガイドはプレイヤー向けです。プログラミングの知識は必要ありません。

## クイックスタート <!-- icon: send -->

1. [nodejs.org](https://nodejs.org)から**Node.js**をインストールします（LTS版）。
2. **AIエージェント**をインストールして、サインインします。AIエージェントとは、GMが動くプログラムです。たとえばClaude CodeやCodexです（[2.4](#24-connect-your-ai)）。
3. ターミナルで、RPG Engineをインストールします：`npm install -g rpg-engine`。
4. キャンペーンを作ります：`rpg init "The Salt Isles"`。
5. 作られたフォルダーに入り（`cd "The Salt Isles"`）、そこでエージェントを起動します。Claude Codeなら`claude`、Codexなら`codex`です。フォルダーを信頼するか聞かれたら、はいと答えます（[2.4](#24-connect-your-ai)）。そして*こんにちは！始めましょう。*と書きます。GMがダッシュボードへのリンクを伝えます。

## 1. RPG Engineとは <!-- icon: about -->

| 誰が | 何をするか |
|---|---|
| **自分** | キャラクターを演じます。何をして、何を言い、何を試みるかを決めます。 |
| **GM**（AI） | 物語を語り、ほかの全員を演じ、何が起こるかを決め、ロールを求めます。 |
| **RPG Engine** | 世界をファイルに保ち、ダイスを振り、ヒットポイント、お金、時間、距離を数え、発見されるまで秘密を守ります。 |

世界は、夜が変わっても、新しいチャットでも、別のAIでも変わりません。

- **語られたことは真実のままです。**倒された悪役は倒されたままです。
- **ダイスは本物です。**GMはダイスを曲げられません。ただし、最も易しい難易度を選んだ場合は例外です。
- **秘密は秘密のままです。**キャラクターが知らないことを、GMが伝えることはありません。
- **世界は動きます。**休息や旅のあいだにも脅威は進み、その兆しが見えます。
- **キャンペーンはコンピューター上のフォルダーです。**いつでも中断して、あとで続きを遊べます。

現在、RPG Engineが遊べるゲームシステムは、無料のSystem Reference Document 5.1にもとづく**第5版**です。ほかのシステムも今後追加されます（[今後の予定](#9-coming-later)）。

## 2. はじめに <!-- icon: path -->

### 2.1 必要なもの

- Windows、macOS、Linuxのいずれかが動くパソコンと、Webブラウザ。
- **Node.js 22**以降。[nodejs.org](https://nodejs.org)から入手します。`npm`が付属しており、RPG Engineのインストールに使います。
- **ターミナル**：Windowsではターミナル（Terminal）かPowerShell、macOSではターミナル。フォルダでターミナルを開くには、フォルダを右クリックして、**ターミナルで開く**（Windows）か**サービス > フォルダに新規ターミナル**（macOS）を選びます。
- GMになる**AIエージェント**（[2.4](#24-connect-your-ai)）。使えるなかで**最も大きいモデル**を選びます。小さいモデルは、言いくるめられて秘密をもらしたり、ルールを曲げたりしやすくなります。

### 2.2 インストール

```text
npm install -g rpg-engine
```

`rpg --version`で、インストールできたか確認できます。`rpg`を使うのは、キャンペーンを作るときの1回だけです。その後は、エージェントがRPG Engineを自動で起動します。

### 2.3 キャンペーンを作る

ゲームを置いておくフォルダでターミナルを開きます（開き方は[2.1](#21-what-you-need)）。

```text
rpg init "The Salt Isles"
```

これで`The Salt Isles`というフォルダができ、新しいキャンペーンが入ります。`cd "The Salt Isles"`で、そのフォルダに移動します。場所は覚えておいてください。遊ぶたびに、ここへ戻ってきます。ほかの設定はあとから、チャットかダッシュボードで決められます。今のうちに決めたい場合は、`rpg init --help`でオプションを確認できます。たとえば`--language it`や`--difficulty hard`です。

GMはキャンペーンを作れません。`init`の前は、RPG Engineがどこにあるのか、エージェントにはわからないためです。

### 2.4 AIをつなぐ

GMは**AIエージェント**の中で動きます。AIエージェントとは、パソコン上のファイルを扱えるAIアプリのことで、ターミナル版もデスクトップ版もあります。たとえばClaude CodeやCodexです。claude.aiやChatGPTのような普通のチャットや、スマートフォンのアプリでは足りません。GMは、パソコンにあるキャンペーンのファイルにアクセスする必要があるからです。エージェントごとに、契約とログインが必要です。Claude Codeは有料のClaudeプラン、CodexはChatGPTのログインです。インストールは最初の1回だけで、それぞれの公式ページから行います：[Claude Code](https://code.claude.com/docs/en/setup)、[Codex](https://learn.chatgpt.com/docs/codex/cli)。

- **Claude Code**：キャンペーンのフォルダで`claude`と入力します。フォルダを信頼するか聞かれたら、**Yes, I trust this folder**を選びます。最初に選ばれているのは*No, exit*なので、注意してください。キャンペーンには小さなフック`rpg --listen`もあります。この質問には表示されませんが、ダッシュボードで操作するとすぐGMに伝わる仕組みです。
- **Codex**：キャンペーンのフォルダで`codex`と入力し、フォルダを信頼するか聞かれたら、はいと答えます。デスクトップアプリでは、ゲームのチャットでメモリがオフになっているか、設定で確認します。
- **ほかのエージェント**：キャンペーンのフォルダで起動し、MCPサーバー`rpg mcp`を渡します。RPG Engineは標準的なMCPサーバーです。MCPに対応したエージェントなら、ローカルで動くものも含め、どれでもGMにできます。

プレイとテストは**Claude Code**で行っています。**Codex**は接続と動作確認まで済んでいますが、キャンペーンを最後まで遊んだことはまだありません。キャンペーンでは、エージェント自身のメモリをオフにします。ゲームの内容はファイルの中にあるので、セーブに戻れば本当に元の状態に戻ります。

### 2.5 最初のチャット

「こんにちは！始めましょう。」など、何でも書いてかまいません。チャットを始めるたび、GMは最初の返答で**ダッシュボードへのリンク**を知らせます。`http://127.0.0.1:4750`のような形です。開いて、チャットの横に置いておきます。

GMのメッセージの合間に、エージェントが使っているツールが表示されます。その詳細は開かないでください（Claude Codeではctrl+o）。秘密が見えてしまうことがあります。

新しいキャンペーンは、ダッシュボードの上部に表示される3つの段階で進みます。**1 設定**（遊び方を決める）、**2 セッションゼロ**（プレイしながらキャラクターを作る）、**3 プレイ**です。

### 2.6 設定：遊び方を決める

GMは、まだ決まっていないことだけを、いくつかずつ質問します。ダッシュボードの**設定**の段階でも、同じ質問がカードで表示されます。「おまかせ」と書けば、GMが選びます。どの項目もあとから、チャットか**設定**で変えられます。

| 設定 | 決めること | 値 |
|---|---|---|
| **メンター** | GMがルールをどれくらい教えるか | オフ、ヒント、チュートリアル |
| **難易度** | 世界の厳しさ | ストーリー、イージー、ノーマル、ハード、ブルータル |
| **致死性** | 戦闘で倒れたときの扱い | 物語優先（死なない）、叙事詩（重要な場面のみ）、ダイス |
| **セーブ** | いつ戻れるか | 永久死亡、チェックポイント、自由（[3.8](#38-saves-and-going-back)） |
| **厳しさ** | 食料、光源、旅をどれくらい厳密に扱うか | なめらか、ルール重視、シミュレーション |
| **ダイス** | 誰がダイスを振るか | デジタル、物理 |
| **単位** | 距離と重さの単位 | メートル法、ヤード・ポンド法 |
| **声** | 出会う人物の声を誰が担当するか。重要な場面では、その人物自身が、知っていることだけを知る者として話す。GMが選ぶ、常にGM、あるいは主要人物または全員が常に本人として話す。後者は遅く、費用もかさみ、AIアプリが対応している場合のみ | 自動、GM、重要な場面のみ、常に本人 |
| **仲間** | 誰が旅に同行するか | なし、一緒に作る、GMが作る、プレイ中に出会う |
| **画像** | 場所、クエスト、出会う人物の画像 | なし、リクエスト時、新しい場所・クエスト・出会う人物（[3.11](#311-pictures)） |
| **ライン**と**ヴェール** | 決して登場させないこと、そして画面の外でのみ起こること | リスト |
| **言語** | ゲームとダッシュボードの言語 | 任意 |

第5版では、**成長**も加わります。経験値かマイルストーンです。

世界が用意されていない場合、GMは**プレミス**（ジャンル、雰囲気、いくつかの要素を自分の言葉で）と、**準備**も質問します。準備とは、進めながら世界をその場で作るか、最初にすべて作っておくかです。

**GMの文体**は質問されませんが、チャットか**設定**で変えられます。**文章**（素朴、文学的、パルプ、皮肉）、GMが作る**物語**（状況、長編、エピソード、ミステリー）、**文体の手本**にする作家、そのほか**自分の言葉**での指定ができます。

### 2.7 セッションゼロ：キャラクターを作る

卓を囲むときと同じように、GMと一緒にキャラクターを作ります。GMに任せると頼まない限り、選ぶのはすべて自分です。しっかりしたイメージでも、ぼんやりしたイメージでも、何もなくても大丈夫です。能力値の決め方は、ダイスを振る前にGMが説明します。キャラクターの物語は必須ではありません。用意した場合、GMは本人の言葉のまま書き留めます。そのあとGMが、キャラクターの画像について尋ねます（[3.7](#37-your-characters-story-and-picture)）。キャラクターシートはRPG Engineが整えるので、計算は一切不要です。

## 3. プレイする <!-- icon: chat -->

### 3.1 GMと話す

キャラクターの行動やセリフを、自分の言葉で書きます。

> 宿の主人に、今夜ほかに誰が通ったか尋ねる。

物語の外のことは、角かっこの中に書きます。*[組みつきはどう処理しますか？]* GMも角かっこで答えます。

試みることを伝えるのはプレイヤーで、何が起こるかを伝えるのはGMです。GMがキャラクターの行動を勝手に決めることはなく、エンジンの話をすることもありません。ダッシュボードの使い方は、GMに聞けます。

**ダッシュボードから行動する**：キャラクターシートの名前（武器、呪文、持ち物など）をクリックし、次に対象を選びます。人物をクリックして話しかけることもできます。ダッシュボードが「*フード姿の山賊1をメイスで攻撃する。*」のような文を作ります。**GMに伝える**を押す前に、文は書き換えられます。GMはチャットで言ったときと同じように受け取り、ほかの行動と同じように裁定します。AIアプリが自動では受け取れない場合は、**コピー**を押すと、チャットに貼りつける準備ができます。

### 3.2 ロール

GMがロールを求めるのは、結果が不確かで、かつ重要なときだけです。何がかかっているかも、先に伝えます。そのうえで：

- **ダッシュボードで**は、バナーに判定ごとのボタンが表示されます。たとえば*アクロバット +4 · 有利*です。クリックすると、ページ上でダイスが転がり、GMに結果が伝わります。ほかにも、光ったキャラクターシートの行をクリックする、ダイストレイからダイスを振る、バナーに別の内容を書く、といった方法もあります。
- **手動**は、バナーの隅か**設定**で選びます。バナーが何を振るか知らせるので、キャラクターシートかダイストレイから振ります。
- **物理ダイス**は、ダイスの設定が物理のときの方法です。出た目を書くと（*[14が出た。]*）、RPG Engineが修正値を加えます。

**フリーロール**：キャラクターシートの数字をクリックするか、ダイストレイを開けば、気軽に振れます。結果は一切反映されず、GMにも見えません。

**GMのロール**は、秘密のものを除き、ロール欄に表示されます。*[今のロールは本物でしたか？]*といつでも聞けます。秘密のロールについては、質問より前に振られたことを証明するフィンガープリントを、GMが示します。

### 3.3 シーンと戦闘

物語は**シーン**で進みます。戦闘、会話、探索、移動、休憩などです。シーンが終わるたびにゲームは自動でセーブされ、そのシーンはジャーナルに記録されます。

戦闘では、自分以外のターンはGMがすべて語り、自分が決める場面で止まります。**シーン**の上部には、今誰のターンか、次は誰かが表示されます。マップの横には、キャラクターのカードが出ます。ターンの順番、パーティのヒットポイント、敵の傷つき具合（言葉で表示）は、ページの横に表示されたままです。キャラクターが倒れると、死亡セーブがページに大きく表示されます。

### 3.4 時間、旅、動いていく世界

RPG Engineは日付を管理しています。セッションとセッションの間に時間は流れません。「長い休憩をとる」と伝え、GMが認めると、休憩で回復すべきものが回復します。短い休憩では、使うヒットダイスの数をGMがダッシュボードで尋ねることがあります。1つずつ振って、それぞれの回復量を見ながら、好きなところでやめられます。行き先を伝えると（「北のロッカへ街道を進む」）、RPG Engineが道のり、距離、日数を計算します。途中で何か起これば、そこで止まります。お金はゲーム内の硬貨で数えられ、おつりも出ます。

悪役には、期限つきの計画があります。新しい日になるたび、GMは時間が進めた脅威を動かします。その兆しは見えますが、時計そのものは見えません。

### 3.5 マップ

**ワールド**には、キャラクターが知っている場所、その間の道、歩いてきた足跡が表示され、残りは霧に包まれています。**シーン**には、今いる場所のマップがあれば表示され、誰がどこにいるかもわかります。戦闘中の自分のターンでは、届かないマスにヴェールがかかります。GMにどこへ動くか聞かれたら、マスをタッチするか、*E4*のように書いて答えます。

### 3.6 クエスト、ジャーナル、メモ

キャラクターが引き受けた仕事は、**ジャーナル**でクエストになります。目標、期限、進み具合を示すものも一緒に記録されます。星をつけると、シーンの上部に表示され続けます。ジャーナルには、シーンごとの**物語**も書かれ、**メモ**も保管されます。メモは非公開ですが、**共有**すれば、GMには事実ではなく、キャラクターの考えとして伝わります。

### 3.7 キャラクターの物語と画像

キャラクターシートの**説明**カードには、キャラクターの物語を入れる欄があります。同意すると、GMが書き込みます。画像は、パソコン上のファイル（PNG、JPEG、WebP、SVGのいずれか、5 MBまで）とその場所をGMに伝えるか、肖像画を作ってもらいます（[3.11](#311-pictures)）：*[肖像画をお願いします。三つ編みの白髪で、あごに傷があります。]*

### 3.8 セーブと巻き戻し

RPG Engineは、シーンが終わるたびにキャンペーン全体をセーブします。そのほかは、**セーブ**の設定で決まります。

| セーブ | 好きなときにセーブ | 巻き戻し |
|---|---|---|
| **永久死亡** | できない | できない |
| **チェックポイント** | できない | キャラクターが死んだときだけ、最後のセーブへ |
| **自由** | できる | どのセーブにも |

どのモードでも、プレイの最初かセッションゼロから**やり直す**ことができます。チャットか**セーブ**で行います。

巻き戻したあとは、**新しいチャットを開いてください**。古いチャットは、取り消された出来事を覚えています。新しいチャットで「続けます」と書き、そのあとセーブで**新しいチャットを開いた**を押します。

### 3.9 セッション：中断と再開

やめたいときにいつでもやめられます：*[今夜はここまでにしましょう。]* すべてすでにファイルに保存されています。再開するには、キャンペーンのフォルダでエージェントを起動し、「続けます」と書きます。GMが短いあらすじを伝えてから、続きに入ります。

### 3.10 GMの気分

ダッシュボード上部のロボットがGMです。表情は物語の雰囲気に合わせて変わりますが、まだ知らないことを明かしてしまうことはありません。チャットを閉じると眠ります。

### 3.11 画像

**画像**の設定に従って、RPG Engineは、たどり着いた場所、引き受けたクエスト、出会った人物の画像を作れます。頼めば、キャラクターの肖像画も作ります。使うのは自分のCodexかClaude Codeで、ログインもプランも利用制限も自分のものです。**Codex**があればCodexが描き、なければ**Claude Code**が描きます。このパソコンで作れるかどうか、作れない場合の設定方法は、**設定**に表示されます。自分で用意した画像は、いつでもGMに渡せます。

### 3.12 安全：ライン、ヴェール、ストップ

**ライン**はゲームに決して登場しません。**ヴェール**は画面の外でのみ起こります。*[ストップ]*と書けば、いつでも使えます。GMはすぐにその内容をやめ、ラインに加えます。

### 3.13 気が変わったとき

どの設定も、チャットか**設定**でいつでも変えられます。ルールブックにないことをGMが裁定した場合は**先例**になり、次に同じ問いがあれば同じ答えが返ります。

## 4. ダッシュボード <!-- icon: party -->

自分のパソコン上のページです。そのパソコンのブラウザでだけ開け、チャットが開いている間だけ動きます。チャットを閉じると *Not connected* と表示され、次のチャットで自動的に戻ります。

- **パーティ**：自分のキャラクターシートと、仲間のシートです。数字をクリックするとロールします。数字にカーソルを合わせると、その由来が分かります。横にはロールが並びます。
- **シーン**：今いる場所、その画像とマップ、そこにいる人、起きていることです。戦闘中はターンとキャラクターのカードが出ます。
- **ジャーナル**：クエスト、ストーリー、メモです。
- **ワールド**：キャラクターが知っている範囲の世界マップです。
- **ダイストレイ**：ダイスと修正値を選んで振ります。
- **セーブ**、**ヘルプ**、**設定**、**概要**：列の末尾にアイコンで並びます。設定には、ページ自体の好みもあります。テーマ、ダイスの音、ダイスのセットです。

GMから何か聞かれると、どのセクションにいても、バナーが上部に表示され続けます。

## 5. ゲームシステムとハウスルール <!-- icon: dice -->

### 5.1 ゲームシステムとは

1つのゲームのデータです。キャラクターシート、数値、クリーチャー、アイテム、呪文、ルールのテキストが含まれます。キャンペーンごとに、遊ぶシステムは1つです。RPG Engineは、キャラクターシートの計算と、消費したものや戻ってくるものの管理を行います。特技がどう働くかは、GMがルールを読んで判断します。実際のテーブルと同じです。

### 5.2 第5版を収録

SRD 5.1の種族、クラス、サブクラス、背景、特技。319種の呪文、武器、防具、魔法のアイテム、モンスター。GMが正確な文面で読むルール各章。計算済みの完全なキャラクターシート。

SRDにない内容も、お持ちの書籍から遊べます。GMがキャンペーンのページとして書き起こし、RPG Engineが自前のデータと同じように扱います。RPG Engineが収録するのはオープンコンテンツだけです。GMが知っている範囲に制限はありません。

お手持ちのマニュアルを、ライブラリにできます。GMに場所を伝えるか、*[マニュアルは D:\Books\5e にあります。]* 、Packages › Library でそのフォルダを追加します。そして、コンピューターに表示されるウィンドウで、一度だけ「はい」を選びます。RPG Engineはこのコンピューター上でマニュアルを読みます。各キャンペーンは、そこで有効にしたフォルダを使います。GMはルールを判断するとき、SRDの次にそれらを検索し、書名とページを示します。テキストの形式か、テキストを選択できるPDFが最適です。スキャンしたPDFは、ページの画像から読み取ります。Windowsのみの対応で、数分かかり、誤りも少しあります。RPG Engineがマニュアルを変更することはありません。テキストをどこかへ送ることも、キャンペーンにコピーすることもありません。

### 5.3 ハウスルールと独自の追加

GMに頼みます：*[ハウスルール：攻撃の出目1で武器を落とす。]* GMはそれをテーブルの取り決めとして記録します。必要なら、ページを書くか、キャラクターシートの数値を書きます。すでに文章になっているハウスルールは、テキストファイルにして、キャンペーンの `rules` フォルダに入れられます。

### 5.4 独自のゲームシステムの追加・インポート

まだできません。現在、RPG Engineが遊べるのは第5版だけです（[今後の予定](#9-coming-later)）。

## 7. キャンペーンのもとと言語 <!-- icon: world -->

### 7.1 世界を用意する3つの方法

- **その場で作る**：前提をもとに、場所、人物、筋書きを、必要になる直前にGMが作り、記録しておきます。
- **最初に準備する**：同じ方法で、プレイの前に世界を作っておきます。
- **手持ちのアドベンチャーや本から**：ファイルをGMに渡します。*[このアドベンチャーをキャンペーンとして取り込んでください：D:\Books\adventure.pdf。中身は何も教えないでください。]* テキスト、EPUB、Word文書、テキストを選択できるPDFなら、きれいに読み込めます。スキャンしたPDFはページの画像から読み取りますが、Windowsのみで、時間がかかり、いくつか間違いも出ます。自分のCodexかClaude Codeがチャットの外で読み込みます。なければ、チャットのGMが自分のプランで読み込みます。どちらの場合も、文書全体がOpenAIまたはAnthropicに送られ、アカウントの規約と学習に関する設定が適用されます。進み具合はダッシュボードに表示されます。小説からの場合は、どこから始めるかGMが提案します。場所、キャラクター、秘密はGMが書きます。

キャンペーンは1回だけ遊びます。同じアドベンチャーをもう一度遊ぶには、新しいキャンペーンを作ります。

### 7.2 言語

言語はキャンペーンごとに1つで、GMの言語です。ダッシュボードもそれに合わせます。ダッシュボードは26言語に対応しています。それ以外の言語は、CodexかClaude Codeがパソコン上で翻訳します。なければ、チャットのGMが翻訳します。第5版のイタリア語の用語は、公式のイタリア語版SRDによります。ルールの本文は英語のままで、GMが使用言語で語ります。

## 8. 興味のある方へ：キャンペーンフォルダー <!-- icon: list -->

開く必要はありません。キャンペーンの秘密が入っています。中身は次のとおりです。`campaign.yaml`（設定）、`state.yaml`（ゲームの現在の状態）、`world/`（キャラクター、場所、クエストなどごとにmarkdownのページをひとつずつ）、`rules/`（ハウスルール）、`images/`、`log.jsonl`（すべての変更）、`.saves/`、`.player/`（メモ）、そしてAIエージェントにRPG Engine の場所を伝える小さなファイル。ページはObsidianの形式です。ページを手で変更すると、GMは次の返答の時点でそれを知ります。

RPG Engine はこのフォルダーの中にとどまります。ゲームの読み書きはここだけで行い、ほかのファイルには触れません。マニュアルのフォルダーは読むだけです。この外に置くのは、専用のデータフォルダー（ダッシュボードの翻訳、マニュアルから読み取ったテキスト、許可した場合のCodexやClaude Code）と、画像を描く間の一時フォルダーだけです。エージェントがコンピューター上でほかのことをしたいときは、先に確認があります。

GMが使うコマンドは、すべてキャンペーンフォルダーでも実行できます。`rpg --help` で一覧が出ます。多くは、キャンペーンの秘密を表示します。

## 10. 質問と困ったとき <!-- icon: info -->

### 質問

**ルールを知っている必要はありますか？** いいえ。メンターをtutorialにして、聞きたいときに角括弧で質問してください。

**GMはズルをしますか？** RPG Engineが出したロールは、難易度がstoryのとき以外は変えられません。すでに決まった事実も変えられません。

**お金はかかりますか？** RPG Engineは無料です。GMは、エージェントのプランか、自分のパソコンのローカルモデルで動きます。1晩の遊びは長いチャットになります。小さいプランでは、夜の終わる前にプランの上限に達することがあります。画像、翻訳、取り込みも同じプランを使います。RPG Engine自体はAPIキーを使いません。APIキーは呼び出しごとに課金されます。エージェントには、キーではなく、アカウントでサインインしてください。

**スマートフォンで遊べますか？** いいえ。GMはパソコン上で動き、ダッシュボードもそこでしか開けません。

**友達と遊べますか？** まだできません。今は、プレイヤー1人、キャラクター1人と、仲間までです（[近日対応](#9-coming-later)）。

**次回は別のAIを使えますか？** はい。別のエージェントでキャンペーンを開き、*続ける*と書いてください。

### 困ったとき

**ダッシュボードが開きません。** GMに聞いてください：`[ダッシュボードのリンクを教えてください。]` リンクが使えるのは、そのキャンペーンでチャットが開いている間だけで、GMの最初の返答のあとからです。

**GMがゲームを知らないようです。** エージェントがRPG Engineを読み込んでいません。キャンペーンのフォルダで起動したか、フォルダを信頼したか確認してください。Claude Codeでは`/mcp`と書いて、`rpg`に再接続します。Codexでは、キャンペーンのフォルダで`codex mcp list`を実行すると、`rpg`が表示されるはずです。`rpg --version`が見つからない場合は、RPG Engineをもう一度インストールしてください（[2.2](#22-install)）。

**更新。** `npm install -g rpg-engine`をもう一度実行し、新しいチャットを開きます。動いているGMは、起動したときのバージョンのままです。

**取り消したことをGMが覚えています。** 新しいチャットを開き、セーブの**新しいチャットを開いた**を押してください。

**画像が表示されません。** 設定 > 画像で、このパソコンで作れるかどうかと、その方法を確認できます。

**インストールに失敗する、または`rpg`が起動しません。** `node --version`が22以降を示す必要があります。Windowsでは、RPG Engineとキャンペーンを、`&`を含むパスに置かないでください。

**ダッシュボードのリンクが変わりました。** 別のプログラムがいつものアドレスを使っています。GMが新しいリンクを伝えます。
