# RPG Engine：完全ガイド

**RPG Engine**では、**AIをGM**にして、テーブルトークRPGを遊べます。GMとは**チャット**で会話します。RPG Engineは裏側で動き、**世界を記憶し**、**ダイスを振り**、**数値を管理**します。チャットの横にはブラウザーのページ、**ダッシュボード**を開いておきます。キャラクターシート、ダイス、マップ、ジャーナルが並びます。

このガイドはプレイヤー向けです。プログラミングの知識は必要ありません。

## クイックスタート <!-- icon: send -->

1. [nodejs.org](https://nodejs.org)から**Node.js**をインストールします（LTS版）。
2. **AIエージェント**をインストールして、サインインします。AIエージェントとは、GMが動くプログラムです。たとえばClaude CodeやCodexです（[2.4](#24-connect-your-ai)）。
3. ターミナルで、RPG Engineをインストールします：`npm install -g rpg-engine`。
4. キャンペーンを作ります：`rpg init "The Salt Isles"`。
5. 作られたフォルダーに入り（`cd "The Salt Isles"`）、そこでエージェントを起動します。Claude Codeなら`claude`、Codexなら`codex`です。フォルダーを信頼するか聞かれたら、はいと答えます（[2.4](#24-connect-your-ai)）。そして*こんにちは！始めましょう。*と書きます。GMがダッシュボードへのリンクを伝えます。

## 1. RPG Engineとは <!-- icon: about -->

| 誰が | 何をするか |
|---|---|
| **自分** | キャラクターを演じます。何をして、何を言い、何を試みるかを決めます。 |
| **GM**（AI） | 物語を語り、ほかの全員を演じ、何が起こるかを決め、ロールを求めます。 |
| **RPG Engine** | 世界をファイルに保ち、ダイスを振り、ヒットポイント、お金、時間、距離を数え、発見されるまで秘密を守ります。 |

世界は、夜が変わっても、新しいチャットでも、別のAIでも変わりません。

- **語られたことは真実のままです。**倒された悪役は倒されたままです。
- **ダイスは本物です。**GMはダイスを曲げられません。ただし、最も易しい難易度を選んだ場合は例外です。
- **秘密は秘密のままです。**キャラクターが知らないことを、GMが伝えることはありません。
- **世界は動きます。**休息や旅のあいだにも脅威は進み、その兆しが見えます。
- **キャンペーンはコンピューター上のフォルダーです。**いつでも中断して、あとで続きを遊べます。

現在、RPG Engineが遊べるゲームシステムは、無料のSystem Reference Document 5.1にもとづく**第5版**です。ほかのシステムも今後追加されます（[今後の予定](#9-coming-later)）。

## 2. はじめに <!-- icon: path -->

### 2.1 必要なもの

- Windows、macOS、Linuxのいずれかが動くパソコンと、ウェブブラウザ。
- **Node.js 22**以降。[nodejs.org](https://nodejs.org)から入手できます。RPG Engineをインストールする `npm` が一緒に入ります。
- **ターミナル**：Windowsではターミナル（Terminal）かPowerShell、macOSではターミナル。フォルダでターミナルを開くには、フォルダを右クリックして、**ターミナルで開く**（Windows）または**サービス > フォルダに新規ターミナル**（macOS）を選びます。
- GM用の**AIエージェント**（[2.4](#24-connect-your-ai)）。使うのは、提供されている中で**最も大きいモデル**です。小さいモデルは、言いくるめられて秘密を明かしたり、ルールを曲げたりしやすくなります。

### 2.2 インストール

```text
npm install -g rpg-engine
```

`rpg --version` で、うまくいったか確認できます。`rpg` を使うのは、キャンペーンを作るときの1回だけです。その後は、エージェントが自動でRPG Engineを起動します。

### 2.3 キャンペーンの作成

ゲームを置いているフォルダでターミナルを開きます（開き方は[2.1](#21-what-you-need)）。

```text
rpg init "The Salt Isles"
```

これで `The Salt Isles` フォルダが作られ、新しいキャンペーンが入ります。`cd "The Salt Isles"` でフォルダに入ります。場所は覚えておいてください。遊ぶたびに、ここに戻ってきます。ほかの設定は、あとでチャットかダッシュボードで選べます。今のうちに選びたいときは、`rpg init --help` でオプションの一覧を見られます（例：`--language it`、`--difficulty hard`）。

GMがキャンペーンを作ることはできません。`init` の前は、RPG Engineの場所をエージェントが知らないためです。

### 2.4 AIをつなぐ

GMは**AIエージェント**の中で動きます。AIエージェントとは、パソコン上のファイルを扱えるAIアプリで、ターミナル版もデスクトップ版もあります。Claude CodeやCodexがその例です。claude.aiやChatGPTのような普通のチャットや、スマートフォンのアプリでは足りません。GMは、パソコンにあるキャンペーンのファイルにアクセスする必要があるからです。エージェントごとに、プランとログインが必要です。Claude Codeは有料のClaudeプラン、CodexはChatGPTのログインです。インストールは1回だけで、それぞれの公式ページから行います：[Claude Code](https://code.claude.com/docs/en/setup)、[Codex](https://learn.chatgpt.com/docs/codex/cli)。

- **Claude Code**：キャンペーンのフォルダで `claude` と入力します。フォルダを信頼するか聞かれたら、**Yes, I trust this folder** を選びます。注意：最初に選ばれているのは *No, exit* です。
- **Codex**：キャンペーンのフォルダで `codex` と入力します。フォルダを信頼するか聞かれたら、yesと答えます。デスクトップアプリでは、ゲームのチャットでメモリーがオフになっているか、設定で確認します。
- **ほかのエージェント**：キャンペーンのフォルダで起動し、MCPサーバー `rpg mcp` を渡します。RPG Engineは標準的なMCPサーバーです。MCPに対応したエージェントなら、ローカルのものを含め、どれでもGMにできます。

動作の確認とテストは**Claude Code**で行っています。**Codex**は接続と確認が済んでいますが、キャンペーン全体を通して遊んだことはまだありません。`init` は**Gemini CLI**の設定も行います。キャンペーンでは、エージェント自身のメモリーをオフにします。ゲームの内容はファイルに残るので、セーブに戻ると本当にその時点に戻れます。

### 2.5 最初のチャット

何でもよいので書きます。たとえば *こんにちは！始めましょう。* です。GMは、チャットごとの最初の返答で**ダッシュボードのリンク**を伝えます。`http://127.0.0.1:4750` のような形です。開いて、チャットの横に置いておきます。

GMのメッセージの間に、エージェントが使っているツールが表示されます。詳細は開かないでください（Claude Codeではctrl+o）。秘密が表示されることがあります。

新しいキャンペーンは3つの段階を進みます。ダッシュボードの上部に表示されます：**1 設定**（遊び方を決める）、**2 セッションゼロ**（プレイの中でキャラクターを作る）、**3 プレイ**。

### 2.6 設定：遊び方を決める

GMは、まだ決まっていないことだけを、数問ずつ尋ねます。ダッシュボードの**設定**のステップにも、同じ質問がカードで表示されます。「おまかせ」と書けば、GMが選びます。どの項目も、あとでチャットか**設定**で変えられます。

| 設定 | 決めること | 値 |
|---|---|---|
| **メンター** | GMがルールをどれくらい教えるか | off、hints、tutorial |
| **難易度** | 世界の厳しさ | story、easy、normal、hard、brutal |
| **致死性** | 戦闘で倒れたときの扱い | narrative（死なない）、epic（重要な場面だけ）、dice |
| **セーブ** | いつ戻れるか | permadeath、checkpoint、free（[3.8](#38-saves-and-going-back)） |
| **厳しさ** | 食料、明かり、移動をどれくらい厳密にルール通り扱うか | smooth、rules、simulation |
| **ダイス** | 誰がダイスを振るか | digital、physical |
| **単位** | 距離と重さ | metric、imperial |
| **Voices** | 出会う人々の声を誰が担当するか。重要な場面では、そのキャラクター自身が、知っていることだけを知る立場で話します。GMが選ぶ場合、常にGM、またはAIアプリが対応していれば、主要な人物だけ、または全員を常にそのキャラクター自身が話す方法があります（遅くなり、費用も増えます） | auto、master、important、always |
| **仲間** | 誰が一緒に旅をするか | none、made with you、made by the master、met in play |
| **画像** | 場所、クエスト、出会った人々の画像 | none、on request、new places、quests and those you meet（[3.11](#311-pictures)） |
| **ライン**と**ヴェール** | 決して登場させないこと、画面の外でだけ起きること | 一覧 |
| **言語** | ゲームとダッシュボードの言語 | 任意 |

第5版では**成長**も加わります。経験値かマイルストーンです。

世界が書かれていない場合、GMは**前提**（ジャンル、雰囲気、いくつかの要素を、自分の言葉で）と、**準備**も尋ねます。世界を進行に合わせてその場で作るか、最初にすべて作るかです。

**GMの文体**は尋ねられませんが、チャットか**設定**で変えられます。**文章**（plain、literary、pulp、wry）、GMが作る**物語**（situations、arcs、episodes、mystery）、**文体を真似る**作家、そのほか**自分の言葉**で指定したことも選べます。

### 2.7 セッションゼロ：キャラクター作り

キャラクターは、テーブルを囲んで遊ぶときと同じように、GMと一緒に作ります。選択はすべて自分のものです。GMに任せたいときは、そう頼みます。しっかりしたアイデアでも、漠然としたものでも、何もなくても大丈夫です。能力値の決め方は、ダイスを振る前にGMが説明します。キャラクターの物語は必須ではありません。書く場合は、GMが本人の言葉で文章にします。そのあとGMが、キャラクターの画像を尋ねます（[3.7](#37-your-characters-story-and-picture)）。シートはRPG Engineが計算するので、自分で計算する必要はありません。

## 3. プレイ <!-- icon: chat -->

### 3.1 GMと話す

キャラクターの行動やセリフを、自分の言葉で書きます。

> 宿の主人に、今夜ほかに誰が通ったか尋ねる。

物語の外で話すときは、角かっこで囲みます。*[組み付きはどう働きますか？]* GMも角かっこで答えます。

試すことを伝えると、GMが何が起こるかを伝えます。GMがキャラクターの行動を勝手に決めることはなく、エンジンの話もしません。ダッシュボードの使い方はGMに聞けます。

### 3.2 ロール

GMがロールを求めるのは、結果が不確かで、しかも重要なときだけです。何がかかっているかも先に伝えます。そのうえで、次のとおりです。

- **ダッシュボード**では、判定ごとのボタンがバナーに表示されます。たとえば *Acrobatics +4 · with advantage* です。クリックすると、ページ上にダイスが落ち、結果がGMに伝わります。光っているキャラクターシートの行をクリックしたり、ダイストレイからダイスを振ったり、バナーに別の内容を書いたりもできます。
- **手動**は、バナーの隅か**設定**で選びます。バナーに何を振るかが表示されるので、キャラクターシートかダイストレイから振ります。
- **実物のダイス**は、ダイスの設定を物理にしたときに使います。出た目を *[14が出た。]* のように書くと、RPG Engineが修正値を足します。

**フリーロール**：キャラクターシートの数字をクリックするか、ダイストレイを開くと、気軽に振れます。結果は一切反映されず、GMにも見えません。

**GMのロール**は、秘密のもの以外、ロール欄に表示されます。*[今のロールは本物でしたか？]* といつでも聞けます。秘密のロールの場合、GMは、聞かれる前に振ったことを証明するフィンガープリントを示します。

### 3.3 シーンと戦闘

物語は**シーン**で進みます。戦闘、会話、探索、移動、休息などです。シーンが終わるたびに自動でセーブされ、そのシーンはジャーナルに記録されます。

戦闘では、自分以外のターンはGMがすべて語り、決断できる場面で止まります。**シーン**の上部には、今誰のターンか、次は誰かが表示されます。マップの横にはキャラクターのカードが出ます。ターンの順番、パーティのヒットポイント、敵の負傷の様子（言葉で表示）は、ページの脇にあります。キャラクターが倒れると、死亡セーブが大きく表示されます。

### 3.4 時間、移動、動いていく世界

RPG Engineは日付を管理します。セッションの合間に時間は進みません。*長い休息をとる* と言えば、休息によって回復すべきものが回復します。*北の道を通ってロッカへ向かう* のように行き先を伝えると、RPG Engineが道のり、距離、日数を計算します。途中で何かが起こると、そこで止まります。お金はゲーム内の硬貨で数え、おつりも出ます。

悪役には期限つきの計画があります。新しい日が来るたびに、GMは時間で進んだ脅威を動かします。見えるのはその兆しだけで、期限そのものは見えません。

### 3.5 マップ

**ワールド**には、キャラクターが知っている場所、その間の道、歩いた跡が表示されます。それ以外は霧に覆われています。**シーン**には、今いる場所のマップがあれば表示され、誰がどこにいるかも分かります。戦闘中の自分のターンでは、移動できないマスにヴェールがかかります。GMにどこへ移動するか聞かれたら、マスをタッチするか、*E4* のように書いて伝えます。

### 3.6 クエスト、ジャーナル、メモ

キャラクターが引き受けた依頼は、**ジャーナル**でクエストになります。目標、期限、測るものも載ります。スターをつけると、シーンの上部に表示され続けます。ジャーナルには、シーンごとの**ストーリー**と、**メモ**も残ります。メモは非公開です。**共有**したメモは、GMに「キャラクターの考え」として伝わり、事実としては扱われません。

### 3.7 キャラクターのストーリーと画像

キャラクターシートの**説明**カードに、キャラクターのストーリーを書く欄があります。了承すると、GMが書き込みます。画像を使うときは、ファイル（PNG、JPEG、WebP、SVG、5 MBまで）と、パソコン上の保存場所をGMに伝えます。肖像画を作ることもできます（[3.11](#311-pictures)）。*[肖像画を作って。三つ編みの白髪で、あごに傷がある。]*

### 3.8 セーブと巻き戻し

RPG Engineは、シーンが終わるたびにキャンペーン全体をセーブします。それ以外は、**セーブ**の設定で決まります。

| セーブ | 好きなときにセーブ | 巻き戻し |
|---|---|---|
| **permadeath** | できない | できない |
| **checkpoint** | できない | キャラクターが死んだときだけ、最後のセーブへ |
| **free** | できる | 任意のセーブへ |

どのモードでも、プレイの最初またはセッションゼロから**やり直す**ことができます。チャットか**セーブ**で行います。

巻き戻したあとは、**新しいチャットを開いてください**。古いチャットは、取り消された出来事を覚えたままです。新しいチャットで *続ける* と書き、セーブで**新しいチャットを開いた**を押します。

### 3.9 セッション：中断と再開

いつでも中断できます。*[今夜はここまでにしよう。]* すべてすでにファイルにセーブされています。再開するには、キャンペーンのフォルダでエージェントを起動し、*続ける* と書きます。GMが短くあらすじを伝えて、続きに進みます。

### 3.10 GMの気分

ダッシュボードの上にいるロボットがGMです。表情は物語の調子に合わせて変わりますが、まだ知らないことを明かすことはありません。チャットが閉じているときは眠っています。

### 3.11 画像

RPG Engineは、訪れた場所、引き受けたクエスト、出会った相手の画像を作れます。作るかどうかは**画像**の設定で決まります。頼めばキャラクターの肖像画も作れます。パソコンにあるものを、自分のログインで使います。**Codex**があれば描き、なければ**Claude Code**が描きます。このパソコンで作れるかどうか、作れないときの設定方法は、**設定**に表示されます。自分で用意した画像をGMに渡すこともいつでもできます。

### 3.12 安全：ライン、ヴェール、ストップ

**ライン**は、ゲームに決して出ない話題です。**ヴェール**は、画面の外でだけ起こる話題です。いつでも *[ストップ]* と書けます。GMはすぐにその内容をやめ、ラインに追加します。

### 3.13 気が変わったとき

どの設定も、チャットか**設定**でいつでも変えられます。GMがルールブックにない裁定をしたときは、それが**先例**になり、次に同じ質問があれば同じ答えになります。

## 4. ダッシュボード <!-- icon: party -->

自分のパソコン上のページです。そのパソコンのブラウザでだけ開け、チャットが開いている間だけ動きます。チャットを閉じると *Not connected* と表示され、次のチャットで自動的に戻ります。

- **パーティ**：自分のキャラクターシートと、仲間のシートです。数字をクリックするとロールします。数字にカーソルを合わせると、その由来が分かります。横にはロールが並びます。
- **シーン**：今いる場所、その画像とマップ、そこにいる人、起きていることです。戦闘中はターンとキャラクターのカードが出ます。
- **ジャーナル**：クエスト、ストーリー、メモです。
- **ワールド**：キャラクターが知っている範囲の世界マップです。
- **ダイストレイ**：ダイスと修正値を選んで振ります。
- **セーブ**、**ヘルプ**、**設定**、**概要**：列の末尾にアイコンで並びます。設定には、ページ自体の好みもあります。テーマ、ダイスの音、ダイスのセットです。

GMから何か聞かれると、どのセクションにいても、バナーが上部に表示され続けます。

## 5. ゲームシステムとハウスルール <!-- icon: dice -->

### 5.1 ゲームシステムとは

1つのゲームのデータです。キャラクターシート、数値、クリーチャー、アイテム、呪文、ルールのテキストが含まれます。キャンペーンごとに、遊ぶシステムは1つです。RPG Engineは、キャラクターシートの計算と、消費したものや戻ってくるものの管理を行います。特技がどう働くかは、GMがルールを読んで判断します。実際のテーブルと同じです。

### 5.2 第5版を収録

SRD 5.1の種族、クラス、サブクラス、背景、特技。319種の呪文、武器、防具、魔法のアイテム、モンスター。GMが正確な文面で読むルール各章。計算済みの完全なキャラクターシート。

SRDにない内容も、お持ちの書籍から遊べます。GMがキャンペーンのページとして書き起こし、RPG Engineが自前のデータと同じように扱います。RPG Engineが収録するのはオープンコンテンツだけです。GMが知っている範囲に制限はありません。

お手持ちのマニュアルを、ライブラリにできます。GMに場所を伝えるか、*[マニュアルは D:\Books\5e にあります。]* 、Packages › Library でそのフォルダを追加します。そして、コンピューターに表示されるウィンドウで、一度だけ「はい」を選びます。RPG Engineはこのコンピューター上でマニュアルを読みます。各キャンペーンは、そこで有効にしたフォルダを使います。GMはルールを判断するとき、SRDの次にそれらを検索し、書名とページを示します。テキストの形式か、テキストを選択できるPDFが最適です。スキャンしたPDFは、ページの画像から読み取ります。Windowsのみの対応で、数分かかり、誤りも少しあります。RPG Engineがマニュアルを変更することはありません。テキストをどこかへ送ることも、キャンペーンにコピーすることもありません。

### 5.3 ハウスルールと独自の追加

GMに頼みます：*[ハウスルール：攻撃の出目1で武器を落とす。]* GMはそれをテーブルの取り決めとして記録します。必要なら、ページを書くか、キャラクターシートの数値を書きます。すでに文章になっているハウスルールは、テキストファイルにして、キャンペーンの `rules` フォルダに入れられます。

### 5.4 独自のゲームシステムの追加・インポート

まだできません。現在、RPG Engineが遊べるのは第5版だけです（[今後の予定](#9-coming-later)）。

## 6. 拡張 <!-- icon: plus -->

まだありません。拡張は、ゲームシステムの上に、キャンペーンへ何かを加えるものになる予定です。世界、アドベンチャー、天候のような機能、共有できるハウスルールなどです。

## 7. キャンペーンの世界の作り方と言語 <!-- icon: world -->

### 7.1 世界を用意する3つの方法

- **その場で作る**：前提をもとに、GMが必要になる直前に場所、人物、筋書きを作り、記録します。
- **開始前に用意する**：同じ方法で、遊ぶ前に世界を作っておきます。
- **手持ちのアドベンチャーや書籍から作る**：GMにファイルを渡します。*[このアドベンチャーをキャンペーンとして取り込んで：D:\Books\adventure.pdf。中身は教えないで。]* テキスト、EPUB、Word文書、または文字を選択できるPDFが最適です。スキャンしたPDFはページの画像から読み取ります。これはWindowsのみで、時間がかかり、誤りも少しあります。お使いのコンピューター上のCodexまたはClaude Codeがチャットの外で読み込み、進み具合はダッシュボードに表示されます。小説からの場合は、GMが開始地点を提案します。GMは場所、キャラクター、秘密を書き起こします。

キャンペーンは一度だけ遊べます。同じアドベンチャーをもう一度遊ぶには、新しいキャンペーンを作ります。

### 7.2 言語

キャンペーンの言語はひとつで、GMの言語です。ダッシュボードもそれに従います。ダッシュボードは26言語に対応しています。それ以外の言語は、お使いのコンピューター上のCodexまたはClaude Codeが翻訳します。それらがない場合は、チャットのGMが翻訳します。第5版のイタリア語の用語は、公式のイタリア語版SRDによります。ルールのテキストは英語のままで、GMが言語に合わせて語ります。

## 8. 興味のある方へ：キャンペーンフォルダー <!-- icon: list -->

開く必要はありません。キャンペーンの秘密が入っています。中身は次のとおりです。`campaign.yaml`（設定）、`state.yaml`（ゲームの現在の状態）、`world/`（キャラクター、場所、クエストなどごとにmarkdownのページをひとつずつ）、`rules/`（ハウスルール）、`images/`、`log.jsonl`（すべての変更）、`.saves/`、`.player/`（メモ）、そしてAIエージェントにRPG Engine の場所を伝える小さなファイル。ページはObsidianの形式です。ページを手で変更すると、GMは次の返答の時点でそれを知ります。

RPG Engine はこのフォルダーの中にとどまります。ゲームの読み書きはここだけで行い、ほかのファイルには触れません。マニュアルのフォルダーは読むだけです。この外に置くのは、専用のデータフォルダー（ダッシュボードの翻訳、マニュアルから読み取ったテキスト、許可した場合のCodexやClaude Code）と、画像を描く間の一時フォルダーだけです。エージェントがコンピューター上でほかのことをしたいときは、先に確認があります。

GMが使うコマンドは、すべてキャンペーンフォルダーでも実行できます。`rpg --help` で一覧が出ます。多くは、キャンペーンの秘密を表示します。

## 10. 質問と困ったとき <!-- icon: info -->

### 質問

**ルールを知っている必要はありますか？**いいえ。メンターにチュートリアルを選び、知りたいときはいつでも角かっこで尋ねてください。

**GMはズルをできますか？**RPG Engineが振ったロールは変えられません。すでに決まった事実も変えられません。ただし、難易度がストーリーの場合は例外です。

**お金はかかりますか？**RPG Engineは無料です。GMは、エージェントのプランか、自分のコンピューター上のローカルモデルで動きます。1晩のプレイは長いチャットになります。最小のプランでは、夜が終わる前にプランの上限に達することがあります。画像と翻訳も、同じプランを使います。

**スマートフォンで遊べますか？**いいえ。GMはコンピューター上で動き、ダッシュボードもそこでしか開けません。

**友達と遊べますか？**まだできません。現在は、プレイヤー1人に、キャラクター1人と仲間です（[今後の予定](#9-coming-later)）。

**次回は別のAIを使えますか？**はい。キャンペーンを別のエージェントで開き、*続きから*と書いてください。

### 困ったとき

**ダッシュボードが開きません。**GMに尋ねてください：`[ダッシュボードのリンクは？]`。ダッシュボードが動くのは、そのキャンペーンでチャットが開いている間だけで、GMの最初の返答のあとです。

**GMがゲームを知らないようです。**エージェントがRPG Engineを読み込めていません。キャンペーンのフォルダーで起動したか、フォルダーを信頼したかを確認してください。Claude Codeでは`/mcp`と書いて、`rpg`を再接続します。Codexでは、キャンペーンのフォルダーで`codex mcp list`を実行し、`rpg`が表示される必要があります。`rpg --version`が見つからない場合は、RPG Engineをもう一度インストールしてください（[2.2](#22-install)）。

**更新するには。**`npm install -g rpg-engine`をもう一度実行し、新しいチャットを開きます。動いているGMは、起動したときのバージョンのままです。

**取り消したことをGMが覚えています。**新しいチャットを開き、セーブの**新しいチャットを開いた**を押してください。

**画像が表示されません。**設定 > 画像で、このコンピューターで作れるか、その方法を確認できます。

**インストールに失敗する、または`rpg`が起動しません。**`node --version`が22以降を示す必要があります。Windowsでは、RPG Engineとキャンペーンを、`&`を含むパスに置かないでください。

**ダッシュボードのリンクが変わりました。**ほかのプログラムが、いつものアドレスを使っています。新しいリンクはGMが伝えます。
